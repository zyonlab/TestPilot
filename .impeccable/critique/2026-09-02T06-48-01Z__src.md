## Design Specificity 判定：作者化（Settings 与 Evals 两处例外）

**LLM 评估**：这套界面换个产品搬不走，因为它把「一次跑产出上百条待复核物料」长成了词汇和结构。空态在区分「零」和「坏」——Trace 写 `the zeros here mean "nobody has approved any yet", not "something is broken"`；Delivery 用 `not built yet` 徽标代替假按钮；canvas 右栏那节 `WHAT THIS RUN COULD SEE` 问的是「这次运行凭什么产出这些」，通用后台不会有；令牌专门给「模型说的话」留了一对色（`--chat`/`--chat-soft`）。门禁词汇 `tier-unbacked·27 / method-mismatch·13 / oracle-volatile·6` 是这个产品自己的。

扣分在两处：**Settings**（`mx-auto max-w-2xl` 居中卡片）与 **Evals**（六张中文随笔卡）看起来像任何一个 admin 后台，和其余左对齐满宽的十屏不是同一套东西。

**确定性扫描**：CLI 检测器（`detect.mjs --json src`）退出码 2，仅 **1 条**发现（`border-accent-on-rounded`，`src/index.css:210`）——它对 tsx/css 是纯 regex 匹配，覆盖面窄，这个「干净」不能当结论。真正的证据来自浏览器 overlay，5 个路由共 **162 条**：

| `#/`（复核队列） | 127 | undersized-ui-text 101、low-contrast 12、tiny-text 8、nested-cards 2、text-occlusion 2、cramped-padding 1、flat-type-hierarchy 1 |
| `?open=settings` | 14 | undersized-ui-text 10、low-contrast 2、tiny-text 1、flat-type-hierarchy 1 |

**检测器抓到而人眼漏掉的一条**：`low-contrast 4.4:1 (need 4.5:1) — #78716c on #f5f5f4`。这就是 `--muted-foreground: 25 5.3% 44.7%` 落在 `--background` 上，差 0.1 不达 WCAG AA。它出现 12 次不是因为写了 12 遍，是因为**一个令牌错了 0.1**。改 `index.css` 一行即可全站修好——这是本次投入产出比最高的一条。

**两边互相印证的一条**：`undersized-ui-text` 109 条（默认路由）+ `flat-type-hierarchy` 显示 8 级字号挤在 10px–14px、比例仅 1.4:1；人这边独立测到 Artifacts 六行 `11 / 1 / 12 / 75 / 63% / 52%` 同字号同色同列，计数与百分比看起来是一种量。同一个问题的两个侧面：**字号既太小又不分级**。

**误报**：`<button` 114 个无一带 `aria-label` 这个 0 站不住当结论——多数按钮有可见文字，不需要 aria-label。站得住的只是「零使用」这个事实本身。`<label htmlFor>` 18/115 同理，是信号不是结论。

## 总体印象

**地基比交付面好得多。** 令牌系统、地址机制、空态文案这三样是有人认真想过、并且量过数字才写下来的——`index.css` 的注释里带着「实测 697 处硬编码 px」「一台默认 24px 的机器上按钮 50px 而视图切换 25px」这种只有真的去量过才写得出的话。

但 `plan.mjs` 报 80/80 全绿的同时，**这个产品最核心的那个动作——批准一条用例——是全界面最难点到的按钮**，而它每天要发生上百次。11 个导航项里 6 个是空的。`03` 自己写下的九条全局约定里，统一错误卡、空态引导、focus 可见、切语言无残留四条没有落地。

最大的机会只有一句话：**把「批准」这一件事修到位。** 单条按钮 + 键盘直达 + 光标自动前进，这三件加起来的代码量不到 50 行，但它把 75 条 × 4 次操作变成 75 次按键。

## 做得好的三条

1. **空态在解释「零」和「坏」的区别，并指出下一步。** 实机上 11 个导航项 6 个是空的、4 个 tab 是空的。Trace 那句「这里的零意思是还没人批准过，不是坏了」、Delivery 那句「导出里是已批准的用例，现在还没有——最近一次运行有 75 条待复核 [打开复核队列 →]」、CodeLine 那句「阶段二产物还只活在工作流运行里，去复核队列批准一个 g2 批次」。绝大多数产品在这里写的是 "No data"。这一条把最大的失败模式（人以为产品坏了就再也不回来）单独拆掉了。

2. **Delivery 用 `not built yet` 徽标代替假按钮。** PR 与 CI 两块明确标未实现，并写清「今天只有上面那个 zip」。一个自称接管质量工程的产品，把「我们还没做到」当成产品信息呈现，比给一个点下去什么都不发生的按钮诚实得多。

3. **令牌是成对的语义色 + 钉死的控件底座。** `--ok/--ok-soft` 四对加专给模型说的话的 `--chat`，用法固定 `bg-ok-soft text-ok`，暗色下自己翻面所以调用处不写 `dark:` 孪生类；`index.css` 把 input/select/textarea/button 的下限统一到 25px / 12.5px / line-height 1.35，并解释了 `<select>` 那 2px 固有高度为什么必须写死。这不是抄 shadcn 默认值，是量出来的。

## 优先级问题

### [P0] 语言与主题切换没有 UI 入口，而设置页正在教人去切

**证据（已复核）**：`grep -rn "AppControls" src/` 只返回 `src/components/AppControls.tsx:8` 定义行本身——**这个组件没有被任何地方 import，是死代码**。`setLang` / `toggleTheme` 只在它内部被调用。Settings → PREFERENCES → `Language & debug` 实机上只有两个 toggle，其中一个的说明写着 `Switch the UI language to switch the target language.`

**为什么重要**：US-22 三条并列要求（三语 / 提示词模板 / LLM 调试日志），另两条都做了。`i18n.ts` 里 1387 个 key × 3 语言 = 4161 条翻译全部不可达，语言只由 `navigator.language` 决定一次。同一处还吃掉了 `index.css` 里整套带青调的 `.dark` 令牌。最糟的是设置页在指示用户执行一个产品不提供的操作。

**修法**：`AppControls.tsx:40-62` 的非 collapsed 分支已经写好三语选择 + 主题切换，把它挂进 `PrefsSection` 即可；另在 `AppNav` 的 `ProjectSwitcher` 那行右端放一组语言/主题小图标——换语言是每个新环境要做一次的事，不该藏三跳。

**建议命令**：`$impeccable harden`

### [P0] 复核的批准动作违反 `03 §6` 自家规格：详情面板里没有批准按钮，`1`/`3` 键静默无效，批准后光标不前进

**证据（已复核）**：`Review.tsx:1231` 与 `:1325` 首行 `if (!batch || !selected.size) return;`，而键盘 handler 的 `1`/`3` 直接调 `act`。队列行只有 checkbox，详情卡只有 `Ask` / `Revise` / `Save edit`。唯一批准路径是「勾选 → 底部浮起 → Approve」。`act()` 之后只 `openRun` + `loadRuns` + `loadData`，cursor 不动。

**为什么重要**：`03 §6` 白纸黑字写着「详情内可直接编辑、重新打分、重生成、**批准进入阶段二**」和「`1` 批准、`3` 打回」。实际每条 4 次操作，75 条 = 300 次。而按 `1` 什么都不发生**没有任何反馈**——人会得出「快捷键是假的」然后改回鼠标。`Review.tsx` 里那段注释（「吃掉 `1` 会让人以为键盘坏了」）想避免的正是这件事，只是防错防在输入框上，没防在空选上。这一版把画布降级、导航从 18 收到 11，理由是「十个 review-heavy 的工具没有一个把画布放在中心」——**但同一份调研里 GitHub / Linear / Label Studio 的复核动作是单条、当场、一键、光标自动前进。抄了布局，没抄那件事本身。**

**修法**：`act` 在 `selected.size === 0` 时回退到 `list[cursor]`；批准后把 cursor 推到下一条 pending；详情卡 `Save edit` 那行右端加 Approve / Reject 两颗按钮走同一条 `act`。

**建议命令**：`$impeccable shape`（复核动线）→ `$impeccable harden`

### [P1] 1280 宽的笔记本上，复核台中间那列被压成 20px

**证据**：`Review.tsx:1649` `grid-cols-1 md:grid-cols-[300px_minmax(0,1fr)] xl:grid-cols-[300px_minmax(0,1fr)_268px]`。把外壳宽度设成 768 后实测 `gridTemplateColumns` = **`300px 20px 268px`**；页头需要 780px 而容器只有 588px，被 `overflow-hidden` 裁掉——13 个批次 chip 与三个视图按钮全部消失。换成 md 档则第三格掉到第二行（`top=540`），队列与详情各被压到 398px 高。

**为什么重要**：`xl` 断点是 1280px，一台 1280×800 的 MacBook Air 全屏刚好卡在边界，窗口没最大化就必然掉档。这是每天用上百次的那一屏。全仓 27095 行里响应式工具类一共 **20 个**（sm×4 / md×10 / lg×3 / xl×3）——不是「移动端不做」，是连 1280 与 1600 两档笔记本都没分开考虑过。

**修法**：中间列改 `minmax(420px, 1fr)`；md 以下把右栏改成页头一颗按钮打开的抽屉而不是掉到第二行；页头那排 chip 已有 `.hscroll` 样式，把外层 `overflow-hidden` 换成横向可滚。

**建议命令**：`$impeccable adapt`

### [P1] 两个不同的东西都叫 run，而且「当前运行」没有单一来源

**证据（已复核）**：`nav.ts` 的 `from("wfruns","▤","nav.runs")` 渲染成 "Runs"（工作流运行）；`surfaces.tsx` 的 `{id:"runs", group:"exec", title:"surface.runs"}` 渲染成 "Run report"（用例执行）。实机 `?open=artifacts` 落在 `09-01 12:36`，`?open=review` 落在 `09-01 20:36`。更深一层：`App.tsx` 的 `go()` 会保住 `run` 参数，而页面内部用的 `openCard(id)`（`src/lib/open.ts:18`）直接写 `#/?open=${id}`——**同一个应用里两个导航函数，一个保上下文一个不保。**

**为什么重要**：`02 §3` 术语表把 `WfRun` 与 `Run` 分得清清楚楚，UI 把两个都翻成 "Run…"。用户在 Artifacts 上看到的 75 条和在 Review 上看到的 75 条可能不是同一批，界面上没有任何东西说这件事。

**修法**：`nav.runs` → 「工作流运行 / Workflow runs」，`surface.runs` → 「用例执行 / Case executions」；把「当前运行」提到 shell 层，让 `openCard` 复用 `go()` 的参数保留逻辑。

**建议命令**：`$impeccable clarify` + `$impeccable harden`

### [P1] 原语层太薄，同一个缺口在三个方向上各漏一次

**证据**：`src/components/ui.tsx` 只有 141 行 **6 个原语**（StabilityChip / TypeBadge / PriorityBadge / RunStatusPill / CodeIndicator / Button），**没有 Input、Select、Card、EmptyState、ErrorCard**。`grep -rn "EmptyState\|ErrorCard" src/` = **0 命中**。后果分三路：

**顺带**：`--muted-foreground` 落在 `--background` 上是 4.4:1，差 0.1 不达 AA，检测器在 3 个路由共报 15 次。改 `index.css` 一行全站修好。

**为什么重要**：这不是五个 bug，是同一个结构缺口漏出来的五处水。补 `EmptyState` / `ErrorCard` / `Field` 三个原语并给 `Button` 加一条 `focus-visible:ring-2 ring-ring`，一次修掉四条 `03 §9` 约定 + 15 处对比度告警。

### [P2] Evals 页上没有 `03 §7` 点名的任何一个数字，覆盖矩阵根本不存在

**证据**：`document.body.innerText` 上 `coverage` / `F1` / `McNemar` / 误报型\|漏报型\|均衡 / cost **全部 0 命中**；`grep -rn "覆盖矩阵\|coverage matrix\|matrix" src/` = **0 命中**（US-16 AC-16.1）。页面是六张 4–6 行中文随笔卡各带一颗 `Run paired eval`，页尾 30+ 行 `det-xxxx / no prediction`。

**为什么重要**：US-19 / US-20 / US-21 三条里只有 ABLATE 做了。评测页是这个产品用来自证「这一版比上一版好」的唯一场所——**当一个页面的解释文字比它的结论多一个数量级时，它是给写它的人看的，不是给要做判断的人看的。**

**建议命令**：`$impeccable shape`

## UI 分层诊断

**导航层 —— 三层清楚，但同一件事出现在两层。** `AppNav`(11 项) / `SurfaceTabs`(页头) / `SectionNav`(Settings 内 9 项 4 组) 层级本身立得住，`navIdFor()` 的父项高亮也对。三个问题：① "Runs" 与 "Run report" 撞词（见 P1）；② 第三层只在 Settings 里存在，于是最不常用的东西是唯一需要走三跳的；③ `SectionNav` 里 4 个组标题管 9 项、含一个 **1 项组**——`nav.ts` 的注释刚说过「两项的组几乎不减少什么，却各占一行组标题」所以把四组并成三组，同一条规矩没有应用到第三层。

**一处已复核的 IA 泄漏**：`CasesBoard.tsx:1544` 空态里那颗按钮写着 `cases.emptyToCanvas`（「回画布跑一次 / Back to the canvas」），实际调用的是 `closeCard()`；而 `open.ts:22` 的 `closeCard` 把 hash 设成 `#/`，`App.tsx:219` 的 `readOpen()` 在没有 `run` 参数时返回 `"review"`。**它旁边那颗按钮写着「去复核队列」——两颗按钮落到同一个地方，其中一颗还写着一个导航里根本不存在的目的地。**

**信息层 —— 页头成立，内容区不成立。** `TopBar` 的三级（15.5px semibold 标题 / 11.5px mono 副标 / 12px muted hint）是对的，副标走等宽是为了对齐扫数字，理由充分。但：Case board 页头读到的是 `0 cases | 复核队列 | 用例看板 | 需求追溯`——那个 `0 cases` 属于当前激活的 tab，却印在整排 tab 之前；Artifacts 六行 `11 / 1 / 12 / 75 / 63% / 52%` 同字号同色同列，计数与百分比看起来是一种量；canvas 右栏所有值右对齐并折行，`No mutation run — whether these cases actually catch faults is unknown` 折成四行右对齐而标签左对齐——右对齐的多行段落是最难扫的排版，而这一节正是复核时要反复对照的背景；Evals 的层级是倒的，六张随笔卡在最上面，本该有的结论根本不在页上。检测器在这一层给出的数是 `flat-type-hierarchy`：**8 级字号全挤在 10–14px，最大最小比只有 1.4:1。**

**组件层 —— 原语太薄，page 在造轮子。** 见 P1。做得对的一层是 `src/lib/artifact/`（CaseCard / StoryCard / Findings / Field / registry / oracle / types）——边界干净，Review 与 Workspace 共用同一套渲染契约，**这是本仓库分层最正确的地方，也是 `ui.tsx` 该学的样板**。反面是 `Review.tsx` 2104 行里藏着 FilterBar / StoryMap / TrayButton / Composer 等至少 6 个未导出的本地组件；`Workspace.tsx` 1922 行、`CasesBoard.tsx` 1574 行、`ModelConfig.tsx` 1536 行同理，超 400 行的文件共 14 个。

**路由与状态层 —— 地址做得最好，导航函数切成了两套。** 一个 hash + `?open=`/`?run=`/`?peek=`/`?at=`/`?s=`，深链可发、可跨机复现，`App.tsx` 的 LEGACY 映射保住了旧链接——**这是这套 UI 最好的设计决定**。但状态切成三个 zustand store（`store.ts` 数据 / `prefs.ts` 偏好 / `wf.ts` 工作流）加各页 useState，没有统一的「当前运行」；`go()` 保 `run` 而 `openCard()` 不保。`store.ts` 301 行里 `exploreScreenshot` 和 `model.apiKey`、`projects` 同居，是万能袋的苗头，但规模没失控，比 page 里的轮子轻得多。

## 情绪旅程

**峰** —— Delivery 底部那句：「导出里是已批准的用例，现在还没有——最近一次运行有 75 条待复核 [打开复核队列 →]」。它把「空」翻译成「下一步」并给了链接。Trace 的「零不等于坏」是同一质量的第二座峰。在一个默认 9 个屏幕全空的产品里，这两处把最大的风险拆掉了。

**终 —— 很差。** 批准一条的终点是：勾选 → 底部浮条 → Approve → 那一条 `opacity-50` 变灰、pending 减 1。没有庆祝，没有「还剩 74 条」的推进感，光标不自动前进。**第 75 条和第 1 条的终点体验完全一样。峰终定律在这里是空的。**

**谷 —— 三处。** ① 第一次点开 Review，32 个控件横在你和第一条用例之间；② 1280 宽笔记本上右栏整节掉到队列下面，队列与详情各被压到 398px；③ Set up 攒到 6/6 verified 之后这一屏什么也不做，右侧只有一颗 `Go configure`。

**高风险时刻的安抚 —— 反的。** 一次要复核 75 条，安抚只有右栏 PROGRESS 三行和表头一根 1px 进度条，没有预计时间、没有「今天已过 N 条」。而同一节里写着 `Mutation score — No mutation run — whether these cases actually catch faults is unknown`，右对齐折成四行——**在人开始判断 75 条之前，先告诉他这 75 条可能全是废的，且不给任何补救入口。**

## 次要观察

- **字体从公网 CDN 拉。** `index.css:4` `@import url("https://fonts.googleapis.com/css2?family=IBM+Plex...")`，而 `02 §1` 写明这个产品「运行在私有环境」、模型本地自托管。内网/离线机器上这次请求会挂，回落到 PingFang/system-ui，而全部尺寸是按 IBM Plex 的度量钉死的 px。**字体应该自托管。**
- **服务端文案绕过 i18n。** `Onboard.tsx` 直接渲染 `{it.detail}`：英文界面上出现「6 个能力，一个都没起」「demo.binance.com 不在白名单里」。另有 21 行硬编码中文散在 `registry.tsx`（6 处）、`Baselines`、`Suite`、`Evals`、`Review`、`ModelConfig`。`check-i18n.mjs` 报 1387 条词条引用全部命中、exit 0——**它只验「已登记词条都被引用」，不检测未走 `t()` 的裸中文串**，这个绿灯是假的安全感。
- **不该可点的按钮**：空 Run report 上 `Run all P0` 实测 `disabled:false`（P0 计数为 0）；Delivery 的 `Download .zip` 在 `0 cases / 0 with code` 时可点，会下出一个空工程。
- **`Download .zip` 是 outline 而非 primary**——Delivery 全页没有主色动作，唯一真能干的事视觉权重最低。
- **复数与口径**：Onboard 写 `On this machine: 1 projects, 88 past runs`（`1 projects`），Run management 写 `26 runs`。88 是全机、26 是本项目，界面不说。
- **Product map**：11 个节点排成一条直线挤在画布顶部 90px 内，其余 90% 是空点阵；节点标题全部截断成 `/en/futures…`，11 个彼此无法区分；`How to read this` 图例默认压在头两个节点上；载入时不 fit-to-view；右下角小地图是一块空白灰。`03 §2` 写的 elkjs 自动排布在这里看不出效果。
- **canvas 是唯一带项目选择器的页头**，而 `TopBar.tsx` 的注释明写「项目名去掉了，它在左导航底部常驻——同一件事印两遍，人会以为是两件事」。canvas 同时印了三遍（导航底部 + 页头下拉 + 右栏 Project 行）。
- **措辞不一**：canvas 底部两条折叠区，一条写 `Expand`，一条写 `+ show trace`。
- **canvas 右栏有 TODO 味的占位**：`Materials read (whatever the graph pins)`、`Ablated (none)`、`Prompts e5b80c75`（一个没有含义的裸哈希）。
- **`nav.ts` 的文档串已过期**：`/** …`""` 表示画布 */`，而 `App.tsx:222` 写着「空串曾经是它，但空串现在表示『没写』」。两处注释互相矛盾。
- CLI 检测器唯一那条 `border-accent-on-rounded`（`index.css:210` 的 `.kbd` 用 `border-b-2` 做键帽）站得住但无关痛痒——那是刻意的拟物，不建议改。

## 值得想的五个问题

1. 这一版把画布降级、导航从 18 收到 11，理由是「十个 review-heavy 的工具没有一个把画布放在中心」。同一份调研里，GitHub / Linear / Label Studio 的复核动作是**单条、当场、一键、光标自动前进**。为什么这里的批准要「先勾选 → 底部浮起 → 点 Approve」，而详情面板里根本没有这颗按钮？
2. 一个项目、26 次运行、75 条产物之后，11 个导航项里 **6 个是空的**、4 个页头 tab 是空的。那么「批准」是不是这个产品唯一真正的转折点？如果是，为什么它是全产品最难点到的按钮？如果不是，那 6 个空屏为什么要一直占着导航，而且不显示任何计数？
3. `02` 声称自己是「喂给 harness 的真实输入语料」，而 `00`/`17` 里的「64 条用户故事」出自另一份文档，`02` 自己只有 22 条，代码里 `US-` 只有一句注释。**自举评测到底拿哪一套故事对拍？**
4. Evals 页上六段中文随笔解释着为什么要做这些评测，而 Coverage / P / R / F1 / McNemar **一个数都没有**。当一个页面的解释文字比它的结论多一个数量级时，它是给要判断「这一版有没有变好」的人看的，还是给写它的人自己看的？
5. `html { font-size: 16px }` 那段注释把代价写得很清楚——697 处硬编码 px，不钉死就会劈叉。既然已经量出了 697 这个数，为什么选择钉死根字号，而不是花一次工把它们换成 rem？**这条选择把「视觉一致」排在了「可访问」前面，而 `03 §9.6` 把可访问性列为全局约定。同一份文档里的两条，一条被执行到了 CSS 的最底层，另一条连焦点环都没统一。**
