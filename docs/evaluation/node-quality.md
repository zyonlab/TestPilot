# 节点评测与版本选择

入口：评测页「节点产物对比」。比较目的分为固定输入比较节点、固定节点比较输入、全流程组合比较。保存后固定两侧 revision；后续运行变化不会改写比较。人工评价按节点或全局、按维度追加，含证据和本地操作者来源。它不是 Gold、身份认证或基线批准。

## 能证明什么

当前自动对比提供不可变产物、直接来源引用、运行绑定、登记时工作区提交/跟踪文件差异。来源引用不等于完整 prompt；登记时工作区不等于宿主实际加载实现；历史未记录的模型上下文或初始业务状态必须未知。即便选择「固定输入」，只要缺少这些证据就仍是诊断比较，不能作因果结论。

比较 Explore 时保持目标分母：缺前置条件、找不到或没有结果证据都保留为缺口。控件计数、屏数、文本长度是观察量，不能直接作为质量分。同一元素动态计数可归一化定位，原始数值和空/非空状态仍须保留。UI 的区域证据只证明采集时的上下文，不证明业务结果。

## 测试层次

| 节点 | 主要测试集 | 验收重点 |
|---|---|---|
| Explore | 状态场景、重复名称、动态标签、前置缺失、失效选择器 | 控件识别、状态保留、证据与覆盖不夸大 |
| 模块 | 冻结材料与模块约束 | 范围、出处、漏项与非法重写 |
| 故事 | 需求与状态条件样例 | AC 义务和逐条件证据，不把观察缺口当需求缺口 |
| 用例 | 故事、生命周期与判据样例 | 前置、动作、业务结果、清理以及引用 |
| 门禁 | 合法/非法及变异输入 | 错误不漏放，合法例不误拦 |
| 定稿 | 阶段与不可变输入样例 | 完整性、审阅边界、跨项目隔离 |
| 编译/准备 | 已批准用例、缺凭证、试跑结果 | 确定性、来源与准备状态 |
| 执行 | 已知成功/失败、资源清理场景 | 误报漏报、取消、重试与证据 |
| 全局 UI | 隔离项目、多语言、历史评价、窄屏 | 输入输出可读、评价持久化、无项目串线 |

`pnpm eval:node-quality --node source` 跑指定节点的确定性开发回归；`--node all` 批量跑。报告保存套件、测试文件与评估器指纹、原始日志和退出码。这不是模型效果分，也不调用真实交易。浏览器采集回归另外运行 `server/scripts/verify-explore-state-ui.ts`；评测 UI 使用 `verify-node-comparison-ui.ts`，必须指向隔离数据目录。

## 迭代流程

1. 从失败轨迹中固定输入、目标和证据；先使回归能复现缺陷。
2. 明确改变的是代码、规则包、skill、模型还是上游材料。每项独立分支；评估标准改变时单列版本，不与能力提升混称。
3. 跑节点回归、受影响的下游测试及完整业务抽样。保留失败、阻塞与所有重复试验，不只展示最好一次。
4. 在比较 UI 逐维度评价，并指出状态差异。人工分歧保留历史，追加理由，不改原记录。
5. 候选在冻结验证集上通过后，再由用户选择适用范围内的基线。当前对比入口不自动发布或改基线。
6. 将确认的缺陷转为开发回归、领域规则或 skill 方法；未经验证的猜测不自动写成长期规则。

当前仓库回归集是开发可见的，不宣称独立留出集。建立新验证集时须另行冻结版本、限制调参访问，并按场景配对重复运行。自动修复只产生候选；不能自动改答案、降低门禁、删除失败样例或重跑到成功。

真实交易验证仍需先修复已记录的执行路径跨域边界缺口；本轮不恢复那条路径，不宣称交易成功率或速度提升。
