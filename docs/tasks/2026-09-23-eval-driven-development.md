# 逐节点评测与业务状态探索

按顺序开发，每项独立分支，后项从前项提交继续。现有运行保持暂停，不自动批准、交易或更换生产基线。

1. `codex/node-comparison-records`：冻结运行/节点产物比较、来源差异和人工评价记录；历史缺失版本明确 unknown。验证跨项目隔离、不可变性、归因限制与评审证据。
2. `codex/node-comparison-ui`：评测页接入全局与节点比较、输入/输出证据和人工评价历史；无需最终用例 Gold。验证多语言、错误/空态、窄屏和真实 UI。
3. `codex/explore-state-scenarios`：修复动态标签、区域/模式目标与重复缺口；建立状态场景回归，不将计数或动作成功当业务成功。领域语义留在规则包。
4. `codex/eval-iteration-workflow`：将状态建模、证据边界和评测驱动迭代写入实际下发的 skill；建立节点测试矩阵、冻结验证集与版本选择流程。运行相关测试、构建和集成检查。

评测分三种目的：固定输入比较节点实现；固定实现比较输入；比较整套流程。历史两跑同时变化时只能给诊断/人工结论，不伪造因果效果。人工评价不是用例批准、Gold 或自动部署许可。

进度：开发中。
