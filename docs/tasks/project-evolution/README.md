# 项目持续完善：独立任务与实施顺序

目标：项目拥有版本化资产和待办，运行固定引用输入、执行有限任务并留下证据。项目持续反馈关系不能直接变成带环执行 DAG。

| 顺序 | 独立任务 | 分支 | 状态 |
|---|---|---|---|
| 1 | 项目资产版本、候选采纳与不可变资产快照 | codex/project-asset-versions | 已完成基础实现与验证 |
| 2 | 运行绑定快照、运行计划与重跑模式 | codex/project-run-modes | 已实现并接入验证 |
| 3 | 全节点统一发现与项目级归并 | codex/project-discoveries | 已实现并接入验证 |
| 4 | 项目任务图、影响分析与有界调度 | codex/project-task-dag | 已实现并接入验证 |
| 5 | 全局增量规划、提案审查与版本采纳闭环 | codex/project-incremental-planning | 已实现并接入验证 |
| 6 | 节点评测、整体比较与集成验收 | codex/project-evolution-evals | 已实现并接入验证 |

各任务分支承接已完成依赖。不能以数据库表或 UI 空壳代替执行接入；未完成的能力不在 UI 宣称可用。

## 任务 1：项目资产版本
- 以稳定资产名组织不可变版本，保存源运行/修订、内容哈希、基版本、依赖和操作者。
- 历史产物显式登记为候选；不自动提升旧审批或模型结论。
- 采纳使用 expectedHead 乐观并发检查；落后候选须重新基于当前版本提出。
- 快照固定已采纳版本及其传递依赖，旧内容不随项目头变化。
- 物料页提供候选登记、内容比较、依赖选择、采纳/拒绝和快照。
- 验收：跨项目拒绝、代理不能审批、并发冲突、依赖成环拒绝、旧快照不变、重启后可读、源内容不被修改。
- 边界：资产采纳不是业务需求审批、用例执行授权或测试通过。此任务的快照保存能力不等于运行已消费它。

## 任务 2：运行计划与重跑
- 先生成不可变 plan：选定资产修订、读取策略、环境/模型/skill 版本、任务范围及预算，再启动。
- 增量完善：使用明确基线和缺口；重跑测试：固定已审核用例；从头生成：仅选定知识与规则，禁止旧生成成果与经验；重新建档：新资产演进分支，保留历史但隔离读取。
- 实际宿主输入、检索、准备经验均落实读取策略，不只在 UI 标记 clean。
- 运行创建幂等、快照与执行输入哈希一致、恢复不漂移；重跑不等于交易账户重置。
- UI 计划预览说明继承/排除项；删除操作保持独立。

## 任务 3：发现记录
- Explore/probe/trial/execution 共用发现结构：观察、来源回执、状态、假设、影响范围、建议类别。
- 跨运行归并只合并身份和引用，不把重复推断当独立证据。
- UI 有未归类/待确认/已关联/驳回；单用例不能静默改业务验收。
- 验收：假证据/跨项目拒绝，重复回执不增计数，追加冲突证据保留双方。

## 任务 4：项目任务 DAG
- 任务绑定目标修订和输入快照，依赖必须已满足；循环反馈展开为新任务代次。
- 影响分析沿资产依赖传播，区别历史成功与当前适用性。
- 领取租约、并发去重、幂等完成、失败恢复、预算/停止条件；不可未经审查执行交易准备。
- 验收：多 worker 不重领、进程重启、循环拒绝、过期输入重新规划、无关资产不重跑。

## 任务 5：增量规划
- 宿主读取项目任务及限定资产，合并局部发现，产生增量变更提案。
- 支持修改/新增/无变更结论及来源；模块、故事、用例稳定 ID 不因重新生成漂移。
- 业务变化重新审核；路径修复维持原验收。交易 fixture 的归属与清理另行明确，不默认授权。
- 验收：从非空状态的新发现能生成跨运行任务并完善相关故事；不会把所有发现塞到当前用例或污染旧报告。

## 任务 6：评测与整体 UI
- 固定上游输入比较节点版本；全流程比较记录环境状态差异，不误归因模型。
- 指标：能力/转换覆盖、来源正确、重复、遗漏、语义人工复核、实际执行与成本。
- Gold/held-out 隔离，干净运行不能偷读历史答案。
- 独立测试项目验证从建档到两轮增量，再执行干净重跑；对照旧快照和资产变化。
- 真实浏览器验收，合并前记录无法完成的外部依赖，不把渲染测试等同于点击验收。

## 本轮交付边界（2026-09-24）

六项代码沿依赖顺序在独立分支实施，最终集成分支为 `codex/project-evolution-evals`。

- 运行是执行记录；项目资产拥有独立版本和快照。旧运行、旧快照及审批不会被新版本改写。
- 新建运行提供从头生成、基于快照增量完善、独立重新建档。已有批准用例的执行/重跑仍走原有执行入口，不重新生成用例。“从头生成”不重置测试账户，也不删除历史。
- 发现来自系统 Explore、准备和执行回执；领域假设维持候选状态。held-out 结果禁止进入可复用资产和发现库。
- 项目任务固定快照和依赖，租约防止重复 worker；最多三次尝试、四代反馈。输入变更阻断旧任务，操作者创建新计划，不自动改写历史。
- 宿主全局规划生成完整候选修订及后续任务建议；审核任务与采纳资产是两个明确动作。定向探索实际调用 source 节点，但只允许只读规则包，不自动创建仓位或交易 fixture。
- 资产比较提供内容并排、结构指标、输入/环境一致性及人工优劣记录；全运行详细评测继续使用已有迭代评测页。结构指标不替代语义、来源正确性、业务覆盖和实际执行判决。
- 两轮增量的自动测试使用受控宿主回复验证机制，不冒充真实模型质量提升；真实测试网重跑单独留证。
- 当前后台没有常驻自动扫描/无限自愈循环。任务由操作者发起，发现回收自动接入；发现需要分诊、提案需要复核。

验收脚本：`server/scripts/verify-project-evolution-ui.ts` 在临时项目、独立数据目录和后端端口中进行真实浏览器点击，覆盖资产登记/采纳/快照、发现选取、任务创建、人工版本比较及三种运行方式。不调用模型、不操作业务站点。
