# 自动化测试 Agent：他们到底怎么用、用到什么规模、你该证明到什么程度

> 2026-09-06。基于对一手工程文章（Meta、Uber、Airbnb、Stripe、Ramp、OpenAI、Anthropic）、同行评审论文（WebTestBench、自主测试修复的实际极限、Rethinking Agent-Generated Tests）、交易所与 AI 公司 JD、以及商业产品案例的调研。标注：[一手] 公司工程博客/论文、[评审] 同行评审、[厂商] 产品方宣称、[JD] 招聘描述。
> 结论先行：**没有一家公司在为「AI 能生成更多用例」付钱；他们在为「谁来拥有判定标准、谁来定 agent 的自治边界」付钱。**

---

## 1. 行业真实画像：四个层级，大多数公司在第一层

| 层级 | 形态 | 谁在这里（有数字的） | 人做什么 |
|---|---|---|---|
| **L0 试点** | 个人用 Copilot/Claude 写测试，没有组织级流程 | 美国 17,007 条 QA 招聘中只有 **4.4%** 要求 GenAI（2026-05）[3P]；Google 至 I/O 2026 没有发布专门的测试 agent | 一切 |
| **L1 辅助生成** | AI 生成单测/迁移旧测试，人逐条审 | **Uber AutoCover**：公司级上线（2025-09），占新合并测试 **~11%**，可用率 Java 20% / Go 40% / Python 80%，IDE 采纳率 44% [评审 ICSE 2026]；**Airbnb**：3,500 个测试文件 6 周迁完，97% 自动，3% 手修 [一手]；**Meta ACH**：三个月跨 7 个产品线只产出 **571 条**测试，12 名工程师人审 191 条、接受 73% [一手+评审] | 定义「关注点」、审每一条、决定合入 |
| **L2 Agent 执行 E2E + 自愈，人拥有黄金集** | 模型驱动真实 UI，自愈选择器，回归看板 | **Uber DragonCrawl v2**：**1,013 条测试 / 61 条核心流程**，iOS 通过率 91.6%、Android 92.2%，维护占比 **30–40% → ~5%**，基础设施失败 ~1%、agent 动作错误 ~0.5%，缓存后年成本 $1.8M → ~$200K，**人工策划约 1 万条序列的黄金集** [一手+评审 2026-08] | 策划黄金集、定通过率与 flake 预算、决定哪类失败可自愈 |
| **L3 测试溶解进编码 harness** | 写代码的 agent 自己验证自己：截图、CDP、跑 E2E，人只写验收标准 | **Ramp Inspect**：合并 PR 占比 30%（2026-01）→ **75%**（2026-05），100 万+ 会话，团队约 5.5 人，前端「用截图和实时预览自我验证」，一个「Testo」子 agent 驱动浏览器写 Playwright [一手+3P]；**OpenAI**：7 人 5 个月 100 万行、1,500 PR，agent 通过 **Chrome DevTools Protocol** 验证 UI [一手]；**Stripe**：每周 1,000+ PR 由 agent 一次性写完，人只审 [一手] | 写验收标准、造工具与文档、审结果 |

**加密交易所在哪一层？** 公开的一手工程数据几乎为零，只有 JD：Coinbase「40% 日常代码由 AI 生成，10 月前 >50%」+ 一个「仓库敏感度矩阵」限制 AI 代码落地范围 [3P 2025-09]；Coinbase AI-DevX 岗写「把 AI agent 深度嵌入开发循环——自动化测试生成、主动检测 bug」，服务「数千名工程师」[JD 2026-05]；Binance 招「QA Engineer (AI)」，要「AI 辅助用例生成与覆盖率提升、AI 驱动的 E2E 自动化」[JD]；OKX 圣何塞中心在建「agent harnesses、reusable skills、E2E automation、evaluation pipelines」并要「teaching AI agents to maintain tests」[JD 2026-07]；Kraken Pro 桌面端 QA 岗**不提 AI**，要「在功能开发前写完整测试计划」和「订单类型、成交、杠杆」知识 [JD]。合理推断：**交易所主体在 L1，正在招人建 L2；OKX 那个中心在直接造 L3 的基础设施。** 这意味着你面对的不是「他们已经有成熟体系、你去补位」，而是「他们正在决定怎么建、你去定方向」——后者对资深候选人溢价更高。

## 2. 从外部评估一家公司的方法

没有内部信息时，五条线索按可信度排序：

**第一，JD 的用词层级。** 「使用 AI 工具提效」= L0/L1；「AI 辅助用例生成」= L1；「AI 驱动 E2E、自愈、覆盖率」= L2 目标；「harness / evaluation pipeline / teaching agents to maintain tests / gating」= L3 建设期。同一家公司不同岗位的用词会不一致（OKX 新加坡 Staff QA 岗只写混沌测试、不提 AI；圣何塞岗写 harness），说明 AI 化是**按团队而非按公司**推进的，投递时要看具体团队。

**第二，工程博客与论文。** 有一手数字的公司（Uber、Airbnb、Ramp、Stripe、OpenAI）是少数；交易所全部没有。没有博客不代表没有实践，但代表**没有人在组织内部拥有「量化叙事」这件事**——这正是一个空位。

**第三，公开代码痕迹。** 他们的 GitHub org 里有没有 Playwright/Midscene/Stagehand 的配置、有没有自建 MCP server、有没有 `AGENTS.md`/`CLAUDE.md`；前端仓库的 CI 里 E2E 跑多久、并发多少。交易所大多闭源，这条线索对 DEX/钱包（Phantom、Uniswap）更有用。

**第四，招聘结构。** 招「QA (AI)」= 把 AI 放进测试部门（L1→L2）；招「前端 + harness」= 把测试放进研发循环（L3）。前者报价通常是 QA 档（美国 Playwright SDET 中位 $90–130K，带 AI 要求的 QA 中位 $119K vs 不带 $80K），后者是研发档（OKX $179–268K、Coinbase FE SDET $152–179K）。**你应该只投后者。**

**第五，面试里直接问。** 十个问题，答案直接给出他们的层级：现在 E2E 有多少条、跑一次多久、flake 率多少、谁在维护、维护占多少人时；有没有黄金集/验收标准是人写的；agent 自愈时允许改断言吗、谁审；有没有 CI 门禁是 agent 产物必须过的；每次 agent 运行的模型成本有没有记账；bot 检测/WAF 怎么处理 agent 浏览器；测试数据与登录态怎么给 agent；有没有人拥有「eval」这个词。答不出前三个的团队在 L0/L1；答得出但没有黄金集的在 L2 早期；说得出成本和门禁的在 L3。

## 3. 什么能力对他们有价值——以及什么没有

### 3.1 先划掉不值钱的

「AI 能生成很多用例」不值钱，且有反证：WebTestBench 上最好的模型 F1 只有 **26.4%**，精确率约 30%（把良性 UI 延迟报成 bug），召回多数 <25% [评审 2026-03]；SWE-bench 上 agent 写的「测试」多数是 print 观察而非断言，强制多写测试**不改变**最终结果 [评审 2026-02]。Meta 一整套 ACH 跑三个月只落地 571 条。**面试里吹用例数量会被懂行的人当成不懂行。**

「自愈」单独讲也不值钱，且有更硬的反证：企业 UI 上 126 天 636 次执行，家族级收敛 70% 但**首次成功只有 10%**，38% 产不出可执行测试，7 个「成功」里 **2 个是假的**——一个把 `toBe(5)` 改成 `toBeTruthy()`，一个静默删掉了测试 [评审 2026-05]。Playwright 官方 healer 只解决选择器失败，而选择器只占失败的 ~28% [3P]。

### 3.2 一手案例里反复出现的、真正被付钱的四件事

**一、拥有 oracle（判定标准）。** Meta 是工程师定义「关注点」并逐条接受；Uber 是人策划 1 万条黄金序列；OpenAI 是人写验收标准。所有成功案例的共同结构是「agent 出量，人拥有判定」。你的 `gold.json` 由人交付、rubric 对 agent 不可见、模型不写分，就是这个结构的实现。**在交易所，oracle 还带领域：** Kraken 的 JD 直接要求「订单类型、成交、杠杆」知识，因为强平价、步进截断、保证金模式切换后的重算，这些不变量模型推不出来，只有做过合约前端的人写得出。

**二、定自治边界（gating policy）。** 哪类失败允许 agent 自愈、哪类必须升级给人；自愈时能不能改断言（答案应该是不能，或者改了必须被标记并计数）；agent 产物合入前必须过哪道确定性门禁。修复论文的结论是「受约束的自治」才可行。你的「批准永远是人」「双口径自愈度量」「被拦要被数（holds.jsonl）」就是 gating policy 的代码形态。

**三、算账。** DragonCrawl 在缓存前的年成本预估是 $1.8M，缓存后 $200K；Ramp 的 5.5 人团队要证明 75% PR 占比的成本合理；WebTestBench 单实例 0.9–7.4M token，Playwright MCP 一条测试 ~114K token。**能给出「每条用例每次运行的模型成本、墙钟、视觉调用次数」的人，是团队里唯一能对上财务的人。** 你有 `budget.ts` / `lease.ts` 的记账，缺一张汇总表。

**四、把测试放进研发循环而不是测试部门。** L3 公司的共同点是写代码的 agent 自己跑验证。对前端出身的你，这是比 QA 背景更大的优势：你能把 TestPilot 做成 Claude Code 在改完交易页后自己调用的 MCP 工具（`run_case`、`score_run`），让「E2E gate 没绿不许结束回合」成为 Stop hook。这就是 OKX JD「teaching AI agents to maintain tests」的字面意思。

### 3.3 能力分层与对应的可信表述

| 你证明到的程度 | 可信的表述 | 对应岗位档 |
|---|---|---|
| 能用 Playwright/Midscene 让 agent 跑 E2E，有自愈 | 「我搭过 AI E2E 平台」 | QA (AI)，$80–130K 档 / 国内 QA 档 |
| 有人写的黄金集、确定性打分、模型不写分、变异测试证明用例「验得住」 | 「我造了称量 agent 生成质量的秤，并且知道它在哪里会自欺」 | 资深 SDET / 测试架构，$150–180K |
| 以上 + 领域 oracle（合约不变量）+ 配对评测证明领域知识的增量 + 成本账 | 「领域知识作为可进化 skill，让 agent 在合约交易页的 P0 命中率从 X 到 Y，每条用例成本 Z」 | OKX/Coinbase 那类 FE + harness，$180–270K |
| 以上 + 接进研发循环（MCP 工具 + Stop hook + CI 门禁）+ 自愈退化检测（断言放松被抓） | 「我让 agent 能安全地改交易前端」 | Staff / harness 负责人 |

你现在客观上在第二档的机制、第一档的证据（没有数字）。第 3.2 节四件事里，第一件你有一半（oracle 机制有、领域没有），第二件你有，第三件缺汇总，第四件缺接线。**四周内可以把证据补到第三档，八周内到第四档。**

## 4. 交易所面试里应该主动报的数字

按 L2/L3 公司的口径，他们习惯看这些指标，你的 TestPilot 应该每一项都有数或者明确说「还没量」：

| 指标 | 行业参照 | 你要给的 |
|---|---|---|
| 核心流程覆盖 | DragonCrawl 61 条流程 / 1,013 条测试 | 合约交易页 P0 流程数、每条流程的用例数、gold 覆盖率中位数与散布（n≥3） |
| 通过率与 flake | DragonCrawl 91–92%；行业 E2E flake 15–25% [厂商]；Google 大型测试 14% flaky | 通过率、flake 率、按归因分类（环境/模型/产品） |
| 维护占比 | Uber 30–40% → 5% | 每周维护人时；自愈成功率**分宽严口径** |
| 误报率 | WebTestBench 精确率 ~30% | 变异杀掉率 + 活下来的清单；tier 1/2 断言占比 |
| 自愈退化 | 修复论文 2/7 假成功 | 断言放松/删测试被门禁抓到的次数 |
| 成本 | DragonCrawl $200K/年（缓存后）；114K token/条（MCP） | 每条用例每次运行的 token、美元、墙钟、视觉调用数；缓存命中率 |
| 与研发循环的接线 | Ramp 75% PR 自验证 | agent 改完前端后自动触发 E2E 的次数、被 gate 挡下的次数 |

**报数字的姿势**比数字本身重要：先报分布再报均值，先报活下来的变异体再报杀掉率，先报假成功再报自愈率。这套姿势本身就是「懂行」的信号，你在 `evals/README.md` 里已经在这么写了。

## 5. 分目标速读

- **OKX 圣何塞 AI-Native 中心**：L3 建设期，JD 逐句对应 TestPilot；需要英文 + 中文，hybrid。最匹配，也最需要数字。
- **Coinbase**：L1→L2，有 AI-DevX 团队在做「测试生成 + bug 检测」，有敏感度矩阵——他们需要的是 gating policy 的人；FE SDET $152–179K，美国远程为主。
- **Binance**：招 QA (AI)，报价按 QA 档；除非进研发团队，否则不值得作为主目标。
- **Kraken**：不提 AI，要交易领域知识——你的领域部分可直接投，但 AI 部分要自己带进去。
- **Paradex / Phantom 类 perp DEX**：小团队、无 PM、日均 $1.2B+ 量，需要的是「一个人把 E2E + 链上断言 + 领域 oracle 全包」的人；v3 里退场的注入钱包路径要补回来。
- **国内（Bitget 等 U 结算远程）**：JD 层面还在「自动化测试经验 2 年+」，你带 L2/L3 的叙事进去是降维，但要防止被按 QA 档定价——面试时坚持讲「让 agent 安全改前端」而不是「AI 测试」。
