# 领域臂结果 · The domain arm, so far

> 2026-09-07 · 出处：`docs/v3/history/07` T-10 / T-11 / T-12 / T-13；`plugins/testpilot/skills/testpilot-design/REFERENCE-domain-perp.md`；`benchmark/hyperliquid-testnet/materials/rules.md`；`docs/v3/history/06 §6`

## 中文

**问题。** `benchmark/binance-futures/README.md` 里最准确的一句：「对着观察写的用例只能发现产品变了，永远不可能发现产品错了。」领域臂要回答的是：给生成器一份合约交易的**规则**（不是观察），它写出的用例会不会第一次有资格反驳被观察者。

**建了什么（T-10 / T-11 / T-13）。** ① `REFERENCE-domain-perp.md`：10 条合约前端的不变量，每条都写成能变成判据的句子并带 `kind: api` 示例——杠杆分档是从 `meta.marginTables` 抄的真实档位（BTC 40/25/10x），不是文档里那句泛话；作为一个**可选文件**，装 / 卸它就是一臂（`ABLATABLE.domainPerp`）。② 材料从「观察」变成「观察 + 规则」（`materials/rules.md`）。③ 生成器能产出 `kind: api` 判据（ORACLE_STRICT 加了接口判据的行），机器判据不再只有文本。

**已经量到的（不是配对评测，是执行层）。** hyperliquid-testnet 的 7 条 P0 全部用接口判据，判决 100% `decidedBy: machine`。首跑 A 那次「市价开多 0.001」成交了 0.17365 BTC（两笔：0.1724 + 0.00125），屏幕上看不出来，`szi eq 0.001` 一眼——这一档的口径就是为这类事立的（`06 §6`）。

**没量到的（T-12，blocked）。** 装 vs 卸领域 REFERENCE 的配对评测（n ≥ 3，冻结上游）**没有跑**：它要一份人复核过并冻结的 `gold.json`（hyperliquid-testnet 目前只有材料，没有 gold），而 gold 是人的交付物，不能由这个会话代写。所以这篇没有 McNemar，没有 p 值。

**跑之前写下的预判（给 T-12 用，不许事后改）。**
- 方向：**装了 REFERENCE 的一臂在「反驳型」用例上更多**——即 `expected` 里出现「被拒 / 不变 / 不得超过」这类否定句、且判据是 `kind: api` 的用例数。
- 但**覆盖率不一定更高**：10 条规则会把生成器的注意力从观察到的屏幕拉走，`heldOut` 里按屏幕抽的条目可能反而少命中。
- 最可能的白跑形状（见 `01-三次白跑`）：REFERENCE 太长被检索截掉——所以两臂先数一遍产物里 `kind: api` 的比例，再读分数。

**它为什么值得记。** 领域臂是这个项目里唯一一件「只有你能做」的事：harness 是商品，规则是资产。现在资产写好了，秤还没上——这就是 2026-09-07 的真实状态，写下来比写一个漂亮的数好。

## English

**The question.** The most accurate sentence in `benchmark/binance-futures/README.md`: "Cases written from observation can only detect that the product changed; they can never detect that it is wrong." The domain arm asks whether giving the generator the **rules** of perpetual trading (not observations) lets its cases contradict the thing they observe, for the first time.

**What was built (T-10 / T-11 / T-13).** `REFERENCE-domain-perp.md`: ten invariants of a perp trading front-end, each phrased so it can become an oracle, each with a `kind: api` example; leverage tiers copied from the real `meta.marginTables` (BTC 40/25/10x) rather than a generic sentence. It is an optional file, so installing or removing it is one arm (`ABLATABLE.domainPerp`). Materials went from "observation" to "observation + rules" (`materials/rules.md`). The generator can now emit `kind: api` oracles.

**What has been measured (execution layer, not a paired eval).** All 7 P0 cases on hyperliquid-testnet use API oracles; 100% of verdicts are `decidedBy: machine`. On first pass A, "market buy 0.001" filled 0.17365 BTC (two fills: 0.1724 + 0.00125); invisible on screen, obvious to `szi eq 0.001`. This tier exists for exactly that (`06 §6`).

**What has not (T-12, blocked).** The paired eval, REFERENCE installed vs removed (n ≥ 3, frozen upstream), **has not run**: it needs a human-reviewed, frozen `gold.json`, and hyperliquid-testnet has materials only. Gold is a human deliverable and cannot be written by this session. So this post has no McNemar and no p-value.

**Predictions written before the run (for T-12; not to be edited afterwards).**
- Direction: the arm with the REFERENCE produces **more contradicting cases**, meaning `expected` containing "rejected / unchanged / must not exceed" with a `kind: api` oracle.
- Coverage may **not** rise: ten rules pull the generator's attention away from the observed screens, so screen-derived held-out items may hit less.
- Most likely blank-run shape (see `01`): the REFERENCE is too long and gets truncated by retrieval. So count the share of `kind: api` oracles in both arms before reading any score.

**Why it is worth recording.** The domain arm is the one thing in this project only its author can do: the harness is a commodity, the rules are the asset. The asset is written; the scale is not yet on it. That is the honest state on 2026-09-07, and worth more than a pretty number.

## 2026-09-08 补记：秤上了一半，先量出来的是秤自己的问题

换到 DashScope `qwen3.8-flash` 后在 hyperliquid 材料上跑了两臂各 3 次（Claude Code 运行时，`limit 3`）。**先数产物**这一步抓到两件事，所以那六次一个都不算数：

- 装着 REFERENCE 的一臂，`expected` 句句在说 `clearinghouseState…szi = 0.001`，产出的 oracle 却 **0 条 `api`**——`CASES_SCHEMA` 里 oracle.kind 的 enum 没有 `api`，约束解码产不出提示词要的形式。和 2026-08-30 三次白跑同一个坑，第四次。T-13 的验收 ①「领域臂产出 api 判据 ≥ 1」其实从没过。
- 「卸掉 REFERENCE」的一臂三次 meta 里 `ablated: []`：起跑话术里的 `ablate` 被 agent 丢了，因为 skill 写着「不要改参数」。两臂其实同配置——而同配置的 refuting 用例数是 7 / 3 / 11 对 13 / 13 / 13，n=3 的抖动就有这么大。

两处都修了（schema 加 `api` 与它的字段；`ablate` 走 MCP env 兜底 + skill 明说原样传）。修后重跑时 DashScope 免费额度用尽（403 `FreeTierOnly`），0 次成功。上面写的预判一条没动。

**English.** Two arms × 3 runs on the hyperliquid materials after switching to DashScope. Counting the products first disqualified all six: the REFERENCE-on arm wrote `expected` sentences about `clearinghouseState…szi = 0.001` yet emitted zero `api` oracles, because the constrained-decoding schema's `kind` enum lacked `api` (the fourth instance of the 2026-08-30 blank-run pattern; T-13's acceptance ① had never actually held); and the "REFERENCE-off" arm ran with `ablated: []` because the agent dropped `ablate` in obedience to the skill's "do not change parameters". Same configuration, refuting-case counts 7 / 3 / 11 vs 13 / 13 / 13: that is the size of n=3 noise. Both fixed (schema gains `api` and its fields; `ablate` now reaches the tool through the MCP env). The rerun hit DashScope's exhausted free quota (403). The predictions above are unchanged.
