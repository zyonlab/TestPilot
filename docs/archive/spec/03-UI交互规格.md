# 03 UI 交互规格

> **双重身份**：本文档同时是自举时 gold checklist 的来源——每条"可验证的交互契约"都能被抽成一条黄金用例。
> 因此每页都要写出：元素、交互、状态（空/载入/错误）、以及**可验证的断言点**。

## 1. 信息架构

> 2026-09-02 更新：整体 UI 重构（`docs/spec/17`，80/80）落地后的真实结构。
> 上一版这里画的是「十三项平铺的侧栏 + 画布占主屏 + 常驻 Chat 列」，那三样都已经不成立。

**左导航 11 项，三组，按「人在干什么」分**（`src/lib/nav.ts`）：

```
工作                       每天做的事
├─ 复核队列（review）      每天做上百次的那件事，排第一
├─ 运行（wfruns）          所有工作流运行的管理屏
├─ 套件批次（batches）
├─ 物料（artifacts）
└─ 交付（deliver）
素材与质量                 每周看几次、要拿来对照的东西
├─ 测试数据（data）        拿什么测
├─ 测试代码（code）        跑的是什么
├─ 产品地图（map）         测的是什么
└─ 迭代评测（evals）       这套 harness 好不好
配置
├─ 接入（onboard）
└─ 设置（settings）        项目、进程、能力、环境、提示词、偏好都在这里分节
```

> 2026-09-02 二次调整：原来是四组（工作 / 编排 / 质量 / 配置）。两处不成立：
> ①「编排」在原型里指的是**图**（编排 = 图 + 数据与基线），画布降级成运行的详情之后
> 这个组名就悬空了；② 三个只有两项的组——分组是为了减少扫描，两项的组几乎不减少什么，
> 却各占一行组标题，四行标题管十一个条目。合成三组后组标题少一行，
> 四件「要拿来对照但不是每天点」的东西也待到了一起。
> 「交付与接入」同时改回「交付」：它和配置组的「接入」撞名，而英文本来就只叫 Delivery。

**项目是全局上下文，入口在导航底部**（`AppNav.tsx` 的 `ProjectSwitcher`）：
点开是项目列表 + 「新建项目」。此前这一行是不可点的死文字，后果是项目**既切不了也建不了**
——切换只剩 ⌘K 那条看不见的路，新建要走「接入 → 去配置 → 设置 → 项目 → 新建项目」
五步跨三屏。「接入」的页头也有一颗 `新建项目` 主按钮（原型 v3 就是这么放的），
因为那一屏的全部意义就是回答「现在还差哪一条」，而第一条常常正是「还没有项目」。

**断言点**：
- 导航底部点开能切项目，也能新建；Esc 与点击浮层外都能收起；
- 「接入」页头的 `新建项目` 与导航底部的 `新建项目` 打开同一张表单（`NewProjectDialog`）。

**同一个对象的不同镜头不占导航项，改成页头上的 tab**（`src/lib/surfaceTabs.tsx`）：

| 导航项 | 页头 tab |
|---|---|
| 复核队列 | 复核队列 · 用例看板 · 需求追溯 |
| 套件批次 | 套件批次 · 执行记录 · 趋势 |
| 测试数据 | 测试数据 · 待审批基线 |
| 测试代码 | 测试代码 · 变更 |

**地址机制没变**：仍然是一个地址加 `?open=`，`#/?open=cases`、`#/?open=trends` 照样打得开；
换的只是它渲染成一屏还是一个 tab。左导航高亮的是**这一屏所属那一组的落点**——
站在「用例看板」上，高亮的仍是「复核队列」。

**断言点**：任意一屏的 `?open=` 深链在新标签页打开后，落到同一屏，且左导航高亮其所属组。

## 2. 工作流画布（Canvas）★

**定位**：画布是执行图的**真实视图**，不是示意图。它显示什么，运行时就在做什么。

> 2026-09-02 更新：**画布不再是导航里的一项，也不占主屏**。它是「运行」那一屏的详情——
> 从运行列表点「在画布上打开」进入（`?open=canvas&run=…`），站在它上面时左导航高亮「运行」。
> 推翻的理由在 `00-文档地图.md` 的「2026-09-01 · 推翻一条已拍板」：十个 review-heavy 的
> 工具没有一个把画布放在中心。**下面这张表描述的能力一条都没少**，换的只是它的位置。

| 元素 | 交互 | 断言点 |
|---|---|---|
| 节点卡 | 显示：类型图标、标题、状态色、耗时、token、门禁摘要 | 运行中节点必须有区别于待运行节点的视觉状态 |
| 连线 | 拖拽连接；类型不兼容时红色 + 悬浮说明原因 | 非法连线不可保存，且给出可读原因 |
| 选中节点 | 右侧属性面板：参数编辑（zod 驱动表单）、IO 契约、最近一次输入/输出/prompt | 面板内容与该节点最近一次运行一致 |
| 右键菜单 | 只跑此节点 / 从此节点续跑 / 设断点 / 查看轨迹 / 复制产物 | 三种调试模式全部从这里发起 |
| 顶栏 | 图版本选择器、保存（产生新版本）、与另一版对比、运行/暂停/取消、预算与花费 | 保存后版本号 +1；历史运行仍指向旧版本 |
| 布局 | elkjs 自动排布 + 手动微调；缩放/平移/小地图 | — |
| 状态 | 空态（未选图，引导创建）/ 载入 / 运行中（实时推送）/ 已暂停（断点） | 暂停时明确显示停在哪个节点、为什么停 |

**运行实时性**：节点状态、日志、产出全部走 WS 推送（见文档 06），不轮询。

## 3. 三种调试的 UI 形态

| 模式 | 入口 | 展示 |
|---|---|---|
| ① 拆解调试 | 画布上 pin `plan.*` 子图 → 运行 | **覆盖矩阵**：gold checklist × 生成用例，命中/遗漏/多余三色；顶部给 Coverage 数值与遗漏清单 |
| ② 结构调试 | 复核队列或画布节点上"抽样 1-2 条" | 门禁①逐条判据表：判据、命中、证据片段、建议 |
| ③ 单例贯通 | 用例详情页"走阶段二" | 三栏：文本用例 / 生成代码（含静态门禁标注）/ 执行轨迹（截图+步骤+断言结果） |

## 4. 进程（Processes）　🟡 已实现（缺 CPU/内存、能力进程、日志筛选）

> 2026-09-02 更新：它不再是顶层页，而是**「设置」里的一个分节**（`SettingsDrawer.tsx`）。
> 一个每周看几次的东西不该和每天用上百次的复核队列平起平坐。

每进程一张卡：类型徽标、pid、状态（spawning/alive/draining/crashed）、启动时间、重启次数、CPU/内存、最后心跳、当前任务、累计 calls/tokens/耗时、日志尾巴（可展开）。
操作：重启、停止、杀掉当前执行。能力进程额外显示 recipe 名与健康检查结果。
断言点：杀掉一个 runner 后，页面在 3 秒内反映其状态变化，且不影响其他进程卡。

## 5. 用例看板（Cases，改造）

在现有 P0/P1/P2 分列基础上增加：判定 tier 徽标（1/2/3）、设计方法标签、门禁①分数、退化标记（曾被自动改过断言语义或曾被删除重建）、故事归属。
筛选器：按 tier / 设计方法 / 门禁分数 / 退化标记 / 故事。
断言点：切换筛选后列表条数与顶部统计一致。

## 6. 复核队列（Review，新增）

来源：门禁①不合格项、门禁②放弃项、带退化标记的用例。
交互：**三栏工作台**——队列 300px / 详情 / 背景 268px，各自滚动、一起撑满视口（不是一根居中的阅读列）。
右栏三节固定顺序：**进度 / 产物 / 这次它看得到什么**。
详情内可直接编辑文本用例、重新打分、重生成、批准进入阶段二。
键盘：`J`/`K` 移动光标（详情跟随）、`X` 多选、`A` 全选、`1` 批准、`3` 打回。
批量操作走**底部浮起的批量条**，只在有选中时出现；查找替换 / 优先级 / 前置条件 / 还原 / 重生成
折在它的「批量调整」里。

断言点：
- 批准后该条从队列消失并出现在 `approved` 状态；
- 这次运行没绑定项目时「批准入库」必须禁用，且页头写出原因（选中项目后才启用）；
- 光标位置写进地址（`?peek=`），换一台机器打开同一链接落到同一条。

## 7. 评测页（Evals，新增）

- 运行一次评测：选 gold checklist + 图版本 + 消融配置。
- 结果卡：Coverage、Precision/Recall/F1（Fail 为正类）、**滑向判定**（误报型 / 漏报型 / 均衡）、成本。
- 配对比较：选两次 eval → 差值、McNemar 的 nAB/nBA/p 值、逐题翻转清单。
- 断言点：同输入同图版本跑两次，结果一致（可复现性自检）。

## 8. 能力（Capabilities）

> 2026-09-02 更新：两处变了。
> ① 能力不再是顶层页，是**「设置」里的一个分节**；
> ② **那条常驻的 Chat 列已经删掉**——一条永远在场的对话栏是在宣告「这个产品主要靠聊天驱动」，
> 而它不是。提问改成**挂在条目上的 composer**：选中一条用例或一次运行，再从那里问，
> 「你现在问的是哪一条」由它所在的位置回答，不需要另写一句解释（见 `docs/spec/17` 的 P4）。

能力列表（recipe 名、状态、健康检查、端口/参数、起停按钮）；产出 recipe 草稿 → 校验 → 保存 → 启动。
断言点：生成的 recipe 必须先通过 schema 校验才出现"保存"按钮。

## 9. 全局交互约定

1. **长任务**：本地模型一步几十秒——所有可能超过 3 秒的操作必须有进度、可取消、可后台化（切页不中断）。
2. **实时**：一条 WS 订阅全部；断线自动重连并补拉断线期间事件（按事件 id 续传）。
3. **空态**：每个列表页都有空态文案与下一步引导（现有 Projects 页的做法保持）。
4. **错误**：统一错误卡（code + 可读原因 + 重试按钮），不吞异常。
5. **i18n**：zh/en/ja 三语，新增文案一律走 `t()`；断言点：切换语言后无硬编码残留。
6. **可访问性**：键盘可达、focus 可见、色彩不作为唯一状态区分（tier/状态色都配文字或图标）。
