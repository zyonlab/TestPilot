## 0. 接手指引（三分钟）

```bash
# 1. 看总进度
node scripts/plan.mjs

# 2. 看下一批可以动手的任务（依赖已满足且未做）
node scripts/plan.mjs --next

# 3. 认领一个
node scripts/plan.mjs --set U-07 doing
# 做完
node scripts/plan.mjs --set U-07 done
```

状态只有五个值，写在每个任务块的 `- 状态：` 那一行，**这一行是唯一的真相源**：

| 值 | 含义 |
|---|---|
| `todo` | 没开始 |
| `doing` | 有人在做（写上是谁/哪天，避免撞车） |
| `done` | 做完**且验收判据全过** |
| `blocked` | 卡住了，必须在任务块里写清被什么卡住 |
| `dropped` | 决定不做，必须写清理由 |

**做完一个任务就在 §9 执行记录里追加一行**，写清「改了什么、什么出乎意料」。
出乎意料的那部分比改了什么更值钱——这个仓库的注释之所以有用，就是因为它记的是失败。

### 三条接手纪律

1. **行号是写作时的快照，会漂。** 每个任务给的是**符号名 + 文件**，行号只作参考。
   动手前先 `grep` 符号名确认它还在。
2. **不要重新评审。** 依据见 §1。那些结论是走过真 UI、通读过 `server/src` 与
   `packages/harness-testing/src` 得来的，重做一遍很贵而且会因为记不全而退化。
3. **P0 那一批不改界面长相。** 它们改的是「界面对自己状态的陈述」。
   在一个会把「拿不到判决」画成「已隔离」的界面上做呈现改造，只是把假话渲染得更好看。

## 4. P0 · 事实与正确性

> 这一批的共同点：**改完之后界面看起来几乎一样，但它不再说假话。**
> 每一条都能写成一个测试——因为「界面说的话对不对」是个可判定的问题。

#### U-01 · 空态卡不再盖住真实产物
- 状态：done
- 兑现：BOOT-01 · US-LIFE-01
- 为什么：实测 `server/.data/testpilot.db` projects=0、test_cases=0，而 `workflows.db` wf_runs=80（done 78）、wf_node_outputs=381、磁盘 61MB 截图。挂载时会自动落到「这张图最新的一次运行」把产物铺满画布，而空态卡的条件只有 `!projects.length`，与画布上有没有产物无关；它是 `absolute inset-0 z-10` 且 pointer-events-auto，**正好压在画布中央的节点上，那些产物既读不了也点不到**。
- 改：`src/pages/Workspace.tsx`（`!projects.length &&` 那个分支，约 :1236）、`src/lib/wf.ts`（`load` 里落到 latest 的那段，约 :362）
- 验收：① 0 项目 + N 次历史运行时，历史产物仍可见可点开；② 全仓前端 grep 不到覆盖整块画布的 `inset-0 z-10` 空态层；③ 空态同时说出「还缺什么」与「这台机器上已经有多少次运行」
- 依赖：—

#### U-17 · 编辑模式下拓扑与参数是同一个草稿，一次保存
- 状态：done

- 改：`src/lib/wf.ts`（`saveNodeParams` 约 :884、`saveTopology`）、`src/pages/Workspace.tsx`（参数块的保存按钮，约 :1317-1325）
- 验收：同时改一条边和一个节点参数，保存一次，版本号只 +1，diff 同时含两处
- 依赖：—

#### U-18 · 保存带 note；只挪位置不立新版本
- 状态：done
- 兑现：ORCH-23

## 11. 红线

1. **不要在 P0 之前做 P4。** 在一个读不到事实的系统上做 chat，产出的是语气正确的空话，
   而它会看起来像是成功了。
2. **不要顺手换掉 `ModelClient`。** 前置是两件事：把那五条实测行为写成测试钉住、
   给 `requestKey` 一个迁移映射。做完这两件之后再换。
3. **不要 bump `PROTOCOL_VERSION`。** 前置是加一次版本协商与「请刷新」提示；
   今天三处硬拒绝、无协商，会**永久搁浅已打开的标签页**。
4. **不要把 AG-UI / parts 的形状写进 `events.db`。** 事件是事实，parts 是投影；
   两份都能写就会有两份不一致的历史。
5. **不要给 `chatRole=none` 的故事加 chat。** 64 条里有 35 条，它们的正确形态是
   表格、表单和按钮——那些形态把「有哪些选项」摆在明面上，而对话会把它藏起来。
6. **不要继续加产物卡。** 「每类产物一张卡」随类型数线性劣化。

#### 撞出来的、原计划里没有的问题

**同一毫秒起的两次运行会拿到同一个 id。** `wf-${Date.now().toString(36)}` 没有随机位，

是写 U-64 的中断测试时撞出来的：第二个用例读到了第一个用例的产物。

**「带覆盖」这枚标签一开始每条运行都带着。** 因为 `paramOverrides` 记的是最终生效的
全部参数，而项目材料的自动注入每次都会往里写一笔。一个永远亮着的标签什么都区分不出来。
分成两份：`paramOverrides` 是**生效的全部**（复现要靠它），
`requestedOverrides` 是**人自己要求的那一份**（标签看它）。

**手册的行号：机器补做时先把事情做坏了一次。** 第一版按 `git diff` 移位，
而 `docs/refactor/` 根本没进版本库，diff 的基线是一个更旧的提交——
于是 21 处引用被推到了文件末尾之外。撤回之后改成**按标识符对准**：
`budgeted` 该指向 `budgeted` 的声明行，与「上次是哪一版」无关。这一条写进了脚本的注释里。
