## 已拍板的边界（不再讨论）

| 项 | 决定 |
|---|---|

| grounding | 不做（视觉定位归 Midscene） |
| 交互入口 | Web UI；CLI 仅用于 CI / 离线评测 |
| 画布 | ~~可编辑，且是执行图的真实视图~~　**这一条 2026-09-01 被推翻，见下** |

| 现有功能 | 不允许丢失（视觉基线、性能基线、链上断言、自愈/抖动/批次、环境密钥、导出、趋势、实时调试） |
| 模型 | Qwen3.8-27B-4bit @ `http://127.0.0.1:8000/v1`（key 见 `server/.env`）。**必须关思考模式**：实测同一请求开思考 5.0s 且返回推理文本（`finish_reason: length`），关掉后 1.0s 返回 `ok`。平台自己的调用直接注入 `enable_thinking:false`；Midscene 没有 per-request body 钩子，其流量走 `model-proxy` 能力（:8010 → :8000，随网关自启） |
| 框架 | 按 core / domain-pack 边界写，**阶段一不拆包**，阶段二末再抽出 |

### 2026-09-01 · 推翻一条「已拍板」：画布不再是中心

原来的决定是「画布可编辑，且是执行图的真实视图」。推翻它的是一次调研，不是偏好：

GitHub / Graphite / Linear / Label Studio / Langfuse / LangSmith / Braintrust /
Dagster / Temporal / Prefect —— **十个 review-heavy 的工具没有一个把画布放在中心**，
全部是「左导航 + 中队列 + 右详情」。canvas-first 只有 n8n。
而 **Dagster / Temporal / Prefect 更是刻意不给可编辑画布**：流程由代码定义，
UI 只负责展示**运行实例**。

TestPilot 是固定 9 步 + 一次跑产出上百条待人复核的物料，属于前一族。
所以画布**降级为「编辑拓扑」一个动作**（`docs/spec/17` 的 U-41），
而不是被删掉——「执行图的真实视图」这半句仍然成立，只是它不该占着主屏。

**这一条推翻的范围仅限画布的位置。** 同一张表里的其它边界（不加审批、不做 grounding、
现有功能不允许丢失等）没有变，其中「现有功能不允许丢失」在 17 里被当成红线继承。

## 文档的双重身份

02 与 03 不只是给人看的：它们是阶段二自举时**喂给 harness 的真实输入语料**。因此写作时必须保持机器可读的规整结构——故事有 ID、验收标准有编号、状态机显式列出。改这两份文档等于改测试输入，需同步跑一次自举评测。
