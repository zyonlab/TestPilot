# 15 · 文献

这份清单只列**这个项目真的用到、或真的该用而没用**的工作。不列「相关领域概览」——
一份没人读过的参考文献，比没有参考文献更糟。

每一条标了三样：**我们哪里用到它**、**把握程度**、以及**如果没用到，为什么**。

> **把握程度**：✅ 出处我有把握；⚠️ 内容有把握、**卷号/年份需核对**；❓ 只知道有这个方向。
> 正式投稿前，⚠️ 和 ❓ 的都必须逐条核对原文——**一条记错的引用，比不引更伤可信度**。

| 文献 | 我们哪里用到 | 把握 |
|---|---|---|
| **Barr、Harman、McMinn、Shahbaz、Yoo，*The Oracle Problem in Software Testing: A Survey*，IEEE TSE 2015** | **最该引却一直没引的一篇。**我们的 tier 1/2/3 与「判据兑现率」正是对这个问题的一个具体回答：tier 1 ≈ 指定判据（specified），tier 3 ≈ 人/模型充当判据。`exec/oracle.ts` 那段注释讲的就是「一个背后什么都没有的 tier 是装饰」——那正是这篇综述的核心关切 | ✅ |

## 五、我们**没有**引、也不该假装引的

**代码覆盖的基线对不上。**Crawljax / WebExplor 报的代码覆盖是**给被测应用插桩**之后量的。
我们是黑盒的：手上只有一个跑着的产品，没有源码在跑。

诚实的说法是：**我们量的是另一件事。**共有的语言只有状态覆盖 / 0-switch / 1-switch
和状态抽象消融——它们都建立在状态转移图上，不需要源码。**代码覆盖那一栏，就说不比。**

（这一条曾经被我写成一个待办，直到有人问「当前有没有源码？怎么衡量代码覆盖？」
才发现它是一个**错误的目标**。见 `13-…md` 阶段 F。）
