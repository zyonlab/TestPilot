# 17　实施路线与优先级

> 十七章提了几十项改动。这一章回答的是：**先做哪个，为什么，以及哪些不做。**

## 前置

- 读完这一章不需要读完前面十六章，但**每一项都指回它所属的那一章**。
- [第 18 章](./18-风险登记册.md) 是这一章的另一半：本章说做什么，那一章说做的时候会弄坏什么。

## 一、与《补齐这八处》的关系

那份路线图是**站在 JD 的角度**列的八处缺口；这本书是**站在代码的角度**列的改动。
两者不是一回事，对照如下：

| 路线图缺口 | 本书哪几章 | 状态变化 |
|---|---|---|
| **G1** 闭环没接上（缺口→用例、失败→eval） | 09、14 | 不变，仍是第一优先 |
| **G2** 没有第二个 Agent | 03、04、15 | **降级**——见下 |
| **G3** 多模态判据 | 14 | 不变 |
| **G4** 权限维度 | — | 本书未展开，仍成立 |
| **G5** 数据组合算法 | — | 本书未展开，仍成立 |
| **G6** 跨端 | 15 | 不变（不做） |
| **G7** 触发器 | 13 | 不变 |
| **G8** 结构覆盖率置信度 | 14 | 不变 |

### 勘察带来的两处判断修正

**① G2「没有第二个 Agent」的紧迫性下调。**
勘察显示多 Agent 的**进程机制基本齐备**（监工、重启策略、心跳、票据借出、按进程的花费归因），
缺的是身份、任务交接格式、消息传递（[第 04 章](./04-编排三模式.md)）。
而 [第 15 章](./15-AI-SDK与AG-UI.md) 进一步说明：AG-UI 作为**投影**是便宜的，
但今天**没有对手方**——收益无法验证。
**结论：把 G2 从「建一个 Agent」改成「把契约与接口做出来」，等真有消费者再谈。**

**② 出现了一批路线图没有的、更便宜也更急的东西。**
勘察查出 89 条风险和 77 项一天以内的改动，其中若干条是**当前正在造成损害**的
（血缘被日志挤掉、124/125 的 trace 是空的、2,305 帧不可回放、一个凭证泄漏）。
**这些应当排在所有新功能之前**——它们不是新能力，是止损。

## 二、排序的三条原则

**① 先让指标能承受变化，再改被指标衡量的东西。**
这条来自路线图，勘察之后更强了：[第 14 章](./14-评测体系.md) 发现
**预注册机制本身没有在跑**（48 条评测无人记分），
[第 08 章](./08-Prompt是代码.md) 发现**提示词指纹有洞**（`spec.compose` 不在登记里）。
在这两条修好之前，任何 A/B 的结论都可能是假的。

**② 止损优先于新增。**
正在丢东西的地方（保留、trace、帧、泄漏）先补。

**③ 一次只加一个变量。**
`evals/README.md` 的规矩：两组必须只差一件事。
本书任何一项改动上线时，**不要和另一项同批**——否则评测出来的数不属于任何一个。

## 五、明确不做

集中在一处，免得被反复重提。每一条都在对应章节有完整论证。

| 不做 | 理由 | 章 |
|---|---|---|
| 强版本 Generative UI（模型决定渲染） | 已付过两次代价：三千字符的列头、拼死的英文句子 | 16 |
| 用 AI SDK 替换 `ModelClient` | 五条实测行为 + 全部录像会失效，且失败方式是静默的 | 15 |
| 从 zod 推导 JSON Schema | **会精确重现 priority 全空那个 bug** | 15 / 07 |
| bump `PROTOCOL_VERSION` | 三处硬拒绝、无协商，会永久搁浅已打开的标签页 | 15 |
| 写一个假的 dev agent 演示协作 | 绿掉一栏而什么都没证明 | 04 |
| 跨端第二个端 | 要重做基准/清单/算子/抽象一整套 | 15 |
| 思考链面板 | **没有思考链可渲染**（temperature 0 + 无 reasoning 字段） | 13 |
| 把通过的用例喂回黄金清单 | 闭合一个自己量自己的环 | 14 / 02 |
| 探索记忆（在 1-8 之前） | 会破坏配对评测赖以成立的确定性 | 09 |

## 六、如果只做一件事

**做第 0 期。约一人周，零新功能。**

它的产出是一句可以被验证的话：

> **这套 harness 记得住自己做过什么。**

今天它记不住：血缘只占事件表的 1.47% 且正在被丢弃、124/125 次运行的 trace 是空的、
2,305 帧指向已删除的文件、48 次评测的预判无人记分。

**在这些修好之前，后面每一期的收益都无法被证明**——
因为衡量它们的那套东西自己是坏的。

## 七、这份路线的局限

- **人周是粗估**，含实现、测试与至少一轮评测机时，**不含基准应用出问题的时间**
  （按这个仓库自己的记录，那部分占比不低）。
- **第 4 期的排序没有强依据**。四项之间没有硬依赖，实际顺序应当由那时的产品需要决定。
- **本书未展开 G4（权限）与 G5（数据组合）**。它们在路线图里有设计，但这一轮勘察
  没有覆盖到足以写成一章的程度——**这是本书的一个已知空白，不是判断它们不重要**。
- 勘察是一次静态阅读。**没被列出的地方不等于安全。**
