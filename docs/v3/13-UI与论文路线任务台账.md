## 0. 实施顺序与交付规则

第一条切片：P-01 → P-06 → P-25 → P-02 → P-07 → P-27 → P-08 → P-09 → P-10。交付“真实材料创建 run → 整理结构 → 选择 run → 查看产物 → 断点续跑”，先用最小真实项目打通，再铺开大列表与融合。

随后：P-03 → P-04 → P-26 → P-05；P-28、P-17、P-12 的依赖满足后即可接入，再完成 P-11 → P-20。本地产品验收 P-20 不再依赖正式论文结果、真人用户研究或新 Skill 自进化完成。

研究先从 P-13 → P-14 开始准备；后续 P-15 → P-16 / P-22 → P-18 → P-23 → P-24。P-19 承接候选与 Web 证据联动；P-21 单独验收 RQ5。正式模型实验和真人条件按实际授权与可用数据开展，不伪造时间或审批。

每项：认领 doing → 检查可复用实现 → 写目标契约/迁移 → 实现 UI 与服务 → 通过针对性测试与实际路径验收 → 写 evidence → done。仅原型按钮、仅接口返回成功或仅类型检查都不能满足完整验收。预计规模在第一切片结束后依据实际改动再估算。
