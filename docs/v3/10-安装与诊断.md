# 安装与诊断

> 新增 [Claude Code / Codex 分步实操](14-Claude-Code与Codex接入实操.md)，含首次运行提示、宿主配置发现、停止、排障与当前安装收据限制。当前同一 workspace 只建议安装一个宿主：安装器共用 .testpilot/install.json，两个宿主连续安装会覆盖收据；P-12 计划修复。doctor 是配置/依赖预检，不等于真实 MCP/API/模型联调通过。

当前源码交付；尚未发布到公共插件市场。要求 Git、pnpm 和 Node 22+；服务与 better-sqlite3 的安装/启动须使用相同 Node 主版本。Penguin SDK 使用独立 Node 24+ 子进程。

## Web 用户

在 TestPilot checkout 中运行：

```sh
pnpm install --frozen-lockfile
pnpm setup --entry web
pnpm doctor --entry web
node scripts/testpilot-setup.mjs start --entry web
```

首次安装创建 `server/.env`，已有文件不覆盖。现有 Midscene 配置为执行层；Web 规划层用独立 `TP_PLANNER_*`，初期可填相同模型、地址和密钥，以后分别修改。也可从 Web 项目模型设置覆盖环境默认值。服务重启后加载新的 env，已注册运行仍使用冻结快照。

`start` 启动服务及 Web 开发服务器，停止时关闭两者。终端显示实际端口。Web 进入项目 → 模型 → 工作流 → 导入需求材料 → 开始设计 → 审核 → 生成执行物料 → 执行。本地 Web 审核无需身份验证，选择用例即可批准、拒绝或修改。TP_REVIEW_TOKEN 与旧 reviewer-token 不再使用；审批仍绑定具体版本并记录操作来源。

## Claude Code / Codex

宿主自己提供规划账号与模型。先启动 TestPilot 服务并配置执行模型，然后在 checkout 运行：

```sh
pnpm setup --entry codex --workspace /path/to/your/project
pnpm doctor --entry codex
# Claude Code 使用：
pnpm setup --entry claude-code --workspace /path/to/your/project
pnpm doctor --entry claude-code
```

目录可含空格。安装只添加 TestPilot 的技能和 MCP，保留已有宿主模型、其他 MCP 与配置。Codex 写 `.codex/config.toml` 和 `.agents/skills`，Claude 写 `.mcp.json` 和 `.claude/skills`。在宿主中信任自己的项目并启用项目 MCP，然后让宿主使用 `testpilot-run-c`，调用 `register_run` 选定 TestPilot 项目。服务为阶段、版本与执行提供共同约束。

可选 `--server http://127.0.0.1:5301`、`--project-id <id>`、`--model-env /path/to/models.env`。配置中只存 env 文件引用，不复制密钥。不要使用 `--env-file`：部分 Node 版本会把它当 Node 自己的启动参数提前解析。

本机验证 Codex 0.153.4；0.144.5 调用现有 gpt-6-astra 时服务端拒绝版本过旧。用 `TP_CODEX_BIN` 指向新版；不要为绕过版本问题替换宿主模型。原生账号认证保持在宿主。Codex 无需模拟 Claude hook，服务端阶段门禁独立生效。

另提供 `plugins/testpilot-codex` 的有效 Codex 插件目录。插件使用 `testpilot-mcp` 命令，需要把安装器输出的 `bin` 路径加入启动宿主的 PATH；CLI/MCP 的实际项目级安装已经过握手测试。没有自动修改个人 marketplace 或全局配置。`plugins/testpilot-claude` 的历史 `--plugin-dir` 形态仍依赖 checkout 相邻目录；缓存市场安装请先使用上述项目级安装路径，不能把历史目录模式当成可随处搬动的发布包。

## PenguinHarness

先在 Penguin 中创建 agent，保留该项目的原生规划模型：

```sh
pnpm setup --entry penguin --agent-id <agent-id> --project <penguin-project-id>
pnpm doctor --entry penguin
```

可选 `--penguin-home /path/to/penguin` 用于隔离实例。安装器写技能、hook 和 `system_config.yaml` 内 TestPilot MCP；保留其他工具和原生提示。Node 自动从 `TP_PENGUIN_NODE`、可用 nvm Node 24+ 或当前/系统 Node 24+ 查找，`TP_PENGUIN_BIN` 可覆盖 CLI。没有个人 nvm 路径作为代码默认值。Penguin 的候选评估扩展见 [安装与门禁说明](../../extensions/penguin-evaluation/README.md)。当前 0.2.9 没有页面挂载接口，扩展提供单独标识的配套 UI（默认 7365）；需合并 extensions.json 后重启 Penguin。安装成功不是进化效果证明。

## 升级与卸载

重复相同安装幂等更新 TestPilot 自有内容；同名未托管配置会拒绝覆盖。升级前保留用户自定义 skill。卸载使用安装输出的 workspace：

```sh
node scripts/testpilot-setup.mjs uninstall --workspace /path/to/installed/workspace
```

卸载只删除安装收据中哈希未改变的技能/shim，移除自有 MCP 配置；用户改过的文件会列入保留清单。Penguin 的 workspace 为 agent_state 目录。项目数据、运行物料、原生账号和模型配置保留。Web 是源码进程，停止 `start` 即停止服务；数据和 env 不删除。
