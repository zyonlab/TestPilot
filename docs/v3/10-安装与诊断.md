# 安装与诊断

本文讲从源码安装、诊断、升级与卸载。宿主（Claude Code / Codex / Penguin）里怎么接入、怎么用、怎么排障，见 [Claude Code 与 Codex 接入实操](14-Claude-Code与Codex接入实操.md)。

TestPilot 以源码交付（MIT），没有发布到插件市场。入口是 **Web + Claude Code**：Web 发起的生成默认由本机 Claude Code 规划；Codex 与 Penguin 是实验性入口。

## 前置条件

- Git、pnpm（锁文件 v9，用 pnpm 9 或 10）、Node 22+。`better-sqlite3` 是原生模块，**装依赖和起服务要用同一个 Node 主版本**。
- 已登录的 Claude Code CLI：`claude` 在 PATH 里，或用 `TP_CLAUDE_BIN` 指定。
- 一个 OpenAI 协议、能做视觉定位的模型端点，给 Midscene 执行层用。
- 仅实验性入口需要：Codex CLI（`TP_CODEX_BIN`）；Penguin 需要 Node 24+ 与 Penguin CLI（`TP_PENGUIN_NODE` / `TP_PENGUIN_BIN`）。

> **别用 `pnpm setup` / `pnpm doctor`。** 这两个是 pnpm 自带命令，会先于同名 script 执行（`pnpm setup` 会改你的 shell 配置）。用 `pnpm run setup …` / `pnpm run doctor …`，或者直接 `node scripts/testpilot-setup.mjs …`。下文一律写后者。

## 安装（Web + Claude Code）

在 TestPilot checkout 里：

```sh
pnpm install --frozen-lockfile
node scripts/testpilot-setup.mjs install --entry web      # server/.env 不存在时从 .env.example 复制，已有不覆盖
node scripts/testpilot-setup.mjs doctor --entry claude-code
pnpm build:claude-plugin                                  # 生成 plugins/testpilot-claude/（含本机 tp-config.json）
```

编辑 `server/.env`（只看 `server/.env.example` 里的字段说明）。最少要有执行模型：

```dotenv
MIDSCENE_MODEL_NAME=your-vl-model
MIDSCENE_MODEL_BASE_URL=https://your-provider.example/v1   # 旧名 OPENAI_BASE_URL 也认
MIDSCENE_MODEL_API_KEY=your-key                            # 旧名 OPENAI_API_KEY 也认
# TP_AGENT_RUNTIME=claude-code   不设即 claude-code；可选 penguin（实验性）
```

- `TP_PLANNER_*` 只在 Penguin 托管规划或内部流水线（`run_pipeline`）时需要；Claude Code 用它自己登录的模型。
- 项目设置页里保存的模型配置优先于 env；改 env 要重启服务才生效，已登记的运行继续用冻结的模型快照。
- `build:claude-plugin` 写出的 `tp-config.json` 含本机绝对路径、不进仓库。缺了它，Web 发起的 Claude Code 会话里门禁 hook 读不到配置。改过 `plugins/testpilot/skills/**` 后要重跑它和 `pnpm build:codex-plugin`。

## 启动与停止

```sh
node scripts/testpilot-setup.mjs start      # 同时起 API 与 Web；Ctrl+C 两个一起停
# 或分两个终端：
pnpm server:dev                             # API，默认 :5301（PORT 可改）
pnpm dev                                    # Web，:5300
```

打开 http://localhost:5300。Web 发起生成时，新建运行表单可选规划运行时（默认 / Claude Code / Penguin）；运行登记时定下，续跑沿用同一个。本机起不来的运行时会在创建时被拒（`planner_runtime_unavailable`），就绪检查（`/api/readiness`）也会提示。Codex 不能从 Web 发起，只走宿主入口。

本地审核不需要登录，没有 reviewer token；每次批准/退回记录操作来源（`local-operator`）和所针对的版本。

停止后确认端口没有残留监听，只关自己起的进程：

```sh
lsof -nP -iTCP:5300 -iTCP:5301 -sTCP:LISTEN
```

## 诊断：doctor

```sh
node scripts/testpilot-setup.mjs doctor [--entry <web|claude-code|codex|penguin>] [--model-env <env 文件>]
node scripts/testpilot-setup.mjs --help    # 列出全部子命令与参数
```

不给 `--entry` 时按 `web` 检查。输出一段 JSON：`node`、`host`（宿主 CLI 版本）、`webPlanner`（web 入口时：Web 发起的生成由谁规划）、`plannerSource`、`executorSource`、`reviewer`（固定 `local`、无需认证）、`issues`、`ready`；有 issue 时退出码 1，不打印任何密钥值。它检查：

| 检查 | 适用 entry |
|---|---|
| Node ≥ 22；`server/node_modules/better-sqlite3` 已安装 | 全部 |
| 执行模型：`MIDSCENE_MODEL_NAME` 加 `MIDSCENE_MODEL_BASE_URL`（或 `OPENAI_BASE_URL`） | 全部 |
| `claude --version` 能跑 | claude-code；web（`TP_AGENT_RUNTIME` 不设或为 `claude-code`） |
| `codex --version` 能跑（0.140–0.144 会被标为过旧） | codex |
| `TP_PLANNER_MODEL_NAME` + `TP_PLANNER_BASE_URL`；Node 24+ 与 Penguin CLI | penguin；web（`TP_AGENT_RUNTIME=penguin`） |

web 入口按 `TP_AGENT_RUNTIME` 决定查什么：默认查本机 Claude Code，只有选了 Penguin 才要求规划模型配置、Node 24 与 Penguin CLI。

doctor 只是依赖与配置预检：不发真实模型请求，不测 MCP 会话、登录态或被测应用。`ready: true` 不等于能跑通一次生成。

## 守卫与本机数据

- `server/harness.config.ts` 的 `guard.denyHosts` 是唯一的禁止名单（主网 `app.hyperliquid.xyz` 在上面），命中就不执行。
- 不可逆步骤默认放行（`blockIrreversible: false`）；要整机拦截，设 `GUARD_STRICT=1`。没有按环境的「允许不可逆」开关。
- 数据目录默认 `server/.data`，`TP_DATA_DIR` 可改；本机基准应用目录由 `TP_BENCH_DIR` 给（默认 `~/bench`）。
- `TP_MEMORY_ENABLED=0` 关闭之后新运行的执行记忆，已下发的快照不改写。

## 升级与卸载

重复同一条 `install` 会幂等更新 TestPilot 自有内容；工作目录里有同名但不归安装器管的 skill 或 MCP 配置时，安装器拒绝覆盖。升级前备份自己改过的 skill：`install` 直接复制覆盖，只有 `uninstall` 才按哈希保留改动。

```sh
node scripts/testpilot-setup.mjs uninstall --workspace <安装时的工作目录>
```

卸载只删收据（`.testpilot/install.json`）里哈希未变的文件，移除自有的 MCP 配置段；改过的文件列在 `retainedModifiedFiles`。项目数据、运行物料、env、宿主账号与模型配置都保留。Web 是源码进程，停掉 `start` 即可。

**已知限制：** 收据每个工作目录只有一份。同一目录先后装 Claude Code 与 Codex，后装的会覆盖收据，之后的卸载只清理后装的那个宿主。一个工作目录只装一个宿主。
