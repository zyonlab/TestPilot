## 1. 目标

把需求材料（spec）或对被测网站的探索（explore），变成人能复核、能执行的**端到端 UI 测试**：
产品模型 → 模块树（人冻结）→ 用户故事 → 文本用例 → 设计门禁 → 人工复核批准 → 编译成 Midscene 动作代码 → 浏览器执行 → 导出。

几条不变的原则（细节与出处在仓库根 `CLAUDE.md`）：

- **判决从屏幕读**，不调被测站的接口。
- **领域内容是项目数据**（规则包、领域参考、环境画像），代码里不写死领域词；`pnpm check:domain-neutral` 守着。
- **人把关的两处不交给模型**：模块树冻结、用例批准。自愈不许改 oracle。
- **安全只有一张禁止名单** `guard.denyHosts`；不可逆步骤默认放行（它们是被测功能的一部分），运营方用 `GUARD_STRICT=1` 整机拦。

## 3. 现状（2026-09-16）

- **全流程在两个被测对象上都跑通过**，由 Claude Code 规划：Hyperliquid 测试网从探索到门禁通过；Vikunja 走完复核、编译、执行、导出。
- **每一跑可以量四个节点**：`pnpm exec tsx server/scripts/measure-run.ts <runId> <projectId>`（在 `server/` 下运行时路径写 `scripts/measure-run.ts`）。产品结构、用户故事、文本用例、用例代码四张表，指标全部取自服务端已有的机检（`checkModulePlan` / `checkStories` / `runGate`）。
- **单元循环的材料已瘦身**：领域参考全文只在 `load_run_instructions` 里发一次；词表、易变读数、角色、规则包仍随每个单元发——拿走词表会让故事从「用户做什么」退化成「屏幕上有什么」，这是实测出来的。
- 算 Claude 流水的 token 与成本，要**按 `message.id` 去重**（同一条消息会拆成多行，每行都带同一份 usage）。
- **生成内容有了判据**：`judge`（几句是/否条件，采样多次按统计口径判）。golden 集 `fixtures/judge-golden/`，真实评测 `server/scripts/eval-judge.ts --real`。
- **失败会沉淀**：执行里判定失败、或带理由被驳回的用例自动进回归候选，人批准后进项目回归集（`server/src/regressionCandidates.ts`）。
- **每跑有归因报表**：`GET …/workflow-runs/:runId/report` / 宿主工具 `tp_run.report` / `measure-run.ts`，把信号按固定规则归到模型、上下文、工具、工作流、用例、产品六层。

## 4. 下一步

按优先级：

   - 起跑话术没告诉规划器「被模块冻结门禁挡住时停下来报告」，它会在后续阶段上白烧几轮。

   - `server/package.json` 里还有分叉主网之类的 Web3 脚本，公开前要清。
   - `pnpm setup` / `pnpm doctor` 会跑到 pnpm 自带的同名命令上（`pnpm setup` 会改 shell 配置），文档与 `--help` 里一律写 `node scripts/testpilot-setup.mjs …`；script 名可考虑改掉。
   - `server/.env.example` 里 `TP_WEB_ORIGINS` 的注释还写着 reviewer sessions（已取消）。
   - 代码内部：g2 代码包的 `code[]` 带 `entryUrl`，`CodeCaseSchema` 里没有这个字段；`contracts.ts` 顶部自称「唯一 zod 落点」已不成立；`src/lib/audit.ts` 的类型还照旧 `Decision` 抄，而人工批准的真源已是账本批准事件（见 01 §6、§12）。
3. **这一轮留下的**：
   - 回归集还不会被执行自动带上，现在只是一份清单。
   - 由失败或驳回理由**生成新用例**没做（要调模型，而且写出来还得走一遍完整复核）。
   - `judge` 的「多次采样能暴露不稳定」还没被数据检验：golden 9 条都界限分明，54 次采样零分歧。要加模棱两可的题。

4. **验证还不够的地方**：单元瘦身的收益（用例段约 −23%）与故事质量回升都只各跑了一次；「动作型准则占比」只能在模块树相同的两跑之间比较。

2026-09-16 对照一份 QA Agent 岗位要求补了三块：生成内容的判据、失败沉淀为回归候选、一跑的自动归因。**先写出乎意料的**：

③第 1 项的名字不能叫 rubric：`benchmark/*/rubric/` 是受保护目录，读取规则会拦这个词，所以判据叫 `judge`。

**改了什么**：
- **`judge` 判据**（`exec/oracle.ts` 加一支与纯函数 `aggregateJudge`，采样在新文件 `exec/judge.ts`，每次轮换条件的提问顺序——执行模型温度 0.1，不轮换的话重复问几乎总是同一个答案）。执行器、导出工程（`checkJudge`，采样器原样复制进去）、受限解码 schema、占位剥离、单元契约、前端展示都接上了。门禁加 `judge-spec`（条件含糊、及格线超过采样数记 warn，采样少于 3 记 info），并堵了一个洞：只带 `judge` 的 tier 1 用例以前会被当作有机器判据放过。单元契约里原来那行 `{"kind":"api",…}` 写法换掉了——它紧挨着「永远不要对接口下判断」。生成提示词 `CASES_STABLE` 一条规则改写，`testpilot-design` 跳到 `2026-09-16.2`，两份宿主副本已重建。
