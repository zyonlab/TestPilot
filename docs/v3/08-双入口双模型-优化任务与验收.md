## 0. 目标与接手方式

把衍生品交易前端的专业经验沉淀为可复用的领域规则、测试设计 skill、机器判据和基准，使用户通过 Web UI 或现有 coding agent 都能完成可靠测试，并用受控评测证明专业能力、成本和迭代效果。架构与演示服务于这个目标，也形成可以对外展示的工程证据。

本次用户明确的边界：

- **Web UI 是完整产品入口**：配置两个模型角色，管理项目、workflow、材料和产物，review 后执行与交付。
- **宿主 agent 是另一入口**：Claude Code / Codex / PenguinHarness 安装 TestPilot 后，由宿主现有模型思考、规划和生成；另配 Midscene 执行模型。
- **规划模型**负责理解材料、领域推理、测试设计和修复建议；**执行模型**仅供 Midscene 做页面感知、定位和动作执行。机器 oracle 由确定性代码求值。
- **PenguinHarness UI 负责自进化评估**：比较候选版本、看评估证据、批准晋级或回退。TestPilot 提供领域资产和评测工具，产品 UI 显示当前生效版本与结果链接。

两个角色可以选择同一提供商甚至同一模型，但配置、调用归属和预算必须独立。宿主模式不要求用户再买一个规划模型，也不把宿主凭证复制到 TestPilot。Web 模式需在 TestPilot 中配置规划角色和执行角色；规划配置可通过运行时适配层应用，不能只给一个外部设置页面链接。

### 目标结构（不是当前实现宣称）

```text
入口层       TestPilot Web UI                  Claude Code / Codex / Penguin agent
             两角色配置、项目/workflow/review    宿主规划模型 + TestPilot skill/MCP
                         \                    /
产品服务层    项目、workflow 状态机、运行注册、产物版本、人工决策、成本投影
适配层        托管规划运行时 / 宿主会话适配，能力探测与统一事件
领域能力层    规则材料 → 检索/故事/用例 skill → sourceRefs → 机器 oracle
工具执行层    MCP 校验/门禁/打分 + Midscene（仅执行角色）+ API/DOM/链上求值
事实存储层    SQLite 事务记录 + 不可变物料文件/哈希 + 追加事件

PenguinHarness UI / optimizer
   → 调领域评测工具 → 评估候选 Agent State → 人工批准 → 发布版本指针
   （不接管 TestPilot 的项目、workflow 或 review 页面）
```

Web 托管运行时建议先复用 Penguin 适配器；这是实现建议，N-01 需检查其配置与事件能力。宿主模式不要求打开 Web，但需要可达的 TestPilot 本地服务/runner 来执行和持久化；安装检查应自动发现或给出启动方式。纯离线文件导入可作为降级，不宣称“完全无服务”已支持。

A pipeline 是显式研究/回归对照模式，使用**规划角色**生成；C skill 模式才是宿主规划产品路径。固定阶段顺序由服务/MCP 状态机强制，skill 不可任意跳 gate。A 与 C 的机制比较不能声称“仅改变 skill 版本”；单 skill 进化实验要固定同一运行时和执行方式。

| 实体 | 最小字段与不变量 |

| Episode | scope、来源事件、有效条件、过期条件、version、检索记录；必须记录实际被哪个规划调用消费，不能仅统计写入量 |
