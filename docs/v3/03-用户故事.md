## 0. 角色与人把关的地方

| 角色 | 是谁 | 从哪进 |
|---|---|---|
| 操作者（测试人员） | 本机打开 Web 的人。请求不带 `Authorization`、不带 `x-testpilot-actor` 时记为 `{kind:"human", id:"local-operator"}` | `src/App.tsx` → `src/lib/surfaces.tsx` 的各卡片；工作台 `src/pages/WorkflowBench.tsx` |
| 宿主 agent | 用户自己会话里的 Claude Code / Codex，装了 `plugins/testpilot` | MCP 工具 `tp_*`（`host/registry.ts`）+ 运行工具（`testpilot-mcp/src/server.ts`） |
| 规划器 | 服务端替一次 Web 运行拉起的宿主进程（Claude Code / Codex / Penguin），持运行令牌 | `server/src/claudecode.ts`、`codex.ts`、`penguin.ts`；请求自动带 `x-testpilot-actor: planner-host`（`runtime/hostActorTag.ts`） |
| 服务端 | 拆单元、机检、门禁、定稿、编译、执行、记账 | `server/src/runStages.ts`、`workUnits.ts`、`preparation.ts`、`workflowExecution.ts`、`runLedger.ts` |

**只能由人做的决定**（服务端都走 `reviewerPrincipal` 或 `principal.kind !== "human"` 判定；宿主动作表里标 `operatorOnly`，`host/tools.ts::registerHostDomains` 不注册它们）：

| 决定 | 路由 | 服务端函数 | 界面 |
|---|---|---|---|
| 冻结模块树 | `POST …/workflow-runs/:runId/modules/freeze` | `moduleStage.ts::freezeModulePlan` | `NodeDetail.tsx`（modules 节点） |
| 确认 / 驳回候选故事（仅当故事带 `requirementDraft`） | `POST …/story-requirements/approve`、`/reject` | `storyReview.ts::approveStoryRequirements` / `rejectStoryRequirements` | `StoryRequirementsReview.tsx` |
| 复核用例：修改 / 批准 / 驳回（驳回要 ≥4 字理由） | `PATCH`、`POST …/:runId/review` | `approvedRuns.ts::reviseReviewedCase` / `decideRevisions` | `ProjectReview.tsx`、`WorkflowRuns.tsx::RunDetail` |
| 决定回归候选 | `POST …/regression-candidates/:candidateId` | `regressionCandidates.ts::decideRegressionCandidate` | `RegressionCandidates.tsx` |
| 立执行基线 | `POST …/executions/baseline` | `executionBaseline.ts::setExecutionBaseline` | `ExecutionCompare.tsx` |
| 确认界面事实候选 | `POST /api/projects/:id/fact-candidates/:candidateId` | `factCandidates.ts::decideFactCandidate` | `FactCandidates.tsx` |
| 冻结标准集、发起评估、换执行模型 | `…/standard-sets/:setId/freeze`、`…/standard-evaluations[/:id]` | `standardSets.ts::freezeStandardSet`、`standardEvaluation.ts::startEvaluation` / `decideEvaluation` | `StandardSets.tsx` |
| 存知识库新版本 | `POST …/knowledge-library/:kind` | `knowledgeLibrary.ts` | `KnowledgeSelect.tsx` |

CLAUDE.md 与 02 §0 写的是「三处」（模块树、复核、回归候选），那是**流水线会停下来等人**的三处；上表后几行是**流水线不等、但只有人能落笔**的决定，2026-09-24～28 陆续加上。候选故事审核是条件性的第四个停点：只有规则包里的规则是 `hypothesis` 时才会触发（`storyReview.ts::markCandidateStories`）。

**这条红线还没彻底封死**（02 §10-1，核过仍成立）：人的判定只看请求头。MCP 这一路已经按 `operatorOnly` 过滤，规划宿主进程树里的 node/curl/wget 会被自动打上 `x-testpilot-actor`；刻意去掉请求头仍能冒充。

## E1 项目与环境

**E1-1 建项目、改项目、删项目**
作为操作者，我要登记一个被测产品（名字 + 目标地址），以便后续运行、规则包、用例都挂在它下面。
- 新建时 `targetUrl` 必须是 URL；可带探索屏数上限 `explorationMaxScreens`（0–50）与探索范围 `explorationScope`（`current-url` / `rules`）。
- 删项目必须是人：`intentPolicy.ts` 对 `DELETE /projects/:id` 调 `reviewerPrincipal`，带宿主标记的请求 403。
- 代码落点：`server/src/index.ts` 的 `/api/projects` 路由组；`src/pages/Projects.tsx`（设置抽屉里）、`src/components/NewProjectDialog.tsx`；宿主 `tp_project.create/update/remove`。

**E1-2 选这台机器上由谁规划**
作为操作者，我要看到本机 Claude Code / Codex 是否已安装、已登录，并为这个项目选一个，以便 Web 发起的运行有宿主可用。
- `GET …/planner-host` 探测两种宿主，状态是 `ready / unavailable / signed-out / unknown`；只有一个 ready 时自动选它。
- 选的宿主没 ready 会 409 `planner_host_not_ready`；新建运行时没选会 409 `planner_host_selection_required`。
- 只能选 `codex` 或 `claude-code`：Web 表单固定发 `planner:'connected'`，Penguin 从这里选不到（API 仍接受 `planner:'penguin'`）。
- 代码落点：`server/src/plannerHost.ts::hostStatus` / `selectHost` / `requireHost`；`src/components/PlannerHost.tsx`；`workflowOps.ts::createWebWorkflow`。

**E1-3 配环境：基址、视口、登录态、钱包**
作为操作者，我要给项目配一个或多个环境并把登录会话存进去，以便探索与执行能进到登录后的那一半产品。
- 环境可增删；会话可以现场抓（`capture-session`）、直接写入（`set-session`）、配接口登录（`api-login`）或清掉。
- 环境画像里的 `injectWallet` 决定探索默认带不带钱包（`createWebWorkflow` 里 `exploreWallet` 未给时取它）。
- 代码落点：`server/src/index.ts` 的 `/api/projects/:id/environments`、`/api/environments/:id/*`；`server/src/environmentInput.ts`、`sourceSessions.ts`；界面 `src/components/SutPanel.tsx`；宿主 `tp_project.environments/add_environment`、`tp_settings.capture_session/set_session/api_login`。

**E1-4 存密钥，但永远不回显**
作为操作者，我要把账号、私钥一类的值存成项目密钥，以便用例里用占位符引用，而值不出现在任何产物或宿主对话里。
- `GET …/secrets` 只返回名字；执行前 `workflowExecution.ts::missingPlaceholders` 查占位符缺哪个。
- 代码落点：`server/src/vault.ts`、`index.ts` 的 `/api/projects/:id/secrets`；宿主 `tp_project.secrets/set_secret/remove_secret`（registry 注明「值永远不返回，也不该问」）。

**E1-5 接入清单：还差哪几条**
作为第一次用的人，我要一屏看到「离第一批可复核用例还差什么」，以便知道先修哪一项。
- 判定全部由服务端算（`GET /api/readiness`）：守卫禁止名单、环境登录态、能力健康检查等，状态只有四种。
- 代码落点：`src/pages/Onboard.tsx`；`server/src/index.ts` 的 `/api/readiness`。

**E1-6 测试数据集** [遗留]
作为操作者，我要给项目上传一张表并预览列名解析，以便数据驱动的用例导出时带着数据走。
- 落库前可 `POST /api/datasets/preview`；用例可读自己绑定了哪一列（`/api/cases/:id/data-binding`）。
- 绑定的是旧看板用例（`/api/cases`）；工作流的准备与执行路径（`preparation.ts`、`workflowExecution.ts`）不读数据集。
- 代码落点：`server/src/datasets.ts`；`src/pages/Datasets.tsx`；宿主 `tp_project.datasets/add_dataset/preview_dataset`。

## E2 领域知识与规则包（项目数据）

**E2-1 管理规则包**
作为操作者，我要上传、查看、解绑项目的规则包（动作词表、`sideEffectLabels`、`volatileReadings`、业务状态流转等），以便领域规则以数据而不是代码的形式进运行。
- 按内容哈希存版本，重复上传幂等；新建运行时规则包校验不过当场 400 `invalid_rule_pack:…`。
- 没显式选规则包的运行用**项目当前那一份**（`rulePacks.ts::currentRulePack`）；由宿主或带令牌的请求上传的记为 agent 起草，不会被静默当成当前版。
- 代码落点：`server/src/rulePacks.ts`；`index.ts` 的 `/api/projects/:id/rule-packs`；`src/pages/RulePacks.tsx`；宿主 `tp_project.rule_packs/add_rule_pack/remove_rule_pack`。

**E2-2 管理领域参考**
作为操作者，我要按版本存一份「这个产品有哪些不变量」的文字，以便用例能拿它去反驳产品，而且每次运行用的是哪一版查得出来。
- 运行开始时把最新一版冻结绑进账本（`knowledge/domain-reference`），下游只认绑定的那份；被运行用过的版本删不掉。
- 没有就是没有：代码不替任何产品补一段。
- 代码落点：`server/src/domainReferences.ts::saveDomainReference` / `bindDomainReference` / `boundDomainReference`（在 `workflowOps.ts::createWebWorkflow` 与 `runService.ts::registerHostRun` 里绑定）；`src/pages/DomainReferences.tsx`；宿主 `tp_project.domain_references/add_domain_reference`。

**E2-3 用对话抽屉起草领域内容**
作为操作者，我要和模型聊出一份规则包 / 领域参考 / 领域知识的草稿，以便不用手写 JSON 也能把领域内容交给项目。
- 字段草稿有三种：`rulePack`、`domainReference`、`domainKnowledge`，各自带输出 schema。
- 代码落点：`server/src/fieldDraft.ts`、`chat.ts`；`POST /api/chat`、`GET /api/chat/fields`（`host-parity.json` 标 uiOnly：这正是宿主自己在做的事）。

**E2-4 新建运行时选知识库版本** [部分]
作为操作者，我要在新建运行表单里选一版领域知识与一版规则包（或不选），以便这次运行的输入是确定的。
- 知识库列出项目版本和**内置示例的只读条目**（`examples/<id>/`，现在只有 `hyperliquid-testnet`），id 为 `builtin:<hash>`。
- 存新版本只能是人（`POST …/knowledge-library/:kind`，宿主不注册 `save_knowledge_library`）。
- 注意：知识库的「领域知识」（`domain_knowledge` 表）和 E2-2 的「领域参考」（`domain_references` 表）是**两张表**，分别由表单选择与运行开始自动绑定进入运行。
- 代码落点：`server/src/knowledgeLibrary.ts`、`examples.ts::loadExamples`；`src/components/workbench/KnowledgeSelect.tsx`。

## E3 新建运行与运行控制

**E3-1 从一个网址探索出一次运行**
作为操作者，我要给出被测地址、选探索深度，让系统先把产品走一遍，以便没有需求文档也能生成用例。
- 表单默认来源是「探索」；可勾「带钱包」「允许点会改状态的东西」（后者发 `exploreActions:"interact"`，界面给出警告）。
- 地址在 `config.guard.denyHosts` 上直接 403 `explore_host_denied:<host>`（主网在上面）。
- 提交分两步：先生成运行计划预览（模式 `clean / incremental / rebuild`，增量要选快照），再点一次才启动；表单不变时复用同一个幂等键。
- 代码落点：`src/components/workbench/NewRunForm.tsx`；`server/src/projectRunPlans.ts`（`POST …/assets/plans`、`/plans/:id/start`）→ `workflowOps.ts::createWebWorkflow`；探索见 `explorationPlanner.ts`、`explorationResults.ts`；产品地图 `src/pages/ProductMap.tsx`。

**E3-2 从需求材料起一次运行** [缺口]
作为操作者，我要贴一段需求文字或上传最多 20 个 `.md/.txt`，以便按文档生成用例。
- 单文件 ≤2 MB、总量 ≤40 MB，重名 400 `duplicate_material_name`，非文本 400 `text_material_required`。
- **缺口（02 §10-2，核过仍成立）**：表单「工作单元」默认勾选，而 spec 来源开了工作单元又没导入产品模型会 400 `work_units_require_product_model`（`workflowOps.ts` 中 `if(input.workUnits&&!imported&&input.sourceKind!=='explore')`）；表单没有导入入口，用户得自己取消勾选。
- 运行列表页另有一个只填材料的简表（`WorkflowRuns.tsx::MaterialForm`），它不传 `workUnits`，不受此影响。

**E3-3 宿主会话里登记一次运行**
作为宿主 agent，我要把用户给的材料登记成一次运行并拿到运行令牌，以便后续每个节点的写入都落在同一本账上。
- 材料在登记那一刻冻结；登记时同样绑定领域参考。
- 代码落点：`POST …/workflow-runs/register` → `runService.ts::registerHostRun`；MCP 工具 `register_run`；skill `testpilot-run-c`。

**E3-4 看进度、停、续、从某个节点重跑**
作为操作者，我要看到每个节点在干什么、停下一次运行、从检查点续跑，或从某个节点分出一次新运行，以便跑偏时不用从头来。
- 进度按节点取（`GET …/progress?node=`），stories/cases 带单元状态，g2 带准备批次状态。
- 断点：`POST …/controls` 设在某节点前停；取消、续跑（可 `mode:'next-node'`）、重跑都要人。
- 重跑只开在 source/modules/stories/cases/gate 五个节点，运行在跑时按钮禁用；返回新的 `wfRunId`。从故事节点重跑会把上一轮的驳回意见带进新运行。
- 代码落点：`server/src/runRoutes.ts`（`/controls`、`/cancel`、`/resume`、`/rerun`、`/checkpoint`、`/progress`）；`workflowOps.ts::rerunProjectNode` / `resumeProjectWorkflow` / `cancelProjectWorkflow`；界面 `WorkflowBench.tsx`、`NodeDetail.tsx`、`WorkflowProgressDock.tsx`、`NodeProgress.tsx`。
- **缺口（02 §10-3/4/12，未改）**：规划器干净停在半路会记成 `failed`；Claude Code 运行重启后不接回；`claudecode.ts` 不接收预算参数，只受看门狗超时约束。

**E3-5 看每个节点用了什么**
作为操作者，我要在节点详情里看到这一步是哪个角色、哪个 skill（带 SHA256）、哪个模型、读了哪些知识，以便出错时知道该怪哪一层。
- 代码落点：`src/components/workbench/NodeDetail.tsx`（`roles`、`skills` 映射）、`nodeKnowledge.ts`、`RetrievalHistory.tsx`；账本里 `validated/instructions` 与 `context/<node>` 修订。

## E4 模块树

**E4-1 规划器提议模块树，服务端机检**
作为规划器，我要提交一棵模块树并读回机检结果，以便人冻结之前就知道哪里不合契约。
- 代码落点：`POST …/stages/modules` → `moduleStage.ts::writeModulePlan`；`…/stages/modules/state` → `modulePlanState`；MCP `plan_modules`、`module_plan_state`。

**E4-2 人冻结模块树**
作为操作者，我要看过模块树后按一下「冻结」，以便下游的故事与用例单元按这棵树拆。
- 按钮只在 modules 节点处于 `waiting_review` 时出现；带宿主标记或 `Authorization` 的请求 403。
- 冻结不拦未关闭的机检发现，但把条数和代码记进回执（`openFindings`、`openCodes`），审计能看到是谁、何时、附了什么说明。
- 代码落点：`moduleStage.ts::freezeModulePlan`；`runRoutes.ts` 的 `/:runId/modules/freeze`；`NodeDetail.tsx::freeze`。

## E5 用户故事、文本用例与门禁

**E5-1 按单元写故事与用例**
作为规划器，我要一次领一个单元（范围、材料、契约都由服务端给），写完只校验这个单元，以便错在哪个单元就修哪个，而不是整份重写。
- 拆分由服务端做（`planUnits`）；开了单元的运行，整份写入被拒（`assertWholeWriteAllowed`）；全部写完后可单独重试合并。
- `validated/`、`units/`、`review/` 等前缀的产物名只有服务端能写，通用导入路由 403 `reserved_artifact_name`。
- 代码落点：`server/src/workUnits.ts::claimUnit` / `writeUnit` / `mergeUnits` / `unitContract`；`runRoutes.ts` 的 `stages/units/*`、`/:runId/artifacts`；MCP `claim_unit`、`write_unit`、`unit_status`、`merge_units`；skill `testpilot-stories`、`testpilot-design`。

**E5-2 候选故事要人确认**（条件性停点）
作为操作者，当故事引用的规则还是假设时，我要先确认或驳回这些「候选业务预期」，以便假设不会直接变成用例。
- 故事带 `requirementDraft` 且未批准时，cases 及之后的节点被标 `blocked`，运行置 `waiting_review`；续跑时 `guardStoryResume` 会再拦一次。
- 驳回必须写 ≥4 字理由（400 `rejection_requires_reason`），版本变了 409 `story_revision_changed`；从 cases/gate 重跑且故事与业务输入没变时，沿用父运行的批准。
- 代码落点：`server/src/storyReview.ts`；`StoryRequirementsReview.tsx`、`BusinessLifecycle.tsx`。

**E5-3 设计门禁打分并把问题送回单元**
作为规划器，我要跑门禁拿到可操作的 findings，不过时只重开被点名用例所在的单元，以便定向返工。
- 分数低于运行绑定的 `policy.minGateScore` 即 `blocked`；只按 warn 重开单元，info 不重开。
- 门禁规则与 A 臂 `run_pipeline`、hook `gate1.mjs` 是同一个 `runGate`；判据从屏幕读，`oracle-offsite` 按用例扣分。
- 代码落点：`runStages.ts::gateRun`；`workUnits.ts::reopenUnitsFromGate`；`packages/harness-testing/src/casegen/gate.ts`；界面 `GateReport.tsx`。
- **缺口（02 §10-14）**：门禁打回后续跑能否把用例写完，代码里确定不了，要实测。

**E5-4 定稿交人复核**
作为规划器，我要在门禁通过后定稿，以便复核面只看到一份不会再变的用例。
- 定稿复查：用例仍过校验、门禁回执指向当前用例、钉住的报告与新算的一致；已定稿的运行不拿今天的规则重判。
- 代码落点：`runStages.ts::finalizeRun`（写 `waiting_review`）。

## E6 复核
