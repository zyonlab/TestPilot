## 1. 为什么改

`run-03387545`（Hyperliquid 测试网，89 条已审核用例）的执行准备 2026-09-25～27 跑了三天，
准备通过数 25 → 33 → 41 → 51 → 54 → 58 → 62 → 70。逐条看修复落在哪里：

| 失败类 | 修复落点 | 下次生成的用例会不会自动避开 |
|---|---|---|
| 执行器 / 服务端 bug（`${env}` 不替换、补偿倒序、假残留、核对不等刷新、12.8s 阻塞、用量报未知） | 代码 + 测试 | 会 |
| 持久设置、一步多动作、会话状态来源、准备不出来的前提 | 规则包 / 门禁 / 准备前裁决 / 节点契约 | 会 |
| **执行语义**：点完立刻核对「没了」、断言依赖当前标签、瞬时提示、收尾认不出自己的资源、配方不如用例自建 | **只改了用例正文** | **不会** |
| **界面事实**：标签带数量、强平价 N/A、历史撤不掉、Order Value 可读 | **只在 scratchpad** | **不会** |
| 保证金弹窗怎么关 | 领域参考里写的是**错的**（「按 Escape」，实测要点 Confirm） | **会再错** |
| 跨步骤读数比较（前后强平价 / 保证金、加权均价） | 无 | 仍然判不了 |

结论：问题主要不在提示词长短，而在**知识放错地方、到得太晚、还有错的**。

## 2. 依据（已核对出处）

| 结论 | 依据 | 在本项目的含义 |
|---|---|---|
| 指令多了主要是**漏**，且偏向前面的指令 | IFScale（arXiv 2507.11538）：500 条时最好的模型 68%，遗漏是主要失败方式 | 准备器被 409 两次后丢了整个 lifecycle |
| 每轮都用的内容常驻，部分用得上的才按需加载；按需加载省成本、不改质量 | Skill Blocks（arXiv 2608.14943） | 执行语义常驻；配方 / 数值判据 / 只读边界按需 |
| 渐进披露**只要一层**，第二层从没帮上、有时毁掉准确率；强 harness 下收益可能接近零 | arXiv 2607.17598 | 不做多层；改完必须回放对照，没变好就退 |
| 目录常驻、正文按需读 | Anthropic Agent Skills（2025-10）；Effective context engineering | skill 的 `REFERENCE-*.md` 已是这个形状 |
| 拒绝时给「怎么改」比事前多写规则有效 | SWE-agent（NeurIPS 2024，带 lint 的 edit 贡献 +3.0pp）；Anthropic《Writing effective tools for agents》 | 所有 409 带修法 |
| 领域知识检索后给，而不是全塞 | RAG-MCP（arXiv 2505.03275，选择准确率 13.62% → 43.13%） | 界面事实进领域参考，`retrieve_spec` 取 |
| 已测过的功能知识要带进后续推理 | GPTDroid（ICSE 2024） | 实测事实回写领域参考，带证据 |
| 把界面元素符号化，每步带前后置条件，能判跨步骤依赖 | WebTestPilot（arXiv 2602.11724） | 跨步骤读数判据 |
| 自然语言 GUI 用例可靠执行要：步骤消歧、界面就绪确认、严格断言 | Software Quality Journal 2026（仅核对摘要） | 门禁 `step-compound`、执行器等刷新、机器判据优先——已有，但来得太晚 |

## 3. 放置原则

| 内容 | 放哪 |
|---|---|
| 每条用例都用得上的规则（执行语义、红线） | 节点契约**常驻** |
| 部分用例用得上的写法（判据能力表、配方与补偿、只读边界、错误码修法） | **一层按需读**（skill `REFERENCE-*.md` / 准备节点 `guide` 动作），读了什么记账本 |
| 产品相关的界面事实、测试市场说明 | **项目数据**（领域参考 / 规则包），**带证据与状态**，检索引用 |
| 不许做的事 | **服务端校验**，拒绝信息写明违反了哪条、怎么改 |
| 跨步骤比较 | **判据能力**（代码） |
| 额度、内存、残留确认 | **系统预检**，不靠提示词提醒 |

不做：多层按需加载；后端按用例特征替模型挑规则；把领域事实写进提示词或代码（`check:domain-neutral`）。
