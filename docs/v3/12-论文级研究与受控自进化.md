# 论文级研究与受控自进化

2026-09-09 · 研究设计草案，尚未预注册、未完成正式实验。目标是把 TestPilot 建成可被独立复核的垂直测试生成 harness agent；本文不保证录用，也不宣称已经证明有效。本文的实验改进建议是基于已核查资料和当前工程证据的推论。

## 1. 研究定位与贡献候选

拟定题目方向：Evidence-Grounded Test Generation for Derivatives Interfaces with a Versioned Harness and Controlled Adaptation（基于证据和版本化 harness 的衍生品界面测试生成与受控适应）。暂不以“首个自动生成 Web 测试的 agent”叙述创新性。

目标对象是需求到可执行测试与可信判据的生成，不是让 agent 自己修好 SUT 后证明自己通过。代码修复是一个独立使用场景；主实验冻结 buggy/fixed SUT，生成器看不到缺陷补丁和隐藏答案。界面顺利执行、文本用例数量、引用了 skill、某一次通过，均不是测试质量本身。

| 贡献候选 | 可证伪主张 | 所需新增机制/证据 |
|---|---|---|
| C1 领域规则约束的生成与判据 | 在相同模型与预算下，更准确地产生能区分正确/缺陷实现的用例 | 产品作用域、时间/单位/精度/状态不变量的结构契约；独立 oracle 与多个缺陷家族；比较去领域规则和纯模型 |
| C2 从需求到证据的可修订关系 | 结构化来源与影响传播减少无依据断言和漏审，且修订可复现 | 版本化模块/故事/验收点/判据关系；独立关系标注；图形 review 与列表 review 的对照任务 |
| C3 在预算与隔离下的受控自进化 | 通过开发集反馈改变策略，在未知任务上保持或提升质量，同时不增加关键误报 | 有界候选空间、固定开发/验证/测试划分、外部评分、配对预算、一次留出与人工晋级；负结果完整保留 |

双模型分工、多个宿主兼容和 Web 管理属于工程贡献；是否构成研究贡献要由对照实验支持。第一篇优先聚焦 C1，C2 是可审查性机制；C3 先以严格的受控适应实验呈现。若 C3 无效，明确报告负结果，不为写“自进化”牺牲结论可信度。

## 2. 最近相关工作及差异

核查时间为 2026-09-09；论文事实以原文为准。没有把外部论文的结果数值当作本项目的效果。

| 相关工作 | 已有内容 | 对本项目的约束 |
|---|---|---|
| [WebTestPilot，2026，v3](https://arxiv.org/abs/2602.11724v3) | GUI 符号化，并将自然语言需求转为带前后置条件的 E2E 测试；包含注入缺陷的 Web 评测 | 与本项目题目和名称高度相近，必须直接比较方法和可执行基线；研究标题突出衍生品领域与可证实的新机制，不能只换名字 |
| [REAG，2026](https://arxiv.org/abs/2608.12970) | 面向 LLM 软件，检索需求/领域知识/persona 构造 oracle，并通过校准的级联判定处理不确定性；页面标注 ASE2026 接收 | “RAG + 领域知识 + 判据”本身不够新；我们的独立程序判据、金融数值/状态规则和冻结因果比较需具体化。任务对象不同，不能直接搬用其分数 |
| [TestGen-LLM，2024](https://arxiv.org/abs/2402.09171) | 生成并筛选已有单元测试的增强版本，使用构建、通过及覆盖条件 | 借鉴可执行筛选；本项目必须另证缺陷检出与错误判据率，不能只看健康实现通过 |
| [CoverUp，2024](https://arxiv.org/abs/2403.16218) | 利用代码上下文和覆盖反馈迭代生成 Python 测试 | 反馈驱动测试生成并非新贡献；若借用其反馈基线，需说明是 E2E 适配，不直接比较跨任务分数 |
| [较新模型复评研究，2026，v2](https://arxiv.org/abs/2601.09695v2) | 复现四种测试生成方法；其数据和指标下，较强 plain LLM 可超过复杂方法 | 必须有强、同模型的简单基线和等预算重试；不能通过过时模型或薄弱提示制造优势 |
| [UTBoost，ACL 2025](https://arxiv.org/abs/2506.09289) | 用增强测试揭示 SWE-Bench 中原测试不足导致的误判 | “补丁通过现有测试”不等于修复成功；独立缺陷判据与错误实现区分力是核心 |
| [GEPA，2025](https://arxiv.org/abs/2507.19457) | 以执行反馈反思和搜索改进提示策略 | 当前一次 memory 开关候选不是 GEPA 复现；自进化应与等预算随机搜索/反思或可运行的 GEPA 适配比较 |

这些资料并非系统综述。正式写论文前建立检索式、日期、纳入/排除规则和复现可用性表；优先复核 WebTestPilot 全文、代码、许可证和任务适配。源代码不可获得时明确记录，不把自行复刻称为官方实现，也不能省掉强 plain LLM 基线。

## 4. 数据集与人工依据

数据单位是独立任务及缺陷家族。每个任务绑定产品版本、需求快照、环境 manifest、可观察接口、正确实现，以及一组独立验证的缺陷实现；多次模型采样嵌套于任务。对同一缺陷生成十条用例，仍只算一个独立缺陷检出。

按产品/规则家族分组切分开发、验证与最终留出，避免仅打散同一需求的改写。先做样本盘点、合法发布条件、难度与规则家族矩阵，再用开发集 pilot 估计变异和效应，进行功效/精度设计确定任务数及重复数。不能把每臂 n=3 当正式规模；在冻结前写明纳入、排除、最小有意义效应、主指标、预算与停止条件。

范围至少覆盖数量/价格边界、拒单与状态一致性、幂等/重复提交、杠杆保证金、只减仓/持仓模式等若干独立家族；这是采集计划，不是当前已有数据。把真实历史缺陷与人工变异分开报告。等价、不可达、不稳定变异由独立规则审查后标识，不事后只移除不利样本；排除前后数量都公布。

金标由实际领域人员根据冻结需求/官方来源建立。至少两位独立标注者对覆盖关系、expected 和缺陷类别进行标注，盲于方法臂，分歧裁决留痕；按标签性质报告原始一致率及合适的一致性指标。不得生成“人类确认”事件。既有 protected assets 保持原样，新增正式数据在独立版本/目录创建，由实际人类冻结。

领域知识库可包含业务规则；私有 evaluator 包含隐藏缺陷标识、测试金标与结果。优化器及生成宿主不能读取后者的文件、HTTP 页面、检索内容或日志。当前 macOS 候选隔离已有验证，普通宿主未因此自动具备同等隔离；正式实验要对所有参试方法提供等价的受限访问。UI 的“只读”不是隐藏。

## 5. 实验设计与基线

| RQ | 主比较 | 主要结果与判定 |
|---|---|---|
| RQ1 领域 harness 是否提高有效缺陷检出 | B0 强 plain LLM、B1 等预算通用检索/执行反馈、B2 可复现的最近 NL→E2E 方法、TestPilot | 独立缺陷检出、健康误报、有效产物率；相同 planner、executor、材料、环境、预算；相关方法能力差异明确记录 |
| RQ2 哪些机制有效 | 完整版本 vs 去领域包、去结构化关系、去确定性判据、去反馈、去记忆，分别单因素 | 不删除运行所需的基本依赖；记录约束失效和输出无效率；次级比较作多重检验校正 |
| RQ3 双模型是否有性价比 | planner/executor 相同强模型、相同廉价模型、强规划+廉价执行；当前相同模型配置作现实基线 | 质量—成本曲线与预声明非劣界；同环境/任务。只换 executor 时 planner 固定；未知价格不补零 |
| RQ4 受控适应是否泛化 | 冻结策略、等预算随机候选、反思/GEPA 适配、TestPilot 有界策略搜索 | 开发反馈→验证选优→单次留出；预算含所有失败候选和搜索成本；负向与无改进结果也发布 |
| RQ5 结构下钻是否改善人工 review | 同数据/权限下图形层级 vs 列表/现有界面 | 漏检错误率、正确修订率、任务完成时间、定位步数、工作负担；真实参与者的随机平衡交叉设计 |

B0 必須是经过开发集调好的合理提示，提供相同公开需求与目标接口；B0 可使用相同输出 schema 和执行器，但不使用被研究的领域/图约束，记录提示。另比较 token/call 预算匹配与端到端时间/费用匹配，不能只选对自己有利的一种。换模型实验与换 harness 实验分开，不用 Claude 与 Qwen 的差异证明框架优势。

消融“去确定性判据”仍要由外部 evaluator 判断是否发现真实缺陷，否则模型自判会污染评价。不能为了测试消融而允许生产流程绕过审核；研究实例与生产权限分离。

## 6. 指标与统计口径

| 指标 | 定义与边界 |
|---|---|
| End-to-end defect recall | 在所有符合预注册条件的独立缺陷实例上，生成用例能在正确实现通过、在缺陷实现因目标行为失败的比例；无效生成保留在端到端分母 |
| Conditional detection | 仅有效生成条件下的检出率，与有效率同时展示；不能替代主指标 |
| False positive rate | 健康任务/实现中被错误报告为产品缺陷的比例；环境故障单列，并给出其数量占总尝试的比例 |
| Oracle correctness | 独立金标检查用例预期与规则是否一致；输入、单位、精度、时间条件分别分析；引用存在不等于语义正确 |
| Requirement coverage | 被独立核验为真正测试的验收条件 / 适用验收条件；另报有效执行覆盖。关键词命中仅作代理指标 |
| Mutation score | 杀死的非等价、可达变异 / 适用变异；真实 bug 检出另报；同家族变异聚类 |
| Validity / failure taxonomy | JSON/schema 有效、可执行、判据有效、健康通过逐层漏斗；truncated、invalid_plan、infra、budget、missing_evidence、assertion_failure 区分 |
| Cost / latency | 全部模型调用、token、缓存、节点时延、p50/p95、重试与搜索开销；按成功任务/独立缺陷同时报告；价格未知为 null |
| Stability | 固定输入/SUT 的重复一致性、flaky 比例、环境噪声；跨夜观察按真实日期，不改时间戳凑样本 |

配对单位是任务/缺陷家族，非每条 case probe。主分析在任务层配对，用聚类 bootstrap 置信区间或合适的层级模型；只有满足独立二元配对前提才用 McNemar 等方法。报告效应量、区间与原始计数，不只 p 值。预声明一个主要结局和有限次级指标；功效不足时报告不确定性，不把“未显著”写成等效。

RQ5 用不同但匹配难度的任务组平衡顺序，避免参与者记住同一答案。预先定义正确修订评分与时间截断，记录放弃任务；招募实际目标用户并取得适当同意，公开匿名汇总而非未经许可的行为轨迹。可用性不能只靠 agent 点击速度。

## 7. 自进化的边界与流程

“自进化”先定义为有界策略适应：改检索预算/规则选择策略/固定结构的记忆策略/技能草稿；不自动改隐藏答案、评价程序、批准策略和 oracle gold。技能内容改动与模型参数微调是不同工作，当前没有训练模型权重。

流程：冻结开发任务与基线→收集失败分类→候选生成→静态/协议检查→隔离运行→开发集评分→固定预算内验证选优→独立留出一次→人工审核→CAS 激活→监测回归→回滚。研究留出不是每次产品晋级都可反复使用的数据池；消耗后该版本测试集退役，下一周期另建测试集。

保留所有候选，包括失败、拒绝、超时、截断和回滚；隔离 canary 失败则不运行。Web 显示当前激活版本、候选所依据的证据摘要和 Penguin 深链；Penguin 展示候选变更 diff、配对结果、失败样本、预算消耗、评估协议及晋级门禁。宿主可以提出和管理候选，不拥有虚构评分或代替人的权力。

控制奖励投机：新增用例数量不作为唯一目标；拒绝缺证时适当 abstain，不能靠少报所有错误获得高通过率；把健康误报和关键缺陷漏报作为独立约束。回归集含领域正确性和行为隔离用例，安全通过也不等于质量提高。

## 8. 复现包与论文结构

每次实验 manifest 固定代码 commit/dirty patch hash、schema/skill/role/domain/workflow 版本、模型 ID/端点类型/采样参数、输入及公开知识 hash、SUT镜像/环境/浏览器/依赖锁文件、试验单位/随机化种子、预算/重试/超时、数据划分摘要和授权范围。LLM 即使设置 seed 仍可能非确定，记录提供商版本和真实响应证据；凭证只保留引用。

复现包包含：安装脚本、无密钥样例配置、任务目录、公开需求与许可、正确/缺陷环境部署、原始尝试索引、外部评分脚本、统计脚本、生成图表、失败样本、排除清单、数据字典、硬件与运行时说明。私有资料说明获取条件并提供可公开替代集；若不能公开主数据，要明确复现限制。

论文建议结构：问题与研究缺口→领域挑战与形式化定义→方法/信任边界→实验设计→主要与消融结果→成本/稳定性→受控适应→人工 review 研究（如完成）→威胁与限制→可用工件。把 UI 截图作为可审查机制证据，不能替代主要实验表。

投稿准备门槛：最近工作差异明确；独立冻结数据完成；同模型强基线可运行；主结果含区间及负结果；消融与成本完整；至少一次独立复现；所有结论能追到实验 manifest。论文级不是新增一个“评测”页面即可达到。
