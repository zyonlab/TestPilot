# 06 执行层降本：30 条 P0 十分钟跑完

> 2026-09-07 起。第四档六项里的第 1 项（`docs/v3/history/00-架构.md` 之外的评审结论，见项目「求职分析」里的
> 《v3 优化项、迁移决策、UI 完备性》）。这一篇记决定、机制、以及**跑完要回填的数**。

## 1. 为什么是它先

BingX 那次（2024–2026）：用 Claude 把产品文档拆成 30 条「影响用户资金」的 P0 故事，劫持账户接口只验 UI，
视觉模型驱动真实 UI——**一个业务线 30 条要跑好几个小时，staging 又变得太频繁**，于是停了。
生成一个下午就完成了；杀死它的是执行成本和环境。v3 至今在生成器上投入最多（九步、单 skill 进化、配对评测），
执行层还是逐步视觉调用——给一辆车装更好的导航，油耗没变。

行业参照：DragonCrawl 缓存前年成本预估 $1.8M，缓存后 ~$200K（arXiv 2607.28750）；Uber 维护占比 30–40% → 5%。
贵的是首跑，边际成本靠缓存和确定性判据压下去。

## 2. 目标与验收

| 指标 | 目标 |
|---|---|
| 8 条 hyperliquid-testnet P0 二跑（缓存命中）总墙钟 | ≤ 首跑的 1/3；外推 30 条 ≤ 10 分钟 |
| 缓存命中率（hits / (hits+misses+stale)） | 二跑 ≥ 80% |
| 判据由机器判定的比例 | 100%（这份基准全部 `kind: api`） |
| 连续 5 次通过率 / flake | flake ≤ 5%，失败按 infra / locate / assert 分账 |
| 每条用例每次运行的 modelCalls / modelMs / tokens | 有数，`node scripts/cost-report.mjs` 一张表 |

## 3. 这一批改了什么

**账（`RunSpend`）。** `packages/harness-testing/src/report.ts` 新增 `parseSpend` / `sumSpend`：按时间窗从
`ai-profile-stats.log` 读模型调用数、`cost-ms`、token，从 `cache.log` 读缓存三态——命中（`cache hit`）、
未命中（`no unused cache found`）、失效（`rectMatchesCacheFeature error`，缓存在但元素对不上，这是自愈发生的地方）。
`captureMidsceneReport` 多了 `untilMs`，网关传 `sinceMs + durationMs + 1s` 收口。`runs` 表加 `spendJson`。
**纪律与 `sumTokens` 一样：日志跨运行追加，必须按窗口过滤；并发 > 1 时窗口重叠，数字会串，报表把它标出来。**

**接口判据（`kind: api`）。** `exec/apiOracle.ts` + `oracle.ts` 的第六种 oracle：问一个 JSON 接口，点分路径取值，
数组可按字段选（`assetPositions[position.coin=BTC].position.szi`——按下标写的判据换个账户就落空）。
`eq/neq/gte/lte/exists/absent` 是 tier 1，`increased/decreased/unchanged` 比较步骤前后两次读数、是 tier 2。
读不到（网络错、路径落空、不是数）是 `unobservable`，不是 fail——和页面判据同一条「None ≠ 0」。
`absent` 是唯一把「路径落空」当结果的判据（撤单后 `openOrders[coin=BTC]` 就该不在）。
导出的 Playwright 工程（`server/src/export.ts` 的 `tests/oracle.ts`）同步支持，导出后仍然不问模型。
界面类型与 i18n 已加（`artifact.oracle.api`）。

**视口。** 跑用例那条路一直没把环境的视口传给执行器（探索那条路早传了），而建环境的接口把界面发来的
`viewport` 丢掉了——所以「配过的视口」从没进过库。两处都修了。交易页在 1024 宽下下单面板整块不渲染，
用例会死在「找不到 Size」上，那不是产品的错。

**被测对象。** `fixtures/hyperliquid-testnet/`：8 条 P0（连接钱包、市价开多、限价挂单、撤单、止盈止损、一键平仓、
超额被拒、杠杆 5x），判据全部落在 `api.hyperliquid-testnet.xyz/info` 的精确数上。`import.mjs` 一条命令导入。
前提（资金、视口、首跑校对、teardown、活行情）写在它的 README。

**报表。** `scripts/cost-report.mjs`（`pnpm cost:report`）：每条用例的墙钟中位与散布、模型调用中位、模型耗时中位、
token 中位、缓存命中率、失效数、机器判定占比；`TP_USD_PER_MTOK` 设了才折美元。

## 4. 没改、且刻意没改的

- 生成器一行没动：这一批不碰 `prompts.ts`、SKILL.md、REFERENCE-oracle.md，所以 `check-drift` 不该红，
  `skillDigests` 不用跳版本。`api` 这种判据现在只能人写；让生成器产出它是领域层（第 2 项）的事，
  到那时 REFERENCE-oracle.md 加第六种形式、跳 `testpilot-design` 的版本、跑一次配对评测。
- 视觉调用本身没变便宜：降本靠的是**二跑走缓存、判据不看图**。首跑仍然是 85–90 秒一步。
- 并发仍是 1。`RUN_CONCURRENCY` 和 `RUNNER_COUNT` 要一起调，而调了之后 spend 按时间窗归账就不可信——
  先在并发 1 下把账算清，再决定要不要为并发改归账方式（按 cacheId 归账是下一步的候选）。

**预判对错。** 三条预判全错，且错的方向一致——**缓存在这个页面上不成立**：
- 「二跑墙钟 ≤ 首跑 1/3」：二跑反而长了 46%。
- 「命中率 ≥ 80%」：30%。命中的 21 次全是每条前面的登录态三步（同一个页面状态下的同三个元素）；用例自己的步骤 **49 次全部失效**。
- 「失效 ≤ 2」：49。`cache.log` 里每一次都是同一句：`cache found and marked as used, type: locate` 紧接 `rectMatchesCacheFeature error: No matching element rect found for the provided cache feature`——xpath 是存下来的绝对路径（`/html/body/div[1]/div[3]/div[2]/…/input[1]`），回放时元素的 rect 特征对不上，退回模型重定位。同一个「Size input field」在同一次运行里刚被重写进缓存、下一步再用又立刻失效（`cache.log` 20:15:03 → 20:15:05），所以不是「页面变了」这么简单，更像这个校验在这个页面上根本过不了。根因是下一条任务（07 T-27），没查清之前 #1 验收的三个数都不能拿缓存当依据。
- 唯一对的：tokens 二跑降到 30%——失效后的重定位调用比首跑的规划便宜，但省的是钱不是时间。

**二跑还暴露了回放路径自己的两个坑。** ① 撤单那条 `Protocol error (Input.dispatchMouseEvent): Invalid parameters … params.x: double value expected`：缓存的 yaml 流程带着一个没定位到的元素直接点，坐标是 undefined，被归到 infra。② 一键平仓那条一次模型调用 635 秒才回来，没超时——`TP_MODEL_TIMEOUT_MS` 没设。

**首跑 A 那条 assert 失败是真抓到的东西。** 「市价开多 0.001」成交了 **0.17365 BTC**（两笔：0.1724 + 0.00125），机器判据 `szi eq 0.001` 把它拦下；teardown 把仓平掉了，一个来回吃掉 8 USDC 手续费与滑点。这一档的口径就是为这类事立的：模型把 Size 填错，屏幕上看不出来，接口上一眼。

**从 0 到 7 条全通过过一次，中间撞的东西（每条都吃掉了一轮真跑）。**
1. 账户 0 USDC 时 `Enable Trading` 弹的是「Deposit USDC from Arbitrum」，模型关弹窗再点、再弹，10 次重规划到上限，98k tokens。前提不满足在 UI 上和元素找不到长得一样。

3. `GUARD_IRREVERSIBLE` 把第 1 条拦下：正则里的「下单」命中了「下单面板」。testnet 域名进了 `harness.config.ts` 白名单。
4. agent 授权存在浏览器 profile 里，每条用例新浏览器，第 2 条的「Place Order」其实是「Enable Trading」——启用交易是**登录态**，写进环境 `login.steps`。
5. 带「如果」的步骤会把当次分支固化进缓存：页面没加载完时模型判「不动」，缓存成 `flow: []`，之后每次回放都不动。登录态改成无条件四步（等 5 秒 → Enable Trading → Establish Connection → 关 Announcements）。
6. 条款弹窗是按地址一次性的，不是按浏览器；接受过一次就再也不出现。
7. 限价 10000 被前端拒：toast「Order price cannot be more than 80% away from the reference price」，且 `historicalOrders` 里根本没有那笔——改 40000；TP/SL 改用 Gain/Loss 百分比框输 30。
8. 右下角 Announcements 面板盖住订单表的 Cancel / Cancel All，撤单类步骤一直点不到。
9. 改判据不落库：`updateCase` 的 UPDATE 里没有 `oracleJson`（`degraded`、`coversJson` 同样），接口回显合并后的对象。修了，加了 `server/test/case-oracle-update.test.ts`。

### 6.1 · T-27 之后：根因与重测（同日 20:49–21:08）

**根因（三步证据，都在 `07 T-27` 的做法里）。**
1. 用 puppeteer 探针在同一页面上分别解析缓存里的 xpath：Announcements 面板开着时，`/html/body/div[1]/div[3]/…` 全部解析到；关掉之后全部 `∅`。`#root` 的子节点从 `img, div(Announcements), div.toaster, div(app), iframe` 变成 `img, div.toaster, div(app), iframe`——面板是从 DOM **移除**的，app 从 `div[3]` 变 `div[2]`，此后所有绝对 xpath 整体位移一格。
2. 首跑 A 里模型是按视觉点的 ×，面板关了，用例步骤记录的是 `div[2]` 路径；缓存里「×」的 xpath 却是 `div[normalize-space()="Announcements"]`（标题栏容器——Midscene 的点到 xpath 不认 svg 图标）。二跑 B 回放点在标题栏中心，面板没关，49 条 `div[2]` 路径一条都解析不到；重定位后又被改写成 `div[3]`（所以事后读缓存文件看到的全是 `div[3]`，A 的记录已被覆盖）。
3. 反向验证：缓存改写成 `div[3]` 之后、面板开着再跑第 7 条，命中 4 / 失效 1 / 模型 1 次，40 秒通过。

**决定。** 记录态与回放态必须是同一个 DOM——登录态不再关面板（它按公告是否已读出现，新浏览器总是有），撤单类步骤改走不被面板盖的 View All 整页。没改产品代码：`login.session` 走不通（agent 私钥不在 localStorage，探针验证过；且有会话就跳过登录步骤）。顺手加了 `cancel-all.mjs`（自签 L1 cancel）做 teardown 兜底，`TP_MODEL_TIMEOUT_MS=120000` 设上。

### 6.3 · T-28：地板拆段、批次复用浏览器、复位——二跑到首跑的 53%

**先量。** 每次运行的墙钟拆成六段进 `RunSpend.phases`（`cost-report` 出「墙钟分段」表）。T-27 之后那次二跑（E）的分段合计：登录态 31% · teardown 28% · 步骤 23% · 起浏览器 9% · settle 6% · 判据 4%。登录态 21 秒里有 8 秒是登录步骤自带的等待，其余是缓存回放的每个动作各截一次图、抓一次 DOM。

**改了什么。**
1. **批次级会话池**（`exec/sessionPool.ts`）：同一批的用例共用一个浏览器，登录态只跑一次；复用时同页 `goto` 回起点、换用例自己的 agent（cacheId 按用例）。**不能换新标签页**：agent 密钥在 sessionStorage 里，按标签页——试过一次，新页面一开就回到 Enable Trading。
2. **起点态只有一个**：登录态跑完也 `goto` 一次（networkidle2），单跑、批次首条、复用条从同一个 DOM 开始——否则一半用例在新浏览器里记的缓存到复用会话里失效 18 次（L）。
3. **环境复位** `vars.TP_RESET_CMD`：每条用例跑之前网关执行 `cancel-all.mjs --flatten`（自签 L1 撤单 + reduce-only IOC 平仓），输出进运行日志。teardown 是模型做的、会失手，失手一次后面每条的判据都被残留仓位带偏（M：一条失败连带两条）。复位不走模型。
4. 登录态第一步「等 5 秒」换成 `waitFor:` 前缀（`aiWaitFor`，等一个明确的东西）；Midscene 回放拿 undefined 坐标那个 bug 撞上时把这一步重试一次；只有浏览器真死了才把会话踢出池。
5. 「市价开多」拆成四步时，模型给 Size 生成的定位词是 "showing '0'"，三轮都定到下面的百分比框并被缓存固化；写成一步（和「一键平仓」第一步同款）之后七轮全过。
