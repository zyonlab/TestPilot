## 3. 建议审阅顺序

1. 工作台 → 产品结构 → 项目与环境 → US-01 → 一条用例。查看详情、规格原文并返回故事；面包屑保持对象位置。
2. 用例 → 修订与对比 → 填写新预期和依据 → 保存草稿 → 模拟确认。新版本仅在本会话生成，代码与证据标为待重验。
3. 资产 → 文本用例。筛选方法 / tier / 审阅状态，选择若干条，预览替换草稿、设优先级或记录模拟审阅决定；批量操作仅作用于当前筛选范围内的选中项。
4. 工作台 → 执行流程 → design 节点。分别查看只跑此节点、续跑、多节点选择的实际范围。关闭复用或修改版本后，缺少匹配输入会阻止模拟运行。
5. 画布 → 编辑拓扑。增删节点并检查输入输出；放弃应恢复定义，保存应产生新版本。参数和技能绑定变化也会生成快照，旧 attempt 保留旧定义。
6. 资产 → 领域知识 / Role、Skill → 详情与候选草稿；设置 → 规划与执行模型 → Web、Claude Code、Codex、PenguinHarness 四种入口。
7. 迭代 → 研究与受控自进化。核对研究问题、实证缺口、旧评测样例和 Penguin 边界；资产 → 交付与接入 → 导出审阅包。

## 7. 历史方案：Flow 工作台与产物下钻

用户确认更新原型后，默认工作台恢复 Flow。简化版已备份至 [历史文件](../../reports/history/testpilot-review-prototype-2026-09-10-simple.html)，当前原型路径不变。

主视图是“理解产品 → 设计用例 → 人工审阅 → 执行测试 → 结果”五个阶段；阶段下分别挂产品结构、测试用例、审阅清单、测试代码、执行证据的聚合卡片。默认只展示阶段状态、产物数量、少量摘要与待处理事项。点击阶段查看说明，点击产物进入对应审阅面板。

工作台常驻“流程 / 产品结构”切换，保留当前项目、模块和故事范围。已有结构与用例深链继续打开原位置，不强行重置；无深链时默认 Flow，点击顶部“工作台”也回到 Flow。范围栏可以明确返回整个项目。

| 动作 | 当前原型行为 |
|---|---|
| 开始审阅 / 审阅清单 | 打开当前范围的待审用例列表；原文、批量工具与技术信息仍按需展开 |
| 单条模拟确认 | 仅更新页面会话中的审阅决定，更新待审数量，不触发执行、不写真实人工标签 |
| 修订已执行用例 | 保留旧结果，Flow 结果阶段标记需要重验，证据面板注明已过期 |
| 点击产品结构产物 | 切换到相同范围的模块 / 故事结构，可继续下钻至用例 |
| 编辑流程 | 直接进入原完整画布的编排态；节点、连线、产物、追踪与版本能力保留 |
| 调试节点 | 按原有单节点 / 多节点 / 续跑规则创建模拟 attempt，检查匹配版本的输入 |
| 节点高级配置 | 参数、Role / Skill、版本与历史成本放在折叠区；主视图保持简洁 |

五阶段是产品视图，**没有把归档执行 DAG 偷换为新的五节点引擎**。理解产品映射来源与故事节点；设计用例映射设计与文本门禁；人工审阅是页面交互入口；执行测试映射生成、代码门禁和修复；结果是证据投影。原七节点图及其版本约束保留。正式产品的审核节点适配仍按 P 台账验收。

证据只按完整用例 ID 关联。当前 40 条样例中只有 2 条能与归档代码 / 执行记录精确匹配；另 2 条历史记录不强行配到当前用例。US-14 范围没有执行证据时显示缺口，不展示其他故事的运行。完整历史视图仍可查阅。

17 项 DOM 测试通过，新增覆盖 Flow 默认入口、阶段产物下钻、跨视图范围保持、本地审阅计数、无证据分支和修订后过期证据。真实浏览器视觉验收仍未完成，未绕过此前 file URL 策略，也没有启动生产 Web/API 或模型请求。原始测试输出和文件指纹见 [Flow 验证记录](../evidence/prototype-flow-2026-09-10/README.md)。

## 9. Flow 首页辐射用户故事与工作流执行记录

用户明确要求 Flow 作为主页工作台，补齐工作流执行记录，并调整左侧菜单位置。此次保留现有界面的导航、完整节点画布、产物和并排复核，只调整主入口和对象间的跳转。上一版保存在 [复核优先历史稿](../../reports/history/testpilot-review-prototype-2026-09-10-review-first.html)。

### 9.1 导航与主路径

1. **工作流**：工作台、工作流执行记录。无显式深链时进入 Flow。旧 structure/story/case 链接仍回到指定对象。
2. **产物审阅**：复核、物料、运行报告、基线。结构/故事是物料和复核的上层视图，工作台仍直接提供“产品结构”。
3. **评测**：记分板、gold。延续论文问题、领域专业性、独立评估和受控自进化要求。

### 13.2 状态机与断点语义

```text
新 run 准备 → ready → running → completed
                         ├─ 节点执行前命中断点 → paused
                         └─ 节点尝试失败       → failed
paused / failed → 继续相同 run → running
```

- 每个节点保存 `status`、`attempted`、尝试次数和完成时间。`paused` 必须结合 `attempted` 判断：断点前暂停的节点尚未执行，失败节点已经尝试过。
- 断点只能设置在本 run 范围内、尚未尝试的 `pending` 或断点前 `paused` 节点；`running`、`done`、已尝试的失败节点和范围外节点均不可添加。
- 运行中尚未到达的后续节点仍满足断点条件；真实执行服务必须在节点入队 / 开始执行前原子校验，避免 UI 旧状态导致断点竞争。
- 命中断点时保持该节点 `attempted=false`。继续操作跨过当前断点一次，保留后续断点；不会再次停在同一位置形成死循环。
- 已完成节点和 artifact ID 在续跑中保持不变；失败节点重试增加尝试次数并保留失败事件，不把已失败尝试伪装成未执行。

### 13.3 数据与物料隔离

原型新 run 使用以下字段，字段名称表示本次原型模型，不代表已有服务类型已替换：

| 数据 | 作用 |
|---|---|
| `project / id / scope` | 项目、运行和业务范围，选择 run 后由它自身恢复查看上下文 |
| `graph` | 创建时复制的节点、连线、参数、Role / Skill 版本和规划 / 执行模型配置；后续修改工作副本不改这里 |
| `nodes / nodeStates` | 计划执行范围与每个节点的状态；未选节点标记 `skipped` |
| `breakpoints / pauseNode / pauseReason` | 运行内断点、停点和暂停原因，独立于其他 run 与新 run 草稿 |
| `artifacts` | 按 `runId + nodeId + version` 关联产物，产物 ID 在续跑中不重复生成 |

`wf-mt0xaw2g` 继续使用初始化时冻结的归档图与已嵌入物料：40 条用例子集、4 条执行结果、对应代码及归档摘要。不把规格中的 22 个故事冒充该 run 完整生成的故事；缺少明细的故事 / 门禁材料只展示归档摘要，缺失节点物料明确说明。
