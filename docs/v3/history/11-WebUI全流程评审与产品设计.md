# 当前 Web UI 与本地实施设计

更新：2026-09-10。设计依据为用户逐轮确认的 [当前原型](../../reports/testpilot-review-prototype.html)、本地 `src/` / `server/` / packages 代码，以及既有验证证据。本轮重新核对源码，没有启动生产 UI 或真实模型；09-09 截图保留为历史问题证据。

本文替代此前“复核作为首页”“产品结构作为工作台平级模式”“工作流执行记录单列菜单”的方案。历史设计保存在 [修改前快照](11-WebUI全流程评审与产品设计-2026-09-10-before-implementation.md)。实施状态只在 [13 · 实施台账](13-UI与论文路线任务台账.md) 维护，原型完成不代表本地代码已经实现。

## 1. 产品目的与边界

TestPilot 是自动生成可执行测试用例的垂直 Harness Agent。输入需求规格或实际产品观察，结合产品结构、领域知识和测试方法，形成可审阅的故事、验收判据、测试用例、执行代码与证据。目标同时包括可用的产品闭环和可发表研究所需的独立实证。

Web UI 管项目、输入材料、工作流执行、产物与 review；Claude Code / Codex / PenguinHarness 宿主也通过相同应用服务管理这些对象。Penguin 的 TestPilot Evaluation 配套扩展管理受控候选与评估发布，不接管 Web 的全部工作流和产物管理。

两个模型角色固定：思考规划由 Web 配置或宿主原生模型承担；Midscene 使用低成本执行模型。Web 暂时默认继承 Midscene 的同一模型，后续 env / 项目配置可独立覆盖；宿主不另配规划模型。业务 Role、Skill、领域知识与模型角色是不同概念，不能给每个节点强行增加一个模型配置。

## 2. 当前导航与页面规则

| 一级入口 | 页面内容与二级入口 | 必须保持的归属 |
| --- | --- | --- |
| 工作台 | Flow、run 选择、新建 / 继续、节点调试、节点产物 | 默认首页；执行记录在选择器里；无流程 / 产品结构平级切换 |
| 复核 | 结构筛选、用例队列、详情 / 修订 / 证据、批量范围 | 产品模块图是筛选和下钻工具，保留现有并排审阅 |
| 物料 | 产品结构、用户故事、文本用例、追溯、领域知识、Role / Skill、代码、变更、交付 | 可按 run / revision 查看；结构是整理故事产物 |
| 运行报告 | 执行记录、套件批次、趋势 | 只反映被测产品测试结果，不混入基线审批 |
| 基线 | 待审批、当前基线、审批记录 | 视觉 / 性能参照独立管理，不切换到运行报告 |
| 记分板 | 能力筛选、实验结果、版本绑定、成本与证据、Penguin 入口 | 结果先于研究说明；不在 Web 实现第二个优化器 |
| Gold | 标签、来源、开发 / 留出划分、人工复核、冻结谱系 | 评测依据独立于测试用例审批与领域知识 |
| 设置 | 项目 / 目标、环境登录、模型、宿主接入、语言；高级流程 / Role / Skill 配置 | 配置来源和生效范围明确，专业设置按需展开 |

侧栏可收起为带可访问名称的图标；底部保留中 / EN / 日与主题；当前项目下拉有新增入口。偏好可以本地保存，真实项目与运行数据必须由服务管理。页面只显示一个当前内容标题，说明进帮助或折叠区；失败、缺内容、权限不足、实际操作结果仍直接显示。

初始打开进入 Flow。历史生产 `#/?open=...` 继续兼容；原型 `#view=...` 用于设计导航，不直接当生产路由协议。正式实现复用/扩展当前 router 与 SurfaceContext，显式携带 project/run/revision/scope；旧 map、stories、wfruns 链接重定向到正确产物或 Flow 选择器，不能静默回到另一运行。

## 4. Flow、节点与产物交互

Flow 顶部只保留 run 选择、输入摘要、必要操作和主要执行按钮。选中的历史 run 决定流程版本、节点状态与物料；新 run 先是未执行节点和空产物。工作流执行记录不是被测产品的测试执行报告，也不再占一个独立侧栏入口。

点击节点打开调试详情：职责、输入来源、Role / Skill / 领域版本、参数、attempt、日志、成本与输出。未执行节点展示预期产物类型；已完成节点展示其真实产物，点击产物进入对应 viewer。不要用同一“产品结构参考图”冒充所有 run 的输出。

| 行为 | 生产语义 |
| --- | --- |
| 新建 run | 新 ID，选择来源入口、runtime、材料与知识，冻结定义和模型配置 |
| 继续 run | 原 ID、原快照，跳过成功节点；不把当前设置覆盖到旧 run |
| 重试节点 | 原节点新增 attempt；保留失败输出与事件，副作用去重 |
| 断点 | 只允许当前范围内尚未尝试的节点；在开始前暂停；失败或已完成不算未运行 |
| 命中后继续 | 跨过当前断点一次，后续断点仍生效；服务端负责并发检查 |
| 单节点 / 多节点 | 明确执行 / 复用 / 阻塞清单，缺上游不隐式扩成全流程 |
| 配置改变 | 新 run 或显式实验工作副本；保留旧运行，不偷换知识、Skill 或批准版本 |

日常是垂直标准流程；重组只放「设置 → 高级实验流程」。任何模板都保留不可绕过的质量与审批约束。默认整理故事后形成结构检查点，首次生成或大幅变更需结构确认后再进入高成本设计；这种确认属于产品数据审批，不是研究晋升。

## 5. 产品结构、知识与融合数据

核心关系：SourceRevision → ProductBundle（模块树 + 故事 + 旅程 + 验收）→ CaseRevision → Approval → Execution → Evidence。每个 run 的候选单独保存，项目融合产生新 revision；共享筛选引用确定产品版本，而不是全局可变的“最新结构”。完整字段定义见 [16 · 产品结构与多入口知识契约](16-产品结构与多入口知识契约.md)。

| 对象 | 服务端必须固定的字段与语义 |
| --- | --- |
| Run / NodeAttempt | project、workflowVersion、scope、input revisions、runtime、模型、node/attempt、状态、预算、事件 |
| SourceRevision | sourceKind、contentHash、来源定位、事实类型 required / observed / inferred、run 来源 |
| ProductBundle | 任意层级 nodes、唯一 stories、多模块/功能关联、journeys、验收条件、parentRevision、来源与冲突 |
| ArtifactRevision | kind/mediaType、contentHash、run/node/attempt、来源及 schemaVersion；正文/图/代码按类型渲染 |
| KnowledgePack / SkillBinding | 来源、适用模块/角色、版本/hash、依赖、权限、解析与兼容状态 |
| ContextManifest | 实际加载知识/Skill/source片段、角色版本、工具授权、token预算、截断及消费收据 |
| Review / BaselineDecision | 对象与旧/新 revision、操作来源（本地免登录，不等同验证身份）、理由/决定、时间、并发版本、幂等键 |
| EvaluationBinding | Gold/input/model/runtime/policy/SUT/预算/协议指纹与完整尝试，禁止缺绑定排名 |

Spec 需求与 Explore 观察互补，但互相矛盾时保留声明与来源，不能以观察覆盖规范。同名实体给对齐建议，用户裁决后保存新版本；跨模块故事唯一存储。大型应用采用子树查询、分页/虚拟化、搜索定位与去重统计。文本上传、图和 Markdown viewer 均需要输入校验与内容清洗。

Role 定义职责与写边界；Skill 定义处理方法及依赖；领域知识提供业务规则；Agent 是承载上下文的执行者。用一个编排器、按需隔离的 LLM 阶段、确定性工具即可。不同节点不一定需要不同常驻 agent，但必须有可验证的上下文与权限边界。

## 6. 复用本地代码的架构分层

| 层 | 现有落点 | 本轮增量 |
| --- | --- | --- |
| React 页面与应用状态 | App / AppNav、Workspace、Review、Artifacts、RunReport、Baselines、Scoreboard、Gold；store / wf / api | Flow 首页、统一身份、run 选择与结构筛选、简化标题与导航，保留原审阅布局 |
| 应用服务与编排 | runRoutes、runService、runStages、workflowOps、workflowExecution、review / approvedRuns | 导入契约、节点状态机、上下文下发、结构确认、融合和影响传播 |
| 领域契约与校验 | harness-core/run-contracts、harness-testing/casegen/types / validate | ProductBundle v2、KnowledgeBinding、ContextManifest；迁移与强制引用校验 |
| 执行适配 | Claude / Codex / native Penguin / Web planner、MCP gateway、Midscene runner | 相同服务协议与角色授权，不复制宿主模型配置、不放宽 oracle |
| 持久化与投影 | 现有 run ledger、artifact revisions、blobs、events、costs | 增量 schema / 索引 / 查询投影；不再建一份独立前端运行事实库 |
| 独立研究与发布 | Gold、scoreboard、server/evolution、Penguin evaluation 扩展 | 证据深链、正式 manifest、受限策略适配；人工审核与私有留出数据隔离 |

生产当前仍有旧“迁移到 Penguin”注释与分组，实施应按实际代码和本次用户决策纠正。`nav.ts` 的 canvas→wfruns 高亮、`App.tsx` 无 run 时默认 review、`surfaces.tsx` 的 exec 混组都是明确入口改造点，不能仅给原型换链接。

对服务实施数据库增量迁移和兼容只读投影；保存前校验 revision / 权限 / 输入，保存后追加事件。run 快照、批准记录、原始产物不可被新 UI 状态覆盖。UI 只负责展示与命令，服务端承担断点、审批、门禁和版本约束。

## 7. 报告、Gold 与 Penguin 的实际职责

运行报告回答被测产品结果，基线管理截图/性能参照；Gold 是人工冻结的评分依据；记分板是版本结果与成本证据；Penguin 配套扩展组织候选对照与发布审核。使用流程见 [17 · 报告基线与评测职责](17-报告基线与评测职责.md)。

本地已经有 Scoreboard / Gold 服务与扩展，实施以接入为主。当前扩展只能改 memory scoped/off，通用 Skill 自动改写需要 P-18 的新适配和版本化资产；已有门禁框架不代表已有真实正向晋升。原型缺指纹时不可比较的规则应落实到服务，而不是只把按钮置灰。

## 8. 实施范围与验证

当前原型已验证：60 项 DOM 检查，包括八项导航、run/断点、产物、产品结构、知识/融合、报告/基线分离、Gold/记分板和语言主题。该证据不包含浏览器像素验收、真实上传提取、模型执行质量或生产数据库变更。原型的重建结构、模拟产物与演示审批不得进入真实数据或评测集。

实际本地实施顺序、代码落点和验收统一见 [13 · 实施台账](13-UI与论文路线任务台账.md)。第一切片先打通真实数据与 Flow，再做大型结构审阅、多入口融合、报告与宿主接续。研究按 [12 · 论文与受控自进化](12-论文级研究与受控自进化.md) 独立推进；方法对照、独立标签、失败分母、置信区间与负结果继续保留。

每次移植保留既有功能与用户改动，以相关测试和实际用户路径关闭任务，不用复制 HTML/Map 示例作为生产实现。仅本轮报告与计划更新不触发项目启动、模型调用、真实人工审批或任务 done。
