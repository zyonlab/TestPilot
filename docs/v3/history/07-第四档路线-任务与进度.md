状态只有五个值：`todo` / `doing` / `done` / `blocked` / `dropped`，写在每个任务块的 `- 状态：` 那一行，**这一行是唯一的真相源**。

### 接手纪律（对 Claude Code 说的）

1. **行号是写作时的快照，会漂。** 每个任务给的是**符号名 + 文件**。动手前先 `grep` 符号名确认它还在。
2. **不要重新评审。** 优先级是走过全仓、读过三份行业调研得出的；重做一遍很贵而且会退化。有异议写进 §10，不要静默改顺序。
3. **不调模型、不真跑浏览器、不提交、不推送——除非用户在当轮明说。** 模型端点要网络和费用，真跑要 testnet 资金，这三件事都由人触发。
   你的产出是：代码、离线测试全绿（`pnpm typecheck && pnpm test`）、以及一段「用户跑什么命令」。
4. **门禁在代码里，不在提示词里。** 任何一条「模型应该…」的规则，如果它重要到值得写，就写成 hook / MCP 工具内校验 / zod / 测试。
   见 `00-架构.md §13` 那张表：新规则加一行，说清在哪强制、谁测。
5. **两臂提示词不漂移。** 动 `packages/harness-testing/src/casegen/prompts.ts` 或任何 `plugins/testpilot/skills/**`，
   必须 `node scripts/check-drift.mjs` 绿，且对应 skill 在 `plugins/testpilot/plugin.json` 的 `skillVersions` 跳版本（`YYYY-MM-DD.N`）。
6. **P2「考卷不能由考生出」不可让步。** `benchmark/*/gold.json`、`human-labels.json`、`held-out/`、`rubric/` 不进任何提示词，
   不被任何自动流程改写。要改 gold 就是新谱系，重算 `goldHash`。
7. **None ≠ 0。** 没量到是 `unobservable`，不是 fail，不进任何分母。
8. **每个数字带 binding。** 进 `scoreboard.yaml` 的条目缺 `skillVersion / promptsDigest / model / materialsHash / runtime` 任一项拒收。
9. **先看产物再看报告**（`evals/README.md`）：任何配对评测跑完，先数一遍两臂产物的分布，再读那个 p 值。

#### T-04 · 并发下的归账：按 cacheId 而不是按时间窗
- 状态：done
- 结果：**按 runner 进程归账，不是解析 cacheId**（`cache.log` 的 hit 行不带 cacheId，解析它是伪造精度）。每个 runner 一份 `MIDSCENE_RUN_DIR=midscene_run/<runner-id>/`，`cache/` 是指回共享 `midscene_run/cache` 的符号链接：日志与报告按进程分开，缓存按用例跨 runner 共用。`execOnRunner` 返回 `runnerId`，网关从那个目录读账；`RunSpend.attribution: "runner" | "window"`，`cost-report` 把 window 的行标 ◌ 并在合计里报两种归账各几次。验收 ①：`spend-attribution.test.ts` 用两份人造日志钉住「并发 1 两种一致、并发 2 按窗口会串」；验收 ②：`RUNNER_COUNT=2 RUN_CONCURRENCY=2` 起网关后两个 runner 各写各的目录（见 §10）。
- 兑现：#1
- 为什么：`RunSpend` 按时间窗从 Midscene 日志读，`RUN_CONCURRENCY > 1` 时窗口重叠，数字会串（`06 §4` 明说了）。30 条十分钟大概率需要并发 2–3。
- 改：`packages/harness-testing/src/report.ts`（`sumSpend`）；`packages/harness-testing/src/exec/session.ts`（`PuppeteerAgent(page, { cacheId })` 那两处）。
- 做法：先验证 Midscene 的 `cache.log` 行里是否带 cacheId（`cache loaded from file, path: …/<cacheId>.cache.yaml` 带；`cache hit,` 行可能不带）。带的行按 cacheId 归；不带的行退回时间窗并在 `RunSpend` 加 `attribution: "cacheId" | "window"` 字段，报表把 `window` 归账的行标灰。**不要伪造精度。**
- 验收：① 并发 1 时两种归账结果一致（写成测试）；② 并发 2 跑同一批用例，`attribution: "cacheId"` 的行占比报出来。
- 依赖：T-01
