# 报告、基线与评测职责

日期：2026-09-10。本文是当前原型交互与正式接入的接手依据。原型只读取内嵌归档，审批演示仅保存在页面会话；本轮没有修改生产服务、启动实验或更新研究标签。

## 1. 用户从哪里开始

| 入口 | 回答的问题 | 用户操作 |
| --- | --- | --- |
| 工作台 | 这一次 workflow 跑到哪里、产出了什么？ | 选择 run，看节点与物料，新建 / 继续 / 设置断点 |
| 运行报告 | 被测产品的测试执行情况如何？ | 查执行记录、套件批次和趋势 |
| 基线 | 此次视觉或性能变化是否应成为新参照？ | 查看差异，批准更新或保留原参照，追查审批记录 |
| Gold 基准 | 什么算正确、应覆盖哪些独立条目？ | 人工编写 / 上传、复核、划分开发与留出集、冻结 |
| 记分板 | 哪个 Agent 版本在相同条件下表现更好？ | 按能力筛选、看指标与证据、比较可比版本 |
| PenguinHarness 评估扩展 | 如何提出改进并确认能否发布？ | 候选差异、对照实验、留出验证、宿主回归、人工晋升 / 回滚 |

产品基线是视觉 / 性能参照；实验中的 baseline 是 Agent 对照策略。两者可以叫基准，但实体、审批和数据来源必须分开。

## 2. 这次修缮的界面约束

- 运行报告的二级导航仅有「执行记录 / 套件批次 / 趋势」。
- 基线的二级导航仅有「待审批 / 当前基线 / 审批记录」。切换子项不能改变所属主菜单。
- `section=base` 旧链接继续有效；新增 `base-current`、`base-history` 都归属于「基线」。
- 物料、设置、报告统一只显示当前子页标题。页面用途放「页面说明」；长说明按需展开。错误、缺失数据与操作结果继续就地显示。
- 用户故事页直接呈现列表、产品文档与融合入口；选中 run 的物料放在可展开区。产品结构仍是整理故事的产物，不增加工作台的平级模式。
- 记分板首屏展示结果表。研究假设、方案和旧评测样例收进「研究与历史材料」；Gold 提供搜索与数据划分筛选。
- 当前 Gold 为只读归档；没有伪造冻结指纹、标签正文、截图或正式版本比较。

基线原型的批准 / 保留均会移出待审批队列，并生成本会话审批记录。「当前基线」随演示决定更新；原始 `PERF`、`RUNS` 和 Gold 不变。视觉样例没有嵌入图像，显示缺失状态。真实接入后须使用服务返回的截图与版本，不能沿用演示值。

## 3. Gold、领域知识与自进化如何配合

使用顺序：人工准备 Gold → 冻结评测条件 → 在 PenguinHarness 扩展组织基准与候选实验 → 记分板审阅证据 → 留出 / 跨宿主检查 → 人工决定晋升或回滚。

以领域测试设计为例：领域知识包告诉生成角色数量精度、边界和业务约束；Gold 由人工独立定义应发现的规则 / 缺陷和可验证结果；评估器将实际生成与执行结果对照 Gold 计分。增加生成条目数量不能代替缺陷检出、误报或可执行率。

| 对象 | 管理者 | 约束 |
| --- | --- | --- |
| 领域知识、Role、Skill 候选 | 产品 / 领域专家与受限 Agent | 带来源、作用范围和版本；改进须独立评估 |
| Gold 标签与评估器 | 独立标注者、评估维护者 | 人工逐条复核，冻结后修改建新谱系；不向优化器暴露留出答案 |
| 候选运行 | PenguinHarness 评估扩展 | 优化器只见开发反馈；外部工具计算分数 |
| 记分板证据 | TestPilot 只读视图 | 绑定输入、模型、Gold、运行时与策略版本；条件不齐不能直接排名 |
| 发布决定 | 人工审核者 | 先满足留出和宿主回归门禁，再晋升；保留历史与回滚 |

Gold 页面不是普通测试用例审批列表，也不是模型生成答案的自动收纳处。物料中的领域知识与 Gold 可以引用相同产品来源，但不能把候选生成内容自动提升为评判它自己的正确答案。

## 4. 现有代码真正实现到哪里

| 能力 | 实际位置与当前行为 |
| --- | --- |
| 记分板 | `src/pages/Scoreboard.tsx` 读取 `/api/scoreboard`；按能力筛选，展示版本与评测绑定、成本、样本，读取服务返回的 Penguin 地址。依据输入 / Gold / 模型 / 运行时分组。 |
| Gold 维护 | `src/pages/Gold.tsx`、`server/src/gold.ts`：人工标签、逐条审核、冻结指纹、谱系。正式写入需要审核身份。 |
| Penguin 入口 | `extensions/penguin-evaluation` 注册评估 workflow，并启动独立配套界面。当前集成不在 Penguin 原生页面内嵌入自进化页，也不调用它的自动接受优化器。 |
| 当前候选范围 | 仅 `contextPolicy.memory = scoped / off`。通用 Role / Skill / 参考文件自动改写尚未接入，需要版本化资产及可验证适配器。 |
| 实验与发布 | `server/src/evolution`：受限候选进程、外部评分、开发改善后待审、留出与跨宿主门禁、人工晋升、原子版本更新与回滚。 |
| 正式回读 | TestPilot 读取激活版本，新 run 冻结 `agentVersion`、`contextPolicy` 与实际记忆摘要；不回写旧运行快照。 |

当前端口默认 7365，TestPilot 通过服务返回的 `TP_PENGUIN_EVALUATION_URL` 链接；实际接入操作见 [扩展 README](../../../extensions/penguin-evaluation/README.md)。本文不启动服务。

现有工程门禁不等于已有正向进化证据。实际人工冻结的领域 Gold、完整留出 / 宿主运行和合格候选仍需完成。默认缺少相应发布依据时必须保持不可晋升。原型「模拟绑定新版本」只演示工作副本配置，不能解释为已通过自进化发布。

论文目标继续按 [研究方案](12-论文级研究与受控自进化.md) 推进：冻结独立数据、严格对照与消融、多个种子 / 重复、置信区间、跨任务留出，以及成本与质量共同报告。界面收简不减少这些要求。
