## 1. 产品目标与评审结论

TestPilot 是面向垂直领域的自动测试用例生成 harness agent。首个领域是衍生品交易前端：从可信需求和领域规则生成可执行用例，以独立判据发现缺陷，供人整体审阅、修订，再用可复现实验评估改进。达到研究论文所需的方法与实证水平是主目标，完整计划见 [论文路线](12-论文级研究与受控自进化.md)。

Web 是项目、执行和产物的管理与 review 界面；Claude Code / Codex / PenguinHarness 是另一种管理入口。两入口应调用相同应用服务、读取同一事实台账。Penguin 配套 UI 负责候选实验、晋级与回滚，Web 展示版本与效果证据并链接过去。产品结构和用户故事审阅属于 TestPilot Web。

当前结论：执行台账、模型绑定、不可变产物、人工审核与机器判据有基础；用户从整体到细节的主路径没有闭合。已有地图、故事树和追溯实现可复用，但被旧路由、不同数据作用域与迁移提示隔开。改善信息架构需要统一数据和导航，不能只换布局。

## 3. 信息架构：项目是起点，结构是主视图

全局：项目列表、服务连接状态、宿主接入、个人偏好。项目进入后，顶部始终展示项目、目标环境和当前快照/运行；避免把项目切换器留在角落。

| 一级入口 | 默认视图 | 下钻内容与操作 |
|---|---|---|
| 项目总览 | 产品模块图 + 待办 + 最近工作 | 模块→流程/故事→验收条件→用例→判据→执行证据；显示缺失模块与未验证关系 |
| 产品与需求 | 模块树 / 用户旅程图 / 文档目录 | 原始材料→结构提取→人工修订；来源原句、冲突、适用范围；图与列表同步 |
| 测试设计 | 当前范围故事与用例 | 待审、已批准、需重审、已废弃；正反例/边界/状态转移；差异与影响预览 |
| Workflow | 定义列表 / 运行列表 | 模板版本、节点图、单节点/选中节点调试、输入输出、role/skill、成本与错误 |
| 执行与证据 | 项目/模块范围的最近结论 | 每轮尝试、录像/截图/API 判据、SUT 版本、复测；基线待办属于此处 |
| 领域知识 | 领域包与规则图 | 术语→业务规则→不变量/判据→引用的故事用例；证据来源与版本 |
| 研究与进化 | 可比性、协议、效果、限制 | Web 只读研究结论/谱系；进入 Penguin 进行实验与晋级；Gold 进入独立人工研究工作区 |
| 项目设置 | 准备状态 | 项目、环境、两模型、宿主接入、预算、领域包、访问与高级配置 |

默认宽屏采用“左结构树 + 主图/列表 + 右详情”，可收起左右区。窄屏改为树/内容/详情逐层切换，不保留三栏挤压正文。图支持键盘访问，列表是等价入口。面包屑、浏览器返回、选中状态、筛选与滚动位置保持一致。空结构显示“尚未建立产品结构”，提供导入/从已有材料整理；未知不能画成已覆盖。

建议路由：/projects/:projectId/structure?revision=…&module=…；/projects/:projectId/stories/:storyId?revision=…；/projects/:projectId/cases/:caseId?revision=…；/projects/:projectId/workflows/:workflowId/runs/:runId/nodes/:nodeId?attempt=…。实现时可保留 hash router，但身份必须完整。链接对象不存在时显示删除/不可访问/迁移状态，不回退到其他 run。

## 4. 主要用户故事与验收场景

| 故事 | 触发→用户行为→结果 | 必须验收的异常路径 |
|---|---|---|
| US01 新用户建项目 | 选择 Web 或宿主→创建目标项目/环境→确认模型来源→导入材料→预检→开始生成 | 无项目、接口离线、错误 CORS、目标不可达、模型不支持图像、凭证缺失分别指向可修复项 |
| US02 产品/领域专家审结构 | 看产品模块全图→点订单模块→看下单流程与故事→打开需求原句→调整模块/术语 | 模块无故事、故事无用例、来源缺失、规则冲突都可定位；结构修订形成新版本 |
| US03 测试负责人审批 | 从模块覆盖缺口进入故事→比对正例/反例/边界用例→核对判据→批准指定版本 | 草稿未满足门禁不能执行；批量批准先显示精确对象范围和各自状态 |
| US04 修缮者 | 从失败证据回到用例→判断执行误差/产品缺陷/需求缺失→修订并查看受影响对象→重新审核 | 修改用例不改旧结果；修改 expected/oracle 需显式差异与重新批准；并发修改用版本冲突提示 |
| US05 执行调试者 | 冻结一次输入→只运行某节点或选定节点→比较两轮输出/成本→保存候选配置 | 上游缺失时阻塞并提供补跑；取消不抹记录；重新运行不重置累计预算 |
| US06 宿主用户 | Claude/Codex/Penguin 注册同一项目→加载技能→检索→写故事/用例→门禁→Web review | 不配置另一个宿主 planner；MCP 断线可恢复；服务拒绝伪造阶段、跨项目引用或自我批准 |
| US07 领域维护者 | 导入规则来源→记录产品/版本/生效时间→设计十进制与状态判据→提议领域包版本 | 多来源冲突、过期规则、未知单位必须显式；更新列出受影响用例与复验任务 |
| US08 研究者 | 冻结协议/数据/预算→配对运行基线与候选→分析缺陷发现及误报→导出复现包 | 无效输出、环境错误、拒答不丢弃；缺少 gold/预算不宣称改进；留出不可反复调参 |
| US09 进化审核者 | 在 Penguin 比较候选策略、失败样本与预算→查看留出和回归门禁→人工晋级或拒绝 | 无改进候选保留拒绝记录；CAS 冲突、过期门禁、回滚均可审计 |
| US10 交接者 | 打开项目报告→查看模块图、故事图、测试图与结论→沿稳定链接回到同一版本 | 离线导出保留实体 ID、来源、摘要、未知项与附件；不能只导出截图或裸 JSON |

新手流程的首页以“还差哪一步才能生成”为主；专家可直接打开旧运行/节点深链。项目总览显示有分母的结构与审批数据；“完成了多少”分为结构整理、设计审阅、有效执行、研究验证，不能合成一个不透明进度分数。

## 5. Workflow、role 与 skill 的产品决策

采用“官方默认模板 + 用户可复制并重组的有类型 DAG”。定义草稿可编辑；发布定义形成不可变版本；运行冻结定义版本。用户可添加已注册类型的节点、调整兼容连线、并行独立分析、配置 role/skill/参数。第一期不开放任意 JavaScript 节点或任意评分脚本上传。是否增加节点类型走单独插件能力协议。

默认逻辑：材料冻结→结构/领域理解→用户故事→用例设计→设计门禁→人工审核→执行编译 g2→Midscene/程序执行→报告。结构与领域检索可以独立并行，故事必须引用已冻结结构/需求。固定的是依赖与门禁语义，非所有任务的视觉排列。

支持全流程、只运行一个节点、运行选中子图、从节点向下运行。多节点选择可不连续，但每个缺失依赖必须补齐或显式复用匹配的冻结输出；启动前显示将执行/复用/阻塞的节点。先做线性范围和单节点，再开放一般子图。不能把旧 only/from 等同于已有任意 selection 支持。

每次调试创建新的 NodeAttempt，绑定 baseRun、输入 revision、配置 hash、预算与 seed/采样配置；生产旧输出不可覆盖。显示“比较输出”“设为候选”，改变运行或技能版本不直接改变激活版本。审核、判据可信性、gold 隔离、晋级策略是服务端约束，图编辑器不能绕过。

| 概念 | 用户看到什么 | 管理方式 |
|---|---|---|
| Role：职责 | 需求分析者、领域测试设计者、执行者、校验者、人类审阅者 | 说明职责、允许的工具、输入输出、模型/程序/人类类型；模型角色只有 planner 与 executor 两类计费入口 |
| Skill：版本化能力 | testpilot-stories、testpilot-design、领域参考包等 | 来源、版本/hash、适用领域、输入输出、依赖、测试结果；编辑产生草稿→验证→发布，历史运行继续绑定旧版本 |
| Node：一次步骤定义 | 节点名、role、skill refs、输入/输出端口、门禁、费用上限 | 点击打开配置与实际运行两个页签；明确哪些值从模板继承 |
| Model binding：调用来源 | 宿主原生 planner / Web planner；Midscene executor | 显示来源与运行快照；宿主模式不展示要求填写规划 API 的表单 |
| Gate / Reviewer | 程序校验或人类决定 | 不伪装成第三个大模型；质量打分、真实错误判定、人工批准分开 |

## 6. 领域知识与产物契约

领域包由术语表、规则集、不变量、状态机、测试设计策略、API/视觉观测适配器、引用来源组成。首期围绕数量步长/精度、价格 tick、价格保护、订单生命周期、保证金/杠杆、只减仓；清算/资金费/组合保证金等列为后续，每个交易场所独立验证，不能把某 fixture 的规则推广到所有交易所。

每条规则记录 ruleFamily、产品/场所、版本、生效时间、来源 URL/文档 hash/段落、单位、精确十进制字符串、适用条件、冲突与未知状态、负责人/批准记录。模型只能提出规则/判据，独立验证器和专家决定其可信性。领域知识是生成输入；研究 gold 与隐藏缺陷答案是隔离的评价资料，不能混入同一检索索引。

产物必须自动导出以下可导航视图，统一由版本化数据生成：产品模块图、关键流程/状态图、用户故事图、故事→验收点→用例矩阵、规则→判据→证据图、缺口/争议/待办、修改影响图。提供 HTML + Markdown + JSON manifest；SVG 图是数据的投影，不单独维护另一套事实。用户新增/修订模块、故事、用例时重建投影，保留旧版。

## 7. 架构分层与数据结构

| 层 | 现有基础 | 规划新增 / 收敛 |
|---|---|---|
| 交互入口 | React Web、MCP tools、宿主 runtime、Penguin 配套 UI | 项目工作区、完整实体深链、研究空间与产品空间；入口共享命令语义 |
| 应用服务 | runService/runStages/workflowOps/approvedRuns/workflowExecution | ProjectGraphQuery、RevisionImpact、WorkflowDefinitionService、NodeAttemptService；避免在组件里拼多个旧存储 |
| 领域层 | run-contracts、casegen 校验、图运行时、decimal/apiOracle | ProductStructure/DomainPack/Role/Skill/Workflow 定义与版本契约；统一门禁和来源约束 |
| 执行适配层 | Native Claude/Codex/Penguin、模型角色 proxy、Midscene、程序判据 | 所有节点运行适配新 Attempt；可取消/重试/断点；执行环境快照 |
| 持久化/证据 | SQLite ledger、内容寻址 blob、workflow event、cost/review | 关系投影索引、修订影响与审批事件；旧数据可读迁移，不覆盖原始证据 |
| 独立评估 | 受控候选沙箱、私有 gold、release gate/CAS | 冻结实验协议、配对清单、统计输出、复现包；生产服务不能代传隐藏答案 |

以下是拟定契约，不表示现有 schema 已具备：

```typescript
type Ref = { projectId: string; entityId: string; revisionId: string };
type Provenance = { source: Ref; locator: string; quoteHash: string };
type ProductModule = { id: string; name: string; parentId?: string; source: Provenance[] };
type Story = { id: string; moduleIds: string[]; actor: string; goal: string;
  benefit: string; acceptanceIds: string[]; ruleRefs: Ref[]; source: Provenance[] };
type TraceEdge = { from: Ref; to: Ref; kind: 'contains'|'derives'|'verifies'|'executes';
  basis: 'generated'|'human-verified'|'machine-observed'; evidenceRefs: Ref[] };
type CaseRevision = { id: string; storyRefs: Ref[]; acceptanceRefs: Ref[];
  ruleRefs: Ref[]; oracleRef: Ref; inputDataRef: Ref; parentRevision?: string };
type WorkflowDefinition = { id: string; version: number; hash: string;
  nodes: NodeDefinition[]; edges: TypedEdge[]; policyVersion: string };
type NodeAttempt = { id: string; runId: string; nodeId: string; attempt: number;
  inputRefs: Ref[]; roleRef: Ref; skillRefs: Ref[]; configHash: string;
  outputRefs: Ref[]; status: string; reasonCode?: string; costRef?: Ref };
type ReviewDecision = { id: string; target: Ref; actorId: string;
  decision: 'approve'|'reject'|'request_changes'; expectedRevision: string; at: string };
```

项目内的实体 ID 与 revision ID 分离。NodeDefinition/TypedEdge 需要由协议任务落正式 schema。边界规则：引用必须同项目或显式允许的共享领域包；空分母为未知；修改父 revision 计算受影响后代，旧审批不自动继承；前端乐观并发由 expectedRevision 校验；每个 sourceRef 能解析至冻结内容与片段，不能只返回一段不稳定原文。

迁移先做只读适配层和身份对照表，再增加新写入路径；旧 wf/目录产物显示 legacy 标识，不能伪造冻结哈希、项目归属和人工批准。无法建立关系的对象进入“待归档/待确认关联”，而不是挂到当前项目。

## 8. 交付与验收边界

本轮交付评审、研究方案、可点击原型、安装指南和任务台账；不把原型接到生产后端。原型数据全部标记为演示，重点验证整体→模块→故事→用例→证据、修订影响、节点选择与模型入口切换。

实现验收应包括：跨项目 A→B→A、刷新/返回/直达深链、对象删除、空数据/加载失败、草稿与已批准区分、旧运行迁移、并发修订、上游缺失、取消和预算累计、环境错误分类、键盘与窄屏布局。写 API 的权限和门禁使用集成测试；交互路径用真实浏览器验证。研究效果必须另做冻结实验，不能由 UI 验收替代。
