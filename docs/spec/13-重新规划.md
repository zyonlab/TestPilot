# 13 · 重新规划：现在卡在哪，原来要去哪，怎么走过去

写于 2026-08-28。这一天提交了 66 次，其中大半是修管道。写这份文档的直接原因是一个提问：
**「你是不是应该给 AI 专业方向的提示词来获得更高质量的物料产出？」**——它点破了一件事：
我一整天在修管道，没有一次动过「让产出变好」的那个杠杆，也没有量过那个杠杆值多少。

这份文档不列愿望。每一条都要么有数，要么明说「没量过」。

---

## 一、原来的目标，一句话

**把一个跑着的产品，变成一批人愿意读、愿意签字、并且真的能跑的端到端测试用例。**

三个限定词都是硬的：
- **人愿意读** —— 产出物料要专业到人能快速评估（这是 `docs/spec/12` 整场重构的起点：
  「目前看产出物料根本不可用，人工介入成本太高」）；
- **人愿意签字** —— 每条断言要能说出自己的出处，能被推翻；
- **真的能跑** —— 不是文字用例，是能执行、能报绿红的代码。

再往上一层的目标：**做到能发论文的程度**。这一条对方法有硬要求——所有结论都要有基准、
有留出集、有误差棒，不能拿单次运行说事。

## 二、这一天真正验证了什么

只列**量过的**。

| 结论 | 证据 | 强度 |
|---|---|---|
| 探索是确定性的 | PetClinic 五次图完全一致（8 状态 / 35 转移，标准差 0） | **强** |
| 每次都漏的项，成因只有两种：探索走不到、要故意输坏值 | 两应用 10 条持续漏项逐条归因，**没有一条**是「探索看到了但下游丢了」 | **强** |
| 单次运行会把效应量报大三倍 | 语义覆盖 n=5 是 0.623 ± 0.149，我曾拿其中一次的 0.778 当证据 | **强** |
| 状态抽象过松漏测、过紧冗余，**同一把尺子在同一个应用上两头都能失效** | Juice Shop：丢哈希 → 20 状态塌成 1 个路由；角标进签名 → 1 屏裂成 11 个 | **强** |
| 留出应用撞掉的是推理里的隐含前提，不是代码里的错 | dimeshift 一次跑翻五条规则，其中「结构同类去重」那条代码一个字没错，是它依赖的前提被换了应用 | **强** |
| 补上实验与触达之后，材料能覆盖到关键行为 | PetClinic 关键词 1/4 → **4/4**；Juice Shop 0/7 → **6/7** | **中**（只到材料层） |
| 开着思考产出更好 | 语义 0.333 → 0.444、留出 0.250 → **0.750**、`covers` 填充 4/9 → 24/25 | **弱**（n=1，且两组条件不等价） |

**「中」和「弱」那两行是这份规划的起点。**

## 三、现在真正卡在哪（按严重程度）

### 问题 1：整条流水线从来没有在「材料很丰富」的条件下量过

探索现在能产出 10 万字材料、64 条转移、9 条实验。而**所有的语义覆盖数字，
都是在材料只有 8 状态 35 转移时量的**。换句话说：我把上游修好了，
却还没有一次干净的下游度量。

今天六次运行全部死在同一件事上——输出预算被截断。这不是巧合：
**材料变丰富，下游的每一个预算都同时变得不够。**（已修：截断就加大重来。）

### 问题 2：提示词的专业含量，从来没量过值多少

`design.cases` 的提示词里有五种设计方法的定义、判据分层、五种 oracle 形式、
「全是正常路径的用例集是坏的用例集」。仓库里躺着一份 `evals/design-methods.json`，
标题是「明确点名测试设计方法，比只说『设计用例』强多少」，`why` 里写着：

> 这是提示词里最长的一段，也是最容易被认为「模型自己也会」而砍掉的一段。
> **它到底换来了多少覆盖率，没人量过。**

**定义写好了，配对评测的机器建好了，从来没跑过。**

这一条现在比一天前更要紧：§14 量出「瓶颈在探索不在下游」时用的是 qwen3.8-27b；
换成 qwen3.8-flash 之后，8 个故事只出 9 条用例——**下游重新变成瓶颈了**。

### 问题 3：模型这一层的变量全是混在一起的

一天之内换过三次模型配置（本地 oMLX → TokenHarbor qwen3.8-27b → DashScope
qwen3.8-flash），每次都伴随着别的改动。现在手上的数字里，
**模型大小、思考开关、提示词、材料丰富度四个变量从来没有被分开过**。

思考那组尤其糟：B 组（思考=开）跑的时候还没有「截断重来」，A 组有——
两臂差的不止一件事，这个对照作废。

### 问题 4：三个基准应用只有一个真正可比

- `petclinic-web` —— 在公开 AWGT 主题应用集里，**唯一能对上已发表基线的**
- `juice-shop` —— 不在文献里，且十几个探索修复都是对着它调的，**不能用来说泛化**
- `dimeshift` —— 在文献集里、没调过，但**它会被写**（一次探索后用户 1→2、流水 2→52），
  每次运行前必须重建容器

**「对上 Crawljax / WebExplor 的已发表覆盖率」这件事，到今天一步都没走。**

### 问题 5：流水线只走到「文字用例」，没走到「能跑的代码」

原目标里的第三个限定词——**真的能跑**——这一天一次都没碰。
codegen、gate②、repair 这几层今天没有任何数据。

## 四、怎么走过去

排序原则：**先让度量可信，再谈提高。** 一个不可信的度量上做的任何优化都是自欺。

但有一条要先说清楚，因为它决定了「可信」是对着什么说的：**这条流水线的验收对象是
故事图，不是覆盖率数字**。覆盖率是我们自己检查自己的工具；而交付给人的东西是一张
「哪些有效、缺了什么」都看得见的图。阶段 D 才是对着原目标的那一段，
A–C 是为了让 D 的判断有依据。

### 阶段 A · 把度量修到可信（预计最短，价值最高）

**A1. 在丰富材料上跑通一次完整基线。** 三个应用各 5 次，同一个模型、同一个配置、
不思考。这是**第一次**在修好的探索之上做的度量，它取代此前所有的语义覆盖数字。
输出：三应用 × 五次的分布，带误差棒。

**A2. 变量隔离表。** 之后每一个数字都必须标明四个变量的取值：

    模型 | 思考 | 提示词版本 | 材料丰富度（状态数/转移数/实验数）

一个不标这四项的数字，在这个项目里不再算数据。

**A3. dimeshift 的重建要进流水线。** 现在是我手工 `docker rm -f`。
它必须变成运行前的自动步骤，否则第二次跑的不是同一个东西——而这件事不会报错。

### 阶段 B · 回答「专业提示词值多少」（直接回应那个提问）

**B1. 跑 `evals/design-methods.json`。** 现成的定义、现成的机器，两臂只差
「点不点名测试设计方法」这一件事。

**B2. 按结果分叉：**
- 如果差距明显 → 往这个方向**加深**：按 ISTQB 的风险等级排优先级、
  用 Chow 的 W 方法补状态迁移对（我们已经在算 0-switch / 1-switch，缺的是让模型知道）、
  给每条用例要求一个「它能发现哪一类缺陷」的标签；
- 如果差距很小 → 那段提示词**该缩短**。它现在占着上下文，也占着每次改提示词时的注意力，
  而上下文正是我们六次被截断的直接原因。

**B3. 把同样的方法用在另外两段提示词上。** `spec.compose` 的海拔、`plan.stories` 的
故事地图骨架，都还没有对应的消融定义。**一个不能被关掉的组件，是一个不能被证明的组件**
——这句话已经写在 `ablation.ts` 里，只是还没兑现到这两处。

### 阶段 C · 把思考这个变量测干净

**C1. 重跑思考对照**，两臂条件完全一致（都带截断重来、同样的预算常数、同一模型）。
n=3 起步，看方差再决定要不要加到 5。

**C2. 分开「模型大小」和「思考」**：qwen3.8-flash 与 qwen3.8-27b 各测思考开/关，
四格表。现在这两个变量是缠在一起的——flash 掉下来的那 0.29 语义覆盖，
有多少是模型小、有多少是没思考，完全说不清。

**C3. 记下成本。** 思考让单次运行从 4 分钟涨到 20+ 分钟。
论文里要报的不只是覆盖率，还有**每一分覆盖率花了多少 token 和多少秒**。

### 阶段 D · 让故事图能回答「缺了什么」——这才是原目标

**这一阶段是 2026-08-28 的一次提问改写出来的**：

> 当前有没有源码？怎么衡量代码覆盖？当前怎么也是规划出合理的产品用户故事，
> 然后用户根据用户故事图去分析哪些有效，缺少了什么。

两句话各推翻了一件事。

**① 代码覆盖这条路，前提就不成立。** 我们是**黑盒**的：手上只有一个跑着的产品，
没有它的源码在跑。文献（Crawljax / WebExplor）报的代码覆盖是**给被测应用插桩**之后量的
——改被测对象、重新构建、跑在插桩版本上。那不是这条流水线在做的事，也不该为了「能对上
一个数」去做。

所以 §D2 原来写的「对上已发表基线」**作废**。诚实的说法是：
**我们量的是另一件事**，论文里必须这么写，而不是含糊地说对上了基线。
状态覆盖 / 0-switch / 1-switch 是我们和文献**共有**的语言（它们都建立在状态转移图上，
不需要源码），能比的只有这些；代码覆盖不能比，就说不能比。

**② 真正的验收对象是故事图，不是覆盖率数字。** 原目标是「人愿意读、愿意签字」，
而人读故事图是为了判断**哪些有效、缺了什么**。

而今天的故事图**只画「有什么」**——活动、故事、用例。唯一的缺口提示是
「这条故事挂不到流程上」。**它没法用来回答「缺了什么」，因为缺的东西根本没画上去。**

更要紧的是：**harness 早就把缺口算出来了，只是没给人看。**

| 已经算出来的东西 | 现在在哪 | 它字面上的意思 |
|---|---|---|
| 没有任何用例覆盖的转移（`scoreStructural.uncovered`） | 只进评测 | 这条路走过，没人验 |
| 规格里的「没有答案的地方」（`unknowns`） | 只在规格正文 | 材料没说清的地方 |
| **看见但没走过**的链接（`walked: false`） | 只在图里 | **产品有这个入口，探索没进去** |
| **走不通**的路（`missed`） | 只在图里 | 试过了，进不去 |
| 走过但没人写故事的流程 | 没算 | 有这条路径，没人为它写故事 |
| 没有故事的模块 | 没算 | 整块功能没人管 |

最后四条尤其可惜——**它们字面意思就是「这个产品有这个东西，我们没测」**，
正是要交给人判断的那一类信息，而它们已经在数据里了。

**D1. 缺口成为故事图的一等公民。** 每个活动列下面，除了故事卡，还要有一格
「这个模块里没被覆盖的东西」：未覆盖的转移、看见没走的入口、走不通的路、
规格里关于这一块的 unknowns。**空白也要画出来**——一个模块有 0 条故事，
那一列要在，而不是不出现。

**D2. 每条缺口要能一键变成任务。** 「这条转移没人验」旁边应该有「为它补一条用例」；
「这个入口没进去」旁边应该有「重跑探索时优先走它」。**只报不给做，等于让人自己记账。**

**D3. 然后才测复核耗时。** 这个指标从 doc 12 立项写到今天还是「未测量」，
而它是三条验收指标里唯一需要人参与、也唯一真正对着原目标的。
在 D1/D2 之前测它没有意义——现在的图缺了一半信息，测出来的是「读一张残图要多久」。

**D4. dimeshift 的黄金清单**（现在只有 PetClinic 和 Juice Shop 有），
按已立的规矩：人写、对着跑起来的应用实测、留出集从不参与调参。

**D5. 消融状态抽象。** `ABSTRACTIONS` 里已有五种尺子，机器早就做成可替换的一族。
这是唯一一处**能和文献直接对话**的对照——因为状态抽象这个变量本身就是他们的核心论点，
而它不需要源码。

### 阶段 F · 文献定位：只比共有的语言，缺的那几支要补上

**2026-08-28 的第三次提问：「之前调研的文献适合我们项目吗？我们目前是偏向黑盒测试。」**

答案有点反直觉：**方法几乎全是黑盒的，不适配的是他们的评价指标。**

| 文献 | 本身是不是黑盒 |
|---|---|
| Crawljax（Mesbah 等） | ✅ 天生黑盒——通过浏览器爬跑着的应用，从 DOM 推状态。我们的状态流图直接来自它 |
| Chow 1978 W-method | ✅ 定义上就是黑盒——从接口测一台有限状态机。0-switch / 1-switch 全部来自这里 |
| WebExplor | ✅ 黑盒探索 |
| ScenGen | ✅ 记录交互，黑盒 |
| Patton 故事地图 | 不是测试研究，是产品实践，对着「给人看」那一侧 |

他们用代码覆盖当指标，是因为**被测应用的构建在他们手里**，插桩很自然。那是一个评价选择，
不是技术属性。**所以问题从来不是「文献不适合黑盒」，而是我拿了他们的评价指标，
而那个指标需要我们不打算做的事。**

#### 更大的问题：文献只覆盖流水线的前三分之一

    探索 → 规格 → 用户故事 → 测试用例 → 可运行代码 → 修复
    └────┘
     文献在这

AWGT 那批工作停在「覆盖了 N 个状态 / 发现了 N 个崩溃」。对**怎么把探索变成人能读的规格、
怎么拆成用户故事、判据从哪来、人怎么复核**几乎只字未提——而那恰恰是这个项目唯一有新意的
部分。**只对着 Crawljax / WebExplor 定位，等于在我们最不新颖、指标还复现不了的那一段上比。**

#### F1. 基线那一行拆成两半

- **探索层可比** —— 状态覆盖、0-switch、1-switch。这三个不需要源码，是我们和他们**共有的
  语言**。状态抽象消融（§D5）在这里，因为抽象本身就是他们的核心论点。
- **下游不可比** —— 代码覆盖不比，明说不比。下游的基线换成「截图直连 LLM 出用例」
  这类同类做法，比的是判据兑现率、可追溯性、缺陷检出。

#### F2. 待读清单（四支，一支都没引过）

| 方向 | 为什么要紧 | 出处把握 |
|---|---|---|
| **判据问题**（The Oracle Problem） — Barr / Harman / McMinn / Shahbaz / Yoo, IEEE TSE 2015 综述 | 我们的 tier 分层 + oracle 兑现率**本身就是对这个问题的一个回答**。最该引却一篇没引 | 有把握 |
| **用户故事质量** — Lucassen 等的 QUS 框架 / AQUSA 工具 | 给「故事写得好不好」一套成文判据（良构、原子、最小、概念自洽），比我自己拍的「海拔」有根据 | **年份与期刊待核** |
| **变异测试** — DeMillo / Lipton / Sayward 1978 | 回答「这套用例真的验得住吗」 | 有把握 |
| **需求—测试可追溯性** — ISO/IEC/IEEE 29119 | 我们的 `covers` + 出处印记正是这个 | 有把握 |

### 阶段 G · 黑盒变异测试：从「说得出验什么」到「真的验得住」

这是我们最大的空白。现在能证明**用例说得出自己验什么**（判据兑现率 100%），
证明不了**它真的验得住**。

语义覆盖问的是「用例集提到了这条行为吗」（关键词匹配，是下界）；
**变异得分问的是「这条行为坏了，用例集会不会叫」——那才是测试的定义。**

变异测试通常要源码，但它的本质是「注入一个缺陷，看用例集抓不抓得到」，
而**缺陷不一定非得注入到源码里**。我们控制着浏览器，可以在响应 / DOM 这一层注入：

- 把一条校验消息从 `must not be empty` 改成别的
- 删掉一个按钮
- 让一个链接指向别处
- 让搜索结果少一条

然后看这套用例**变不变红**。杀掉的比例就是一个**不需要源码的变异得分**。

**G1.** runner 那一层加注入代理（工作量不小，是这个阶段的主要成本）。
**G2.** 变异算子定成一张表，和状态抽象一样**可消融、可横比**——一个只有作者知道注了什么的
变异得分没有意义。
**G3.** 报「杀掉率」时必须同时报**存活的那些**：活下来的变异体是这套用例集的盲区清单，
而盲区清单正是阶段 D 要交给人看的东西。**G 和 D 在这里接上了。**

### 阶段 E · 走完到「能跑的代码」

codegen → gate② → repair。今天完全没碰。
在 A–D 之前不动它：**在一个还没量准的用例集上生成代码，只会把不确定性再乘一层。**

## 五、这份规划里我最不确定的三件事

1. ~~D2 的可比性到底能不能兑现~~ —— **已经有答案了，答案是不能。**
   我们是黑盒的，没有被测应用的源码在跑；文献的代码覆盖是插桩后量的。
   这一条从「不确定」变成「确定不行」，处理方式是**在论文里明说我们量的是另一件事**，
   并把可比的部分（状态覆盖 / 0-switch / 1-switch / 状态抽象消融）单独拎出来说。
   写在这里是因为：我此前把它当成一个待办，而它其实是一个**错误的目标**。
2. **提示词的杠杆有多大。** B1 之前，我对这件事的判断纯属猜测——而今天已经证明过
   我的猜测能错三倍。
3. **这条流水线到底该服务谁。** 「人愿意读、愿意签字」是原目标，
   但**复核耗时这个指标从 doc 12 立项起就写着「未测量」，到今天还是没测**。
   它是三条验收指标里唯一需要人参与的一条，也是唯一一条真正对着原目标的。

| 复核接口 | `reviewBatch` 现在读探索的图和规格——此前这两样它根本没读过，「缺了什么」在界面上因此不存在 |

| 顶部 | 一条汇总：两类各多少 + **探索为什么停下来** |

一路上被真实数据打回来四次，每一次都是「产出看起来正常」那一类：

**① `COMPOSE_SCHEMA` 里没有 `modules`。**提示词要了，schema 不给位置，
约束解码之下模型**不被允许**产出它——于是模块一个名字都没有，横轴写着 `owners`、`oups`。
而那一段代码上面就写着「a field the prompt asks for and the schema omits is a field the
model is not allowed to produce」——那句注释是我为「海拔」那次写的，然后照着又犯了一遍。

**② 活动名放开成自由串，模型把整段规格正文抄了进去。**三千多字符，而那一栏就是列头。
两道防线：schema 钉成模块名枚举；回填层拒绝未知值（**宁可少一个分类，不可多一个假分类**
——一个瞎编的列头比没有列头更糟，因为人会信它）。

**③ `steps` 的 `minItems` 只写在 zod 里，没写在给模型的 schema 里。**于是模型给空数组、
zod 在后面拒绝，**整个故事的产出一条不剩**，八条故事全军覆没。
规矩：**JSON schema 是给模型的约束，zod 是给我们的校验，两边必须说同一件事。**
修完之后同一个模型、同一份提示词，用例从 9 条回到 37–38 条，语义覆盖 0.333 → 0.556，
留出集 0.250 → **0.750**。

**④ 「看见没进去」以前报的全是假缺口。**图里 `walked:false` 的边只在目标路由**确实到过**
时才补，所以它们的意思是「这条链接没走，但那一屏从别的路进去过」——不是缺口。
真正没进去的地址此前被整个丢掉了。给图加 `unvisited` 单独存着。

**一个假缺口比没有缺口更糟：它消耗信任，而信任是这一整块信息唯一的价值。**

修完之后缺口是真的能用了：`/owners/1/pets/new`、`/owners/1/pets/1/visits/new`
——PetClinic 的宠物与就诊管理，探索一次都没进去。而规格自己承认的盲区里
独立地写着「宠物新增、就诊记录的表单字段和校验规则未观察到」。**两个来源互相印证。**

**⑤ 模块起不出名字，是因为没给它信息。**模型看到的模块只有
`- oups　路由 /oups　流程 F-5`——一个路由段、一个流程编号。让它「用用户的话命名」，
却不给它用户看到的东西。补上**这一块里那些界面的标题**之后，四个模块全部有了人话名字
（首页入口 / 异常展示页 / 主人信息管理 / 兽医列表查看）。

### 阶段 B：「专业提示词值多少」——目前的答案是「量不出来」

问题来自一次提问：**「你是不是应该给 AI 专业方向的提示词来获得更高质量的物料产出？」**

`design.cases` 的提示词里点名了五种测试设计方法（等价类 / 边界值 / 状态迁移 / 判定表 /
负例）并要求每条用例说出自己用的哪一种。这是提示词里最长的一段。仓库里躺着一份写好的
消融定义，`why` 里写着「**它到底换来了多少覆盖率，没人量过**」。跑了。

#### 先修了消融本身：两臂差了不止一件事

第一次跑出来门禁 **0.842 vs 0.017**，看着像铁证。查 B 组的发现：55 条 `tier-unbacked`、
21 条 `oracle-vague`，而它的方法分布完全正常——**方法名照样标了，崩的是判据**。

逐行 diff：`CASES_STABLE_PLAIN` 是手写的第二份，46 行只留 26 行。除了 6 行方法定义，
它还砍掉了整段判据规范（五种 oracle 形式、「tier 1/2 必须给 oracle」）、
「界面文案逐字引用」、「全是正常路径的用例集是坏的用例集」、用例预算。

**那次比的是「完整提示词 vs 短得多的提示词」，回答不了它声称的问题。**
而 `evals/README.md` 第一条就写着：「两组必须只差一件事。差两件事然后读一个数字，
是一个项目说服自己相信假话的标准做法。」

改成**从原文里减去方法那一段**——单变量由构造保证，不靠人记得同步两份文本。
现在两臂精确相差 6 行，测试钉住。

#### 再修了题目：原来那道题在天花板上

纯净版在 `fixtures/mock-spec` 上跑两轮：覆盖 1.000/1.000 与 0.778/0.889，p=1 与 p=0.5。
看着像「没用」，但那个读法也是错的——**12 条清单，两臂都覆盖到 0.889–1.000，
没有空间显出差别**。p=1 说明的是「这道题两边都会做」。

换到 Juice Shop：14 条清单，基线 0.289 ± 0.061，余量充足。探索是确定性的
（同一应用五次图完全一致、标准差 0），所以两臂拿到同一张图，配对成立。

#### 结果

| 轮次 | A（点名方法） | B（不点名） | 不一致对 |
|---|---|---|---|
| 1 | 0.333 | **0.778** | A 独占 2 / B 独占 5 |
| 2 | **0.556** | 0.333 | A 独占 5 / B 独占 3 |
| 3 | **0.222** | 0.000 | A 独占 4 / B 独占 0 |
| 4 | 两臂都失败，作废 | | |

    合并：A 独占 11，B 独占 8，共 19 条不一致
    双侧精确二项 p = 0.648 —— 不显著

    两臂均值：0.370 vs 0.370（完全相同）
    单臂跨轮标准差：A ± 0.170，B ± 0.390

**方向逐轮翻转**：第 1 轮 B 好一倍，第 2、3 轮 A 好。

#### 结论要说准

**这不是「点名方法没用」，是「效应比噪声小，这个样本量看不出来」。**两者差别很大，
把前者当结论就是第二次犯今天早上那个错（拿一次运行的 0.778 当证据，而分布是
0.623 ± 0.149）。

能说的只有三句：

1. **在 Juice Shop 上，三轮配对读不出方向**，而单臂自己的跨轮方差（±0.39）
   远大于两臂的均值差（0.00）。
2. **要读出方向，需要的轮数远不止三轮。**19 条不一致里 11:8，要到 p<0.05
   得有明显更多且更一致的不一致对。
3. **在拿到那个答案之前，不该动那段提示词。**但也不该假设它值钱——
   它现在占着上下文，而上下文正是今天六次被截断的直接原因。

#### 这一节真正的产出

不是一个 p 值，是**两个把实验做废的错误被找出来了**：

- **两臂差了不止一件事**（手写第二份提示词必然漂移）——已由构造修掉
- **题目在天花板上**（清单太容易，没有余量）——已换到有余量的应用

这两条都不是这次消融独有的，是**这个项目此后每一次配对评测都要先过的两道检查**。

### 阶段 C：思考开关——覆盖率上看不出差别，但产出稳得多

#### 先更正一次

早先报过「开思考明显更好」（语义 0.333 → 0.444、留出 0.250 → 0.750、状态覆盖 0.231 → 0.769）。
**那个结论作废**，两条理由都记在当时的提交里：

1. **两臂条件不等价** —— 思考那一臂跑的时候还没有「截断就加大重来」，不思考那一臂有。
   我一边跑一边改了代码。
2. **思考那一臂 3 次里 2 次失败**，全是 token 被切断，能比的只有 1 次成功运行。

拿 n=1 且两臂差了不止一件事的数据当结论，正是这份文档反复在说的那个错。

#### 重跑：三处都修平

- 两臂同一份代码、同一套预算常数、同一个模型（qwen3.8-27b:free）
- 换到 TokenHarbor，实测**推理 token 在这个出口上不吃 `max_tokens`**
  （DashScope 上会吃，那正是上次 2/3 失败的原因）
- 三轮对三轮

#### 结果（PetClinic）

| 指标 | 思考=关（n=2） | 思考=开（n=3） |
|---|---|---|
| 语义覆盖 · 调优集 | **0.723 ± 0.078** | 0.630 ± 0.128 |
| 语义覆盖 · 留出集 | 0.625 ± 0.177 | **0.750 ± 0.250** |
| 状态覆盖 | 0.807 ± 0.054 | 0.769 ± 0.204 |
| 0-switch | 0.159 ± 0.012 | 0.150 ± 0.044 |
| **门禁①** | 0.982 ± 0.025 | **1.000 ± 0.000** |
| **用例数** | 34.0 ± **8.5** | 39.7 ± **0.6** |
| **说得出转移** | 26.0 / 34.0（76%） | **35.3 / 39.7（89%）** |
| tokens | 58981 | 69024（+17%） |
| 耗时 | 4.4 分 | 6.8 分（+55%） |

按黄金条目逐条比命中频率：**关更常命中 5 条，开更常命中 4 条**——平手。

#### 结论

**① 覆盖率上看不出差别，而且方向和早先那个作废的结论相反。**调优集是关略高、留出集是开略高，
两者的置信区间大幅重叠。**开思考不会提高覆盖率**，至少在这个样本量上看不出来。

**② 但产出明显更稳、更有据。**三件事是一致的，不是抖动：

- **门禁 1.000 ± 0.000**——三次全满分，而关思考是 0.982 ± 0.025
- **说得出自己覆盖哪条转移的用例从 76% 涨到 89%**
- **用例数的标准差从 ±8.5 掉到 ±0.6**——关思考时一次 28 条一次 40 条，开思考时 39/40/40

**③ 代价：+17% token，+55% 耗时。**

#### 该怎么用这个结果

默认仍然关着——**覆盖率是这条流水线的主要指标，而它没有提升**。

但「产出稳定性」这件事在两个场景下值那 55% 的时间：**要做配对评测的时候**
（今天 B 阶段的消融就死在方差上：单臂跨轮标准差 ±0.39，远大于两臂差 0.00），
以及**要把产出交给人复核的时候**（门禁满分、89% 的用例说得出自己验哪条转移，
直接降低阅读成本）。

**这也是一条方法论：方差本身是可以被当作指标优化的。**一个方差小的配置，
能让同样的样本量读出更小的效应——今天两次配对评测都卡在这一点上。

（A 组三次里有一次失败：`plan.stories: reply does not match the expected shape — stories
Required`。所以关思考那一臂是 n=2。这本身也算一个数据点：开思考那三次一次没失败。）
