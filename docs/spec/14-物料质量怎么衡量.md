# 14 · 目标、现状，以及「怎么正确衡量产出物料的质量」

写于 2026-08-29。这份文档回答一个具体问题：**我们产出的每一种物料，凭什么说它好或不好？
这个「凭什么」有没有学术方法论支撑，还是我自己编的？**

前一份（`13-重新规划.md`）回答的是「做什么、按什么顺序」。这一份回答「做出来之后，
拿什么尺子量」——而这个问题此前从来没有系统地问过。

---

## 一、目标，以及它对度量的硬要求

**把一个跑着的产品，变成一批人愿意读、愿意签字、并且真的能跑的端到端测试用例。**

三个限定词各自对应一类度量，而这一点此前是模糊的：

| 限定词 | 它要求量什么 | 现在量了吗 |
|---|---|---|
| **人愿意读** | 物料的**可读性与结构质量**（规格分层、故事良构、缺口可见） | 部分——有结构指标，**没有任何以人为被试的测量** |
| **人愿意签字** | 每条断言**说得出出处、能被推翻** | ✅ 判据兑现率、`covers`、`derivedFrom` 印记 |
| **真的能跑** | 执行通过率，以及**它真的验得住** | ✅ 通过率；变异得分刚起步 |

再往上一层是「做到能发论文的程度」，那对方法有硬要求：**有基准、有留出集、有误差棒、
指标要有据可依**。前三条这两天补上了，第四条就是这份文档。

---

## 二、现状：五种物料，各自现在被怎么量

    探索 → 材料 → 规格 → 用户故事 → 测试用例 → 代码 → 执行结果
           ①      ②       ③          ④         ⑤      ⑥

| # | 物料 | 现在的指标 | 在哪 |
|---|---|---|---|
| ① | 材料 | 状态数、转移数、实验数、停止原因 | `exec/sfg.ts` |
| ② | 规格 | 规则数、**海拔分布**、`evidence` 能否回材料定位、unknowns 数 | `casegen/nodes.ts` |
| ③ | 故事 | 故事数、有角色的比例、**挂到流程的比例**、活动数（骨架是否比躯干粗） | `casegen/nodes.ts` |
| ④ | 用例 | 门禁①分、**判据兑现率**、`covers` 填充率、方法分布、去重 | `casegen/gate.ts` |
| ⑤ | 代码 | 门禁②分、可执行性、片段复用 | `codegen/gate.ts` |
| ⑥ | 执行 | 通过率、**loose vs strict**、失败归类 | `codegen/repair.ts` |
| 全局 | | **语义覆盖**（黄金清单）、**结构覆盖**（状态/0-switch/1-switch）、**变异得分** | `harness-core/src/eval/` |

### 两块建好了、从没跑过的机制

**`eval/detect.ts`** —— 精确率 / 召回率 / F1，**以「失败」为正类**，并报出这一版
「偏向哪一边」（虚报 vs 沉默）。注释里说明了为什么以失败为正类：
在一个大部分东西都正常的用例集里，「准确率」几乎全是「你有多少 pass 判对了」，
而那是不有趣的那一半。**除了单元测试，它一次都没被真实数据跑过。**

**`eval/semantic.ts`** —— 用模型对关键词匹配漏掉的条目做语义裁决，作为**第二个数**。
它明确写了为什么不取代第一个：配对比较要求可复现，而度量中间放一个模型会让同一次运行
两次打分不同。**它也一次都没被接进流水线。**

## 三、关键问题：每一种物料，学术上是怎么衡量的

这一节是这份文档的主体。按物料分，先说学术方法论，再说我们差在哪。

### ② 规格

**方法论**

- **ISO/IEC/IEEE 29148**（需求工程）给出需求的质量特征：完整、一致、无歧义、
  **可验证**、可追溯、单一。其中「可验证」和「单一」是可以机械检查的。
- **需求异味（Requirements Smells）** —— Femmer 等，*Rapid quality assurance with
  Requirements Smells*，Journal of Systems and Software 2017。它把「写得不好」落成一组
  **可自动检测**的模式：主观语言、模糊副词、没有比较对象的比较级、否定式陈述、
  指代不明的代词、笼统量词。**这一支最适合我们直接用**——它不需要人，也不需要参考答案。
- **目标层级** —— Alistair Cockburn，*Writing Effective Use Cases*（2000）把用例分成
  云层 / 风筝 / 海平面 / 鱼 / 蛤 几个高度。**我们的 `altitude`（screen / flow / domain）
  是同一个想法的一个简化**，只是我当时并不知道有这个前人工作。

**我们差在哪**

- 海拔有了，但**没有任何异味检测**。规格里出现「正确显示」「合理提示」这类主观语言时，
  今天没有任何机制会说话。
- `evidence` 必须能在材料里逐字定位——**这一条其实比 ISO 的「可验证」更严**，是本项目的
  一个真实贡献，但从没被表述成一个指标（它现在只是一个内部布尔值 `source`）。

### ③ 用户故事

**方法论**

- **QUS 框架（Quality User Story）** —— Lucassen、Dalpiaz、van der Werf、Brinkkemper，
  *Improving agile requirements: the Quality User Story framework and tool*，
  Requirements Engineering 期刊，2016 年前后。它给出 **13 条质量准则**，分句法 / 语义 /
  语用三组：良构、原子、最小、概念自洽、面向问题、无歧义、完整、依赖显式、完整句、
  可估算、唯一、统一、独立。配套工具 **AQUSA** 自动检查其中一部分。
  *（年份与期刊卷号我有把握到「2016 年前后的 Requirements Engineering 期刊」，
  正式引用前需核对。）*
- **INVEST** —— Bill Wake，2003：Independent、Negotiable、Valuable、Estimable、
  Small、Testable。业界通用，其中 Valuable（有角色有收益）和 Testable 是可检查的。
- **故事地图** —— Patton 2014，已经在用。

**我们差在哪**

- 我们检查了 QUS 里的两条半：**良构**（有角色/收益）、**唯一**（去重）、
  **可测**（挂到流程 = 有可执行的路径）。**其余十条一条都没有。**
- 最该补的是 **原子（atomic）** 与 **最小（minimal）**：一条故事塞进三个能力，
  或者故事里夹带验收标准之外的实现细节，今天完全看不出来。这两条 AQUSA 能自动查。
- 「骨架必须比躯干粗」是我自己立的规矩（活动数 < 故事数 × 0.8）。
  它呼应 Patton 的结构，但**那个 0.8 是我拍的**。

### ④ 测试用例 —— 这一层的方法论最成熟

**方法论**

- **覆盖准则的统一框架** —— Ammann & Offutt，*Introduction to Software Testing*
  （第二版 2016）。它把覆盖准则分成四类：图覆盖、逻辑覆盖、**输入空间划分**、
  基于语法的覆盖。我们的东西正好落在其中两类：
  - 状态覆盖 / 0-switch / 1-switch = **图覆盖**（源头是 Chow 1978 的 W 方法）
  - 等价类 / 边界值 = **输入空间划分**
  - **逻辑覆盖（判定/条件/MC-DC）我们一条都没有**，而判定表方法本该落在这里。
- **判据问题（The Oracle Problem）** —— Barr、Harman、McMinn、Shahbaz、Yoo，
  *The Oracle Problem in Software Testing: A Survey*，IEEE TSE 2015。它把判据分成
  **指定判据**（specified）、**派生判据**（derived）、**隐式判据**（implicit，如崩溃）
  和**无判据**。**我们的 tier 1/2/3 与这个分类高度对应，而我一篇都没引过**——
  这是我们最该补的一条引用，因为「判据兑现率」这个指标正是对这个问题的一个回答。
- **变异测试** —— DeMillo/Lipton/Sayward 1978；综述见 Jia & Harman，
  *An Analysis and Survey of the Development of Mutation Testing*，IEEE TSE 2011。
  三个概念直接关系到我们刚做的东西：
  - **耦合假设**：简单缺陷与复杂缺陷耦合，所以注入简单缺陷是有效的代理。
    **这正是「近似变异」（`empty`→`blank`）的理论依据**，而我当时只是凭直觉这么做。
  - **等价变异体**：改了但语义不变，本来就不该被杀。判定它不可判定，是这个领域的老问题。
  - **变异体归并**：一部分变异体被另一部分蕴含，用来削减规模。我们还没做。
- **测试异味** —— van Deursen 等 2001 提出，Garousi & Küçük 2018 有综述。
  断言轮盘、条件测试逻辑、神秘来客等。**我们的门禁①有一部分实际上在查测试异味
  （含糊断言、步骤过多、凭空的 covers），但从没和这一支对上过。**

**我们差在哪**

- 逻辑覆盖（判定/条件/MC-DC）完全空白。
- 变异体归并没做，规模一上去会有大量冗余。
- 门禁①的规则是我一条条攒的，**没有对照测试异味的既有目录**——很可能漏了公认的几类。

### ⑥ 执行结果

**方法论**

- **不稳定测试（Flaky tests）** —— Luo、Hariri、Eloussi、Marinov，
  *An Empirical Analysis of Flaky Tests*，FSE 2014。它给出了不稳定的成因分类
  （异步等待、测试顺序依赖、并发、资源泄漏……）。**我们有 `flakiness` 表，
  但从没系统量过，也没按成因分类。**
- **检测质量** —— 以「失败」为正类的精确率/召回率。`detect.ts` 已经实现了。

### 跨物料：LLM 产出物怎么评

- **参考式 vs 无参考式评估。**我们的语义覆盖是参考式（对着人写的黄金清单）。
- **LLM 当裁判的偏差** —— Zheng 等，*Judging LLM-as-a-Judge with MT-Bench and
  Chatbot Arena*，NeurIPS 2023。已知位置偏差与**自我偏好偏差**。
  **这直接威胁 `semantic.ts`**：如果裁决模型和生成模型是同一个，那个偏差是系统性的，
  而我们现在正是同一个模型。
- **实验有效性的四类威胁** —— Wohlin 等，*Experimentation in Software Engineering*
  （2012）：结论有效性、内部有效性、**构念有效性**、外部有效性。
  这是给我们下面那节「缺口」用的框架，而不是又一个指标。

## 四、诚实的对账：哪些有据，哪些是我编的

| 指标 | 学术支撑 | 我发明的部分 |
|---|---|---|
| 状态覆盖 / 0-switch / 1-switch | ✅ Chow 1978；Ammann & Offutt 图覆盖 | 分母定义（排除自环与走不通的边） |
| 变异得分 | ✅ DeMillo 1978；Jia & Harman 2011 | 黑盒注入位置；**notApplied 单列成第三类** |
| 精确率/召回率（`detect.ts`） | ✅ 标准；「以失败为正类」是有意选择 | 「偏向哪一边」的分类 |
| 判据兑现率 | ◐ 对应 Barr 2015 的判据分类，但**没引过** | tier 1/2/3 与「声称 vs 兑现」这个具体形式 |
| 语义覆盖（黄金清单） | ◐ 参考式评估的标准做法 | 关键词匹配器；清单由**读过应用的人**写 |
| 规格海拔 | ◐ 呼应 Cockburn 2000 的目标层级 | screen/flow/domain 这个三分 |
| 门禁①分 | ✗ | 全部（无警告用例占比）；部分规则事实上是测试异味，但没对照过目录 |
| loose vs strict 通过率 | ✗ | 全部（反作弊思路常见，这个具体形式是我发明的） |
| 「骨架比躯干粗」 | ◐ 呼应 Patton 2014 | 0.8 这个阈值是拍的 |

**这张表本身就是一个结论**：我们最硬的三个指标（图覆盖、变异得分、精确率/召回率）都有
成熟支撑；而**最常被我拿来汇报的那个（语义覆盖）恰恰是支撑最弱的**。

## 五、四个最大的方法论缺口

### 缺口一：只量召回，不量精确 —— 最严重

语义覆盖问的是「**该测的测了多少**」。它**不问「测的都对不对」**。

一套生成 200 条垃圾用例外加 10 条好用例的系统，覆盖率和只生成那 10 条的一样高。

我们其实**已经有一个精确率信号，只是从没命名**：**执行**。今天 38 条跑出 3 条失败，
其中 S-08-3（声称电话填负数会报 `numeric value out of bounds`）是**期望写错了**
——那是一条无效用例。也就是说「执行判定的无效率」约 2.6%，而这个数从没被报过。

`detect.ts` 的框架已经在了，**只差把执行结果喂进去并人工标注 actual**。

### 缺口二：黄金清单由读过应用的人写 —— 构念有效性

三份清单的 `bias` 字段都老实写了这一点，但**只是声明，没有缓解**。
学术上的标准做法有两条，我们哪条都没走：

- 清单由**不接触实现**的人依据需求文档写（我们没有需求文档——这是黑盒的固有困难）
- 用**已知缺陷集**（Defects4J 那一类）作为参考，绕开人写清单

**变异测试正好是第二条的一个替代**：它的参考不是人写的清单，而是**人造缺陷**，
而缺陷是从产品自己的事实生成的。这是变异得分比语义覆盖**方法论上更硬**的原因，
而我此前把它当成「补充指标」。

### 缺口三：关键词匹配是弱匹配器，而语义裁决有自我偏好偏差

`semantic.ts` 的注释已经把这个取舍写得很清楚（可复现 vs 更准），但它**从没被接进流水线**。
更要紧的是：如果裁决用的是生成用例的同一个模型，**自我偏好偏差是系统性的**
（Zheng 等 2023）。真要用，裁决模型必须和生成模型不同——这一点代码里没有任何强制。

### 缺口四：复核耗时从没测过

这是三条验收指标里**唯一需要人参与、也唯一直接对着原目标**的一条。
从 `12-…md` 立项写到今天还是「未测量」。

现在故事图终于完整了（三类缺口都在），测它才第一次有意义——
此前测出来的是「读一张残图要多久」。

## 六、建议的补法（按性价比排序）

1. **把执行结果喂进 `detect.ts`。**框架现成，只差人工标注每条用例的 `actual`。
   这一步把「只量召回」变成「召回 + 精确」，是缺口里最严重那个的直接解药。
   38 条用例的人工标注，一次一两个小时。

2. **把变异得分从补充指标提到主指标。**它的参考物是人造缺陷而不是人写清单，
   构念有效性更高。要做的是规模化（几十个变异体 × 全套用例）——靠缓存回放几乎不烧 token。

3. **补需求异味检测**（Femmer 2017 那一支）。纯静态、纯确定性、不需要人也不需要参考答案，
   而且它查的正是「主观语言、模糊副词、指代不明」——那恰恰是模型最容易写出来的东西。

4. **对照 QUS 的 13 条补故事质量检查**，优先「原子」与「最小」。AQUSA 能自动查的那几条
   直接抄过来。

5. **测复核耗时。**需要你或者另一个人参与，一次半小时。

6. **补上该引的文献**，尤其 Barr 2015（判据问题）——我们的 tier 体系正是对它的一个回答，
   而一篇都没引。

## 七、这份文档最该被记住的一句

**我们最硬的指标不是我最常报的那个。**

图覆盖、变异得分、精确率/召回率都有几十年的方法论撑着；而语义覆盖——我这两天在每一份
汇报里放在第一行的那个数——用的是关键词匹配，对着一份由读过应用的人写的清单，
**只量召回不量精确**。

它不是错的，它是一个**下界估计**，而且是可复现的下界估计，这有它的用处。
但把它当成「产出质量」的头号证据，是把最方便的数当成了最有说服力的数。
