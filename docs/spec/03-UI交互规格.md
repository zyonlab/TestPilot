# 03 UI 交互规格

> **双重身份**：本文档同时是自举时 gold checklist 的来源——每条"可验证的交互契约"都能被抽成一条黄金用例。
> 因此每页都要写出：元素、交互、状态（空/载入/错误）、以及**可验证的断言点**。


## 2. 工作流画布（Canvas）★

**定位**：画布是执行图的**真实视图**，不是示意图。它显示什么，运行时就在做什么。

| 元素 | 交互 | 断言点 |
|---|---|---|
| 节点卡 | 显示：类型图标、标题、状态色、耗时、token、门禁摘要 | 运行中节点必须有区别于待运行节点的视觉状态 |
| 连线 | 拖拽连接；类型不兼容时红色 + 悬浮说明原因 | 非法连线不可保存，且给出可读原因 |
| 选中节点 | 右侧属性面板：参数编辑（zod 驱动表单）、IO 契约、最近一次输入/输出/prompt | 面板内容与该节点最近一次运行一致 |
| 右键菜单 | 只跑此节点 / 从此节点续跑 / 设断点 / 查看轨迹 / 复制产物 | 三种调试模式全部从这里发起 |
| 顶栏 | 图版本选择器、保存（产生新版本）、与另一版对比、运行/暂停/取消、预算与花费 | 保存后版本号 +1；历史运行仍指向旧版本 |
| 布局 | elkjs 自动排布 + 手动微调；缩放/平移/小地图 | — |
| 状态 | 空态（未选图，引导创建）/ 载入 / 运行中（实时推送）/ 已暂停（断点） | 暂停时明确显示停在哪个节点、为什么停 |

**运行实时性**：节点状态、日志、产出全部走 WS 推送（见文档 06），不轮询。

## 3. 三种调试的 UI 形态

| 模式 | 入口 | 展示 |
|---|---|---|
| ① 拆解调试 | 画布上 pin `plan.*` 子图 → 运行 | **覆盖矩阵**：gold checklist × 生成用例，命中/遗漏/多余三色；顶部给 Coverage 数值与遗漏清单 |
| ② 结构调试 | 复核队列或画布节点上"抽样 1-2 条" | 门禁①逐条判据表：判据、命中、证据片段、建议 |
| ③ 单例贯通 | 用例详情页"走阶段二" | 三栏：文本用例 / 生成代码（含静态门禁标注）/ 执行轨迹（截图+步骤+断言结果） |

## 4. 进程页（Processes）★　🟡 已实现（缺 CPU/内存、能力进程、日志筛选）

每进程一张卡：类型徽标、pid、状态（spawning/alive/draining/crashed）、启动时间、重启次数、CPU/内存、最后心跳、当前任务、累计 calls/tokens/耗时、日志尾巴（可展开）。
操作：重启、停止、杀掉当前执行。能力进程额外显示 recipe 名与健康检查结果。
断言点：杀掉一个 runner 后，页面在 3 秒内反映其状态变化，且不影响其他进程卡。

## 5. 用例看板（Cases，改造）

在现有 P0/P1/P2 分列基础上增加：判定 tier 徽标（1/2/3）、设计方法标签、门禁①分数、退化标记（曾被自动改过断言语义或曾被删除重建）、故事归属。
筛选器：按 tier / 设计方法 / 门禁分数 / 退化标记 / 故事。
断言点：切换筛选后列表条数与顶部统计一致。

## 6. 复核队列（Review，新增）

来源：门禁①不合格项、门禁②放弃项、带退化标记的用例。
交互：左列表右详情；详情内可直接编辑文本用例、重新打分、重生成、批准进入阶段二；支持批量操作。
断言点：批准后该条从队列消失并出现在 `approved` 状态。

## 7. 评测页（Evals，新增）

- 运行一次评测：选 gold checklist + 图版本 + 消融配置。
- 结果卡：Coverage、Precision/Recall/F1（Fail 为正类）、**滑向判定**（误报型 / 漏报型 / 均衡）、成本。
- 配对比较：选两次 eval → 差值、McNemar 的 nAB/nBA/p 值、逐题翻转清单。
- 断言点：同输入同图版本跑两次，结果一致（可复现性自检）。

## 8. 能力与 Chat（新增）

能力列表（recipe 名、状态、健康检查、端口/参数、起停按钮）；右侧 Chat 与 agent 对话，产出 recipe 草稿 → 校验 → 保存 → 启动。
断言点：Chat 生成的 recipe 必须先通过 schema 校验才出现"保存"按钮。

## 9. 全局交互约定

1. **长任务**：本地模型一步几十秒——所有可能超过 3 秒的操作必须有进度、可取消、可后台化（切页不中断）。
2. **实时**：一条 WS 订阅全部；断线自动重连并补拉断线期间事件（按事件 id 续传）。
3. **空态**：每个列表页都有空态文案与下一步引导（现有 Projects 页的做法保持）。
4. **错误**：统一错误卡（code + 可读原因 + 重试按钮），不吞异常。
5. **i18n**：zh/en/ja 三语，新增文案一律走 `t()`；断言点：切换语言后无硬编码残留。
6. **可访问性**：键盘可达、focus 可见、色彩不作为唯一状态区分（tier/状态色都配文字或图标）。
