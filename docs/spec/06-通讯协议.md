# 06 通讯协议

## 1. 总览

| 链路 | 传输 | 形态 |
|---|---|---|
| 浏览器 ↔ gateway | HTTP REST + WebSocket | REST 做 CRUD 与命令，WS 做单向事件推送 |
| gateway ↔ agent | `birpc` over `child_process.fork` 的 IPC 通道 | 双向类型安全 RPC |
| gateway ↔ runner | 同上 | **阶段 0 现状：网关直连 runner**（还没有图运行时，让 agent 中转只是多一跳）。阶段 1 图运行时上线后改由 agent 派发，本表随之更新 |
| agent ↔ runner | 同上 | 阶段 1 起生效；runner 只被动接活 |
| gateway/agent ↔ capability | 子进程 + 健康检查 HTTP/TCP | 由 recipe 声明 |

原则：**命令走 RPC/REST，事实走事件**。任何状态变化都必须先落 `events` 再广播——UI 看到的与 lineage 记录的是同一份东西。

实现细节（已落地）：
- 传输用 `fork` 自带的 IPC 通道（结构化 JSON 消息），省掉手写分帧；我方帧统一打标 `{ __rpc: ... }`，
  这样同一条通道以后还能承载非 RPC 流量而不干扰 birpc。
- 传输用 `serialization: "advanced"`（结构化克隆）而非默认 JSON：**被拒绝的 RPC 必须带着 message 过来**。默认序列化下 Error 过界会变成 `{}`，最该读的那条诊断正好丢掉——这条是实测撞出来的。
- 交互式会话（explore / debug）的帧走 `session.progress` 事件（不合并），截图以**文件引用**过界，网关读完即删并内联成 SSE 的 data URL，前端契约不变。
- `emit` / `heartbeat` 是**单向方法**（birpc `eventNames`）：调用方不等回包，否则一个话多的 runner
  会堆出一片永不 resolve 的 promise。
- 子进程侧的样板（RPC 接线、心跳循环、spend 记账）由 `startChild()` 统一提供——**心跳方式不一致的进程，
  监工没法推理它的死活**。

## 2. 通用信封

```ts
type Envelope<T> = {
  v: 1;                 // 协议版本
  id: number;           // 单调递增，断线续传的锚点
  ts: string;           // ISO
  scope: { projectId?: string; wfRunId?: string; nodeRunId?: string; runId?: string };
  kind: string;         // 事件/方法名
  payload: T;           // 由 kind 决定，zod 校验
}
type Err = { code: string; message: string; retryable: boolean; detail?: unknown };
```

错误码前缀：`MODEL_*`（模型不可用/格式/上下文超限）、`EXEC_*`（环境/超时/定位/断言）、`CAP_*`（能力未就绪）、`GRAPH_*`（校验失败）、`BUDGET_*`、`GUARD_*`。
**归因即协议**：`EXEC_TIMEOUT` 这类必须映射到失败归因 `infra`，不能与 `assert` 混。

已落地（`harness-testing/src/failure.ts`）：

| code | 归因 | 可重试 | 含义 |
|---|---|---|---|
| `MODEL_UNAVAILABLE` | infra | 是 | 模型端点故障：502/终止/限流 |
| `EXEC_ENV` | infra | 是 | 被测环境或浏览器故障：`net::ERR_*`、Target closed |
| `EXEC_TIMEOUT` | infra | 是 | 导航/操作超时 |
| `EXEC_LOCATE` | locate | 是 | 模型没能在页面上定位目标（重规划可能成功） |
| `EXEC_ASSERT` | assert | 否 | 判据不成立——这是一个结论，重跑还是同一个结论 |

**未知错误默认落 `assert` 而不是 `infra`**：把不认识的错误当成"环境抖动"，等于给漏报开后门。
run 记录上落 `failCode` / `failKind` 两列，HTTP 错误响应同样带 `code`。

## 3. WS 事件表（gateway → 浏览器）

| kind | payload 要点 |
|---|---|
| `wf.run.started` / `wf.run.finished` | wfRunId、graphVersion、结束原因（done/budget/cancelled/failed） |
| `wf.node.started` / `wf.node.finished` | nodeId、状态、耗时、tokens、cost |
| `wf.node.output` | 产物摘要（大对象只给引用，前端按需拉） |
| `wf.paused` | 停在哪个节点、为什么（断点/预算/护栏） |
| `gate.result` | gateId、分数、逐条判据命中、不合格项 |
| `case.created` / `case.updated` | 用例快照（探索直播复用此事件） |
| `run.progress` | runId、步序、动作描述、截图引用 |
| `session.progress` | 交互式会话（explore / live debug）的一帧；不合并，截图以文件引用传递 |
| `run.finished` | 状态、归因、attempts、healed、visual/perf/oracle 结果 |
| `repair.round` | 轮次、diff 分类、是否有进展 |
| `artifact.ready` | 类型、引用 URL |
| `process.status` | 进程快照（含心跳、当前任务、累计成本） |
| `budget.update` | calls/usd/ms 的已用与上限 |
| `log` | 级别、来源进程、文本（截断，全文走工件） |
| `error` | Err |

**背压**：截图一律以引用（`/api/artifacts/:name`）传递，不内联 base64（现有实时调试的 base64 直传逐步改造）；同一 nodeId 的高频进度事件在 gateway 侧做 100ms 合并。
**断线续传**：客户端重连时带 `lastEventId`，gateway 从 `events` 表补发；超出保留窗口则回复 `resync` 让前端全量拉状态。

## 5. gateway ↔ agent（birpc 方法表）

```ts
// gateway → agent
startRun(input: {graphVersionId, inputs, ablate, budget}): {wfRunId}
controlRun(wfRunId, action: 'pause'|'resume'|'cancel'): void
runNode(wfRunId, nodeId, mode: 'only'|'from'): {nodeRunId}
getState(wfRunId): WfState
health(): {ok, spend, activeRuns}

// agent → gateway
emit(evt: Envelope<unknown>): void          // 事件上行，gateway 落库 + 广播
requestCapability(id): {endpoint, vars}      // 需要能力时按需拉起
persist(kind, payload): {ref}                // 大产物落工件，返回引用
```

## 6. agent ↔ runner

```ts
// agent → runner
exec(spec: {target, caseCode|steps, env, capabilities}): {runId}
capture(kind: 'visual'|'perf', opts): Result
explore(opts): Flow[]
cancel(runId): void
// runner → agent
progress(evt): void        // 逐步推送，最终汇总为 run.finished
```

约定：runner **无状态**，一次 exec 一个浏览器/设备会话，结束即清理；崩溃由监工上报为 `infra` 归因，不自动重试（是否重试由 loop 层决定）。

## 7. 心跳、超时与版本

- 心跳 3s；连续 3 次缺失判定 `crashed`。
- 每个 RPC 带超时；模型类调用的超时按节点声明（本地模型一步可达 90s，默认不能用通用 30s）。
- 协议版本 `v` 不匹配时 gateway 拒绝连接并提示升级；事件 payload 用 zod 校验，未知字段忽略、缺字段报错。
