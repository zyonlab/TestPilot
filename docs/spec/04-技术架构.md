# 04 技术架构

## 1. 进程拓扑

```
浏览器 ──REST + WS──▶ tp-gateway ──birpc/stdio──▶ tp-agent ──birpc/stdio──▶ tp-runner ×N
                          │  (网关 + 监工)          (图运行时/规划/预算/评测)      (Midscene 执行/基线采集)
                          └──────────────────────▶ tp-capability ×M
                                                    (anvil / model-proxy / mock / 设备桥)
```

| 进程 | 职责 | 崩了会怎样 | 重启 |
|---|---|---|---|
| `tp-gateway` | HTTP/WS、静态与工件、CRUD、**监工** | UI 断线 | 由 pnpm/systemd 拉起 |
| `tp-agent` | 图运行时（LangGraph）、规划拆解、预算、记忆、评测调度 | 工作流停在最近检查点 | 自动重启 + 续跑 |
| `tp-runner` ×N | Midscene 会话、视觉/性能采集、链上断言、探索 | 只影响该次执行 | **不自动重启**（重试无意义的失败要立刻上报） |
| `tp-capability` ×M | 外部能力 | 依赖它的任务转 blocked | 自动重启 + 健康检查 |

**为什么多进程**：① 浏览器/adb 卡死与 OOM 必须隔离（现在一次泄漏拖垮整个 server）；② VL 长等待下进程比线程干净；③ 能力有独立生命周期；④ 每进程独立记成本账；⑤ 调试时能单杀一次执行而不动 agent。

## 2. 仓库结构（pnpm workspace）

```
packages/
  harness-core/      obs/ harness/ util/ ✅   graph/ loop/ eval/ model/ ⬜   ← 与垂类无关（见文档 05）
  harness-testing/   exec/ baselines/ report ✅   nodes/ gates/ caps/ ⬜     ← Domain Pack
apps/
  gateway/  agent/  runner/  web/
fixtures/
  mock-spec/         阶段一 TDD 的假规格 + gold checklist
  apps/              内置被测应用（现有 /testlogin /testflaky /testdapp 迁出）
```

阶段一**不拆包发版**，但用 lint 规则禁止 `harness-core → harness-testing` 反向依赖。

**`server/` 暂不入 workspace**：它保留自己的 lockfile，直到网关迁移那一块把它变成 `apps/gateway`。
pnpm 的一个副作用要记住：嵌套的非成员包无法从自身目录安装（pnpm 会向上解析到 workspace 根），
因此用根脚本 `pnpm run server:install` / `pnpm run server:dev`（内部带 `--ignore-workspace`），
不要 `cd server && pnpm install`。

## 4. 部署形态

- **dev**：`pnpm dev` 起 gateway（含监工）→ 监工拉起 agent/runner/capability；web 走 rsbuild dev。
- **单机生产**：gateway 服务静态产物 + API；其余进程由监工托管。全部本机，不出网。
- 配置：`.env` + `settings.json`（现有）+ ✅ `server/harness.config.ts`（模型闸并发、队列与 runner 数、事件保留、预算默认值、消融开关、护栏、能力清单）。
  **文件是知识，env 是开关**：文件告诉你有哪些旋钮，环境变量仍然覆盖它——临时调一次并发不该改代码。

## 5. 选型

| 位置 | 选型 |
|---|---|
| 图运行时 | **自研 DAG 运行时**（`harness-core/graph`，约 250 行 + 24 个测试）。原定 LangGraph，实装时改掉了，理由见下 |
| 画布 | React Flow + elkjs |
| 契约 | zod + `zod-to-json-schema`（与模型结构化输出同源） |
| 进程 | `execa` + 极薄监工（PM2 是服务级，我们要任务级语义） |
| 进程 RPC | `birpc` over stdio |
| 并发/重试 | `p-queue`（替换自研 `queue.ts`，保留 label/status 语义）+ `p-retry` |
| 追踪 | OpenTelemetry SDK + GenAI semconv（可选接自托管 Langfuse） |
| WS | `ws` + zod 消息校验 |
| 代码门禁② | `ts-morph` + `jscpd` + `@typescript-eslint` 自定义规则 |
| 执行 | Midscene（web/iOS/Android） |
| 链 | Foundry anvil |
| 存储 | better-sqlite3（现有） |
| 测试 | vitest + msw |

自研只保留四处：图运行时、配对 McNemar 统计、消融开关清单、领域门禁判据。

**为什么图运行时没用 LangGraph**（原定选型，实装时推翻）：装上试了之后，它能给的主要是检查点与 interrupt，而这个项目要的三件事它都不直接支持——
① **从任意节点部分重跑**（三种调试模式的地基）需要按节点缓存产物，我们本来就要为画布存这份产物，存了之后"续跑"是免费的；
② **图是用户可编辑的、从库里读出来的**，映射到 StateGraph 需要每次运行动态建图，比直接走拓扑序更绕；
③ **循环放在节点里而不是图里**——"薄图厚模块"这条原则下，有界修复是一个 `repair.loop` 节点的内部行为，不是图上的环；图保持 DAG，校验、拓扑序、部分重跑全都简单。
代价说清楚：条件路由与并行分支要自己写（目前不需要），换来的是运行时可以完全被单测覆盖、且没有一层版本会漂的外部状态机。

## 5.1 三处实现取舍（记下来免得被当成 bug）

1. **`process.status` 属于合并投递集合**：`draining → exited → spawning` 这类快速跳变，订阅者只会收到最终态。进程卡片显示当前态是对的，完整跳变序列在 lineage 里查。
2. **操作员点重启不计入 `restarts`**，只计崩溃重生——你想看的是"它自己崩了几次"。
3. **runner 的 cwd = 网关目录**：Midscene 往 cwd 下写 `midscene_run/`，钱包与种子在 `.wallets/`，两边必须看到同一份。搬迁期间踩过两次坑（`wallet.ts`、`injectedWallet.ts` 的 `__dirname`），凡是按相对路径找文件的代码进包前都要过一遍这一条。

## 6. 安全与隔离

- 密钥：现有 vault（`.data/secret.key` 加密）保留；只出不进。
- 护栏：非白名单域名上的不可逆动作默认拦截；自举时目标强制 localhost。
- 能力沙箱：能力进程只拿到自己 recipe 声明的环境变量。
- 自测隔离：自举运行使用独立 `.data-selftest/`，不污染生产库。
