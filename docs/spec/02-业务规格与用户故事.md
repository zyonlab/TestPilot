# 02 业务规格与用户故事

> **本文档有双重身份**：既是产品规格，也是阶段二自举时喂给 harness 的 spec 输入。
> 因此结构必须规整：故事 `US-xx`、验收标准 `AC-xx.y`、状态机显式列出。改本文即改测试输入。

## 1. 产品定位

TestPilot 是一个**垂类 harness agent**：吃产品规格 / 代码库 / 运行中的界面，产出两级产物——
① 基于用户故事的**文本用例**（人可读、与端无关、满足测试设计规范）；
② 可在 Midscene 上执行的**测试用例代码**（模块化、可复用、可参数化、易 scale）。
全程可观测、可衡量、可消融，运行在私有环境，模型是本地自托管 VL。

## 2. 角色

| 角色 | 关心什么 |
|---|---|
| QA 工程师 | 用例覆盖全不全、判据准不准、复核与调整是否顺手 |
| 测试开发 | 生成的代码能不能维护、能不能扩、跑得稳不稳 |
| 团队负责人 | 趋势、抖动率、门禁结论、成本 |
| harness 开发（自举时） | 节点级调试、评测差值、失败归因 |

## 3. 术语

| 术语 | 含义 |
|---|---|
| Project | 一个被测产品 |
| Target | 被测目标：`{ kind: web \| ios \| android, entry, capabilities[] }` |
| Capability | 外部能力实例（本地链、mock 服务、设备桥、模型代理） |
| Story | 用户故事，用例的归属主干 |
| TextCase | 阶段一产物：文本用例 |
| CodeCase | 阶段二产物：Midscene 用例代码 |
| Graph | 画布上的工作流定义（有版本） |
| WfRun | 一次工作流运行（pin 了图版本） |
| Run | 一次用例执行 |
| Batch | 一次套件运行（带门禁结论） |
| Gate① / Gate② | 文本用例设计规范门禁 / 用例代码规范门禁 |
| Eval | 一次评测（coverage / P-R-F1 / 配对差值） |
| Gold Checklist | 人工编写的黄金清单，Coverage 的参照物 |

## 4. 用户故事

### 4.1 项目与目标
- **US-01** 作为 QA，我要新建项目并指定目标端（web/iOS/Android）与入口，以便后续所有产物挂在它下面。
  - AC-01.1 目标端为 web 时可选启用 web3 能力；iOS/Android 时该选项不可见。
  - AC-01.2 删除项目级联删除其用例、运行、基线，且需二次确认。
- **US-02** 作为 QA，我要为项目配置多套环境（变量、固定头、query、登录方式），以便同一批用例跑在不同环境上。
  - AC-02.1 登录支持三种：UI 步骤、API 登录、粘贴会话（cookie/storageState）。
  - AC-02.2 密钥只以 `${secret.KEY}` 引用，明文永不返回前端。

### 4.2 输入源与阶段一
- **US-03** 作为 QA，我要上传/指向产品规格文档作为输入源，让 harness 拆出用户故事主干。
  - AC-03.1 拆解结果以故事树呈现，每个故事可展开为测试点。
  - AC-03.2 每条用例可追溯到唯一的故事/需求；孤儿用例被计数并高亮。
- **US-04** 作为 QA，我要用探索模式让 agent 漫游界面补充故事（无规格或规格不全时）。
  - AC-04.1 探索过程实时可见（页面截图 + 日志 + 逐条产出）。
  - AC-04.2 探索产物与规格产物同构，进入同一条流水线。
- **US-05** 作为 QA，我要 harness 按测试设计方法展开用例（等价类、边界值、状态迁移、判定表、异常路径）。
  - AC-05.1 每条用例标注所用设计方法。
  - AC-05.2 负例/边界用例占比不低于阈值。
  - AC-05.3 每条用例标注判定硬度 tier1/2/3，看板显示分布。
- **US-06** 作为 QA，我要看到门禁①的逐条判据结果与总分，以便决定复核哪些。
  - AC-06.1 门禁①只打分标记，不阻断流程。
  - AC-06.2 不合格项进入复核队列，可批量修正或重生成。

### 4.3 阶段二与执行
- **US-07** 作为测试开发，我要把一条文本用例生成为 Midscene 用例代码，并在真实目标上跑通。
  - AC-07.1 代码分层：`cases/` 只表达意图，页面细节在 `actions/`，业务流在 `flows/`。
  - AC-07.2 公共片段（登录、造数、清理）被引用而非复制。
  - AC-07.3 数据与逻辑分离，支持环境变量、密钥、用例级参数、数据行。
- **US-08** 作为测试开发，我要生成失败时 harness 自主有界修复，直到通过门禁②或判定放弃。
  - AC-08.1 修复次数有上限，且连续 K 轮无进展即停并标记原因。
  - AC-08.2 失败先归因为 `infra` / `locate` / `assert` 三类，infra 不计入产品缺陷。
  - AC-08.3 每轮修复的改动分类落盘；报告同时给宽口径与严口径通过率。
- **US-09** 作为 QA，我要单条或成套运行用例，并得到通过/失败与失败原因。
  - AC-09.1 支持数据驱动（一条用例按数据行跑多次）。
  - AC-09.2 套件运行给出门禁结论（pass/fail）与抖动、隔离统计。

### 4.4 基线与专项（现有能力，不允许丢失）
- **US-10** 作为 QA，我要视觉基线：首次运行留基线，之后比对并给出差异百分比与差异图，可审批更新基线。
- **US-11** 作为 QA，我要性能基线：采集 TTFB/FCP/DCL/Load，与基线和预算比对并标回归，可审批更新。
- **US-12** 作为 Web3 QA，我要 dapp 用例在注入钱包的环境下运行，并用链上状态做断言（余额增减、交易提交）。
  - AC-12.1 本地链/主网 fork 由能力层托管，UI 可见可起停。
- **US-13** 作为负责人，我要趋势页看通过率、抖动率、MTTR、覆盖、自愈率与批次历史。

### 4.5 画布与调试
- **US-14** 作为 harness 开发，我要在无限画布上看到工作流的真实执行图，节点上显示状态、耗时、token、门禁结果。
- **US-15** 作为 harness 开发，我要编辑画布（增删节点与连线、改参数），保存即产生新图版本。
  - AC-15.1 连线按节点 IO 契约校验，类型不兼容时给出明确原因。
  - AC-15.2 每次运行 pin 图版本，历史运行的解释不受后续改图影响。
- **US-16** 作为 harness 开发，我要三种调试：
  - AC-16.1 只跑拆解子图，并与 gold checklist 对拍覆盖矩阵（"该拆成 N 个吗"）。
  - AC-16.2 抽样 1-2 条跑阶段一，查看门禁①逐条命中详情（"结构合理吗"）。
  - AC-16.3 pin 单条用例走完阶段二并真实执行（"代码合理吗、跑得动吗"）。
  - AC-16.4 任意节点可单跑、可断点、可带上游产物续跑。

### 4.6 能力、进程与评测
- **US-17** 作为 QA，我要在 UI 上与 agent 对话来扩展外部能力（如"起一条本地链"），agent 产出的是声明式 recipe 与健康检查，而非临时进程。
- **US-18** 作为运维/开发，我要看到所有进程的状态（类型、pid、心跳、重启次数、当前任务、累计成本），并能重启/停止/杀掉某次执行。
- **US-19** 作为 harness 开发，我要跑评测：Coverage、以 Fail 为正类的 P/R/F1，并明确报告这一版滑向误报还是漏报。
- **US-20** 作为 harness 开发，我要配对比较两版（图/提示词/组件开关）跑同一批题的差值与显著性。
- **US-21** 作为 harness 开发，我要用 `ABLATE=` 关掉任一组件跑一遍，以证明该组件的价值。
- **US-22** 作为用户，我要中英日三语界面，并可编辑提示词模板、开关 LLM 调试日志。

## 5. 状态机

**TextCase**：`draft → gated(scored) → approved → codegen → (codeReady | blocked)`；复核队列作用于 `gated`。

**CodeCase**：`generated → executing → (green | repairing) ; repairing → executing ; repairing --K轮无进展--> blocked`。

**Run**：`queued → running → (passed | failed) [→ healed(retry passed)]`；`failed` 带归因 `infra | locate | assert`。

**WfRun**：`pending → running → (done | paused(断点) | budgetExhausted | failed | cancelled)`；`paused/failed` 可从检查点续跑。

**Capability**：`declared → starting → healthy → (unhealthy → restarting) → stopped`。

**Process**：`spawning → alive → (draining → exited | crashed → restarting?)`；runner 崩溃不自动重启。

## 6. 业务规则

1. 用例判重按三元组（覆盖哪条迁移 / 哪组参数 / 断言什么）。
2. 预算三闸：calls / usd / ms，任一耗尽即停，且"耗尽预算"与"干完活"是两种不同结束，报告必须分得开。
3. 模型调用全局串行（默认并发 1），与执行并发解耦。
4. 目标为非本机域名时，不可逆动作（删除/支付/转账…）默认拦截，需显式加白。
5. 密钥只出不进：可写入、可引用、永不回显。
6. 任何自动修复不得静默删除用例；删除必须留记录并计入严口径统计。
