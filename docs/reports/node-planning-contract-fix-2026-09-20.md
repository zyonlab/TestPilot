# 节点规划与执行边界修正

## 检查结果与修改

- 探索：保持事实采集职责，覆盖不足仍记录 partial/frontier/observations；不把这些字段解释为产品需求是否成立。
- 模块规划：消费探索材料和产品模型，结合需求、领域规则规划范围。启动响应新增 upstreamInputs；产物 sourceRefs 记录材料和探索模型来源。
- 用户故事：消费已审核模块树及相关资料。工作单元原本已有 frozenModules；整节点启动现在也返回上游模块产物。删除“探索没到就给验收加界面观察不到”的生成指令。新写入（整份及工作单元）拒绝这个具体错误标记，要求把覆盖信息放回 observationLinks。不修改历史文档。
- 用例设计：消费故事和验收编号，设计步骤、预期、数据前提；没有观察不自动意味着缺 fixture。规划提示词统一说明设计完成与执行就绪是两种状态。
- 质量门禁：核查现有实现，设计评分与 executionAdmission 已分开，保留。
- 人工审核：保留模块审核、用例批准权限，不自动代审。
- 准备执行：当前实现是编译/执行准入检查，并不是已经具备自动登录、造数、浏览器验证每条用例的完整准备器。本次不虚构这项能力。
- 执行与报告：保留执行准入、真实运行和资金计算判据要求，不将 unobserved 批量改成 ready。

## 生效与复验

提示词及 Skill 在新运行中生效；旧运行的冻结指令不被篡改。建议从用户故事节点新建重跑，沿用已审核的模块规划，逐节点复验。这次不自动启动付费规划或交易流程，也不宣称当前 46 条故事已重新生成。

新增规划契约测试覆盖：未观察需求可以规划、真实需求疑问保留、观察缺口标记拒绝、故事与用例两条提示词一致。回归覆盖模块规划、工作单元、工作流控制、执行准入。
