01

判断与自测结果

生产功能的可靠性已有较厚基础；以实验选出更好的 Harness，仍被测量有效性与角色边界卡住。

本轮在新分支完成了两件不同的事：用现有回归检查确认当前实现是否按其既定规则工作；新增独立准入检查，检验这些规则是否足以支持可信的评测驱动选版。两者的结果不同，正是本轮最重要的发现。

证据面结果可以得出的结论
现有回归1419 个 Vitest 测试 + MCP Node 4 项 + hooks 23 项 + scripts 7 项通过已覆盖的功能不变量成立，不等于模型质量已验证。
工程检查typecheck / build / drift / host-parity / domain-neutral 通过代码、分发和构建基础可用。host-parity 不是权限隔离证明。
新增评测准入6 项：4 failed、2 passed；退出码 1，blocked当前仍不应据这条评测链路宣称某个候选可靠胜出。
真实模型与 UI 评测本轮未执行不报告生成质量提升、误报下降或真实成本收益。
加强顺序：先把无效实验挡在评分前，隔离规划器与人工审核能力；再统一 Trial/Grade/Comparison 契约和生产适配器；最后把反馈任务化，接候选比较、留出验证与版本晋升。不要先增加自动搜索复杂度。

本轮没有修改生产生成、评分或权限实现；新增的是可复跑的准入自测、功能生命周期说明与报告。测试不满足要求就保持红色，不用 expected-failure 或 skip 把它包装成绿色。现有默认测试范围仍可独立运行。

事实来源优先级：内容哈希校验过的产物与执行回执 → 冻结配置/输入 → 状态投影 → 报告摘要 → 模型解释。不能拿模型说“完成了”替代 executor receipt，也不能从目录或函数存在推断功能已经在主线上启用。

03

统一生命周期：每个功能都要回答的七个问题

功能不只有“执行一次”。要让迭代可比较，创建、失败恢复、失效和退役都必须进入设计。下面的模板用于后续 16 个功能；具体状态名可以不同，但证据边界要一致。

生命周期阶段必须补齐的内容对评测的意义
定义 / 配置责任模块、能力范围、输入/输出 schema、候选可变参数、schemaVersion。知道究竟改变了哪个因素。
进入 / 预检输入冻结、有效审批、依赖/环境就绪、预算与权限。减少把根本没发生的实验算成质量差。
执行 / 观察真实配置、工具调用、上下文、attempt、产物与证据。声明的候选确实被运行。
失败 / 恢复失败归因、部分结果、有限重试、取消传播、重启恢复、幂等。失败不是消失；修复消耗纳入比较。
完成 / 冻结内容哈希、来源链、校验/评分版本、终态完整性。结果可以被独立重算与审阅。
消费 / 失效下游引用、批准/缓存失效、配置变更影响、证据保留。旧结果不能为新内容背书。
反馈 / 升级 / 退役可复现任务、候选实验、验证、发布与回滚、数据污染管理。从一次修 bug 变成防止同类错误再次出现。

四种状态必须拆开

WorkflowStatus：运行是否推进 / 等人 / 取消 / 完成
ExecutionVerdict：UI 测试 passed / failed / unobservable / infra_error
TrialValidity：这次测量是否具备可比条件与充分证据
ComparisonDecision：improved / regressed / inconclusive / invalid

例如：正确抓到注入缺陷的测试 verdict 是 failed，但生成器的 trial 可以有效且得高质量评价；浏览器未启动则测量无效；取消后迟到的成功结果不应把 workflow 改回完成。

F01 · P1输入与上下文

项目材料、领域规则与环境画像

草稿 → 校验 → 项目版本 → 运行绑定 → 封存 → 被引用/过期

已有事实：workflowOps.createWebWorkflow、runService.freezeRunMaterials、rulePacks、domainReferences 与 modelSnapshots 已把资料、模型与领域数据绑定到运行；产品不再默认读取仓库夹具。

生命周期补足与加强
进入 / 预检将输入来源、语言、目标环境、允许状态变化与能力前提汇总成 preflight receipt；缺失输入失败，不用 benchmark 补位。声明哪些属于实验允许变化因素。
执行 / 观察同一 trial 只能引用绑定的材料版本；记录检索 chunk 及实际发给模型的摘要。资料更新产生新版本，不改变旧运行。
失败 / 恢复材料读取失败、环境不存在、目标不符分别记录；重试仍引用旧快照，要换输入就新建 trial。资料内容不可信，不能提升为工具或系统指令。
冻结 / 失效冻结 inputHash、知识引用和环境摘要；保留可解释的来源链。敏感值仅进受控快照，评测 manifest 使用引用/哈希。删除策略不能静默破坏已引用证据。
评测 / 反馈输入绑定一致性、引用可追溯率、跨项目污染、缺前提的预检拦截；不把文件数量当需求覆盖。

F06 · P1生成与验证

工作单元、故事与验收准则

plan → claim → 生成 → 单元校验 → 重试 → merge → 整体校验

已有事实：workUnits 由服务端切分，最大尝试次数 5；故事按模块加旅程，用例按故事。checkStories/acceptanceIndex 提供结构和动作型准则信号。

生命周期补足与加强
进入 / 预检依赖未完成不可领取；任务集固定单元范围和输入父版本。评测相同工作量，避免候选少生成单元而更便宜。
执行 / 观察领取、写入、校验、合并作为独立 receipt；正文保留明确前置/触发/可观察结果，并绑定 sourceRefs。
失败 / 恢复标注失败是模型格式、范围错误、材料不足还是调度异常；重启后的 claimed 单元需要可验证恢复或租约释放语义。这里是加强验收项，不把它当已复现 bug。
冻结 / 失效局部成功不等于整批完成，merge 后全局去重和一致性仍要跑；修订故事应传播到依赖的 cases。
评测 / 反馈单元首轮通过/最终通过、语义覆盖、合并丢失率、重复故事、修复次数；总分与单元数分开。

复核、修订、批准与驳回

生命周期补足与加强

05

跨层断点：哪里最容易出现假闭环

很多问题不是某个函数没测试，而是两层各自正确、接起来却失去约束。因此重点应放在信息跨边界时有没有被丢掉或提升权限。

边界当前证据 / 风险补强与验收
实验定义 → 执行 adapterR01：runtime 在定义层存在，到 startRun 时丢失。实际回执必须反映有效配置；传递失败或不支持立即 invalid。
规划工具 → 操作员权限R04：注册工具→HostApi→reviewerPrincipal，丢掉运行身份后取得 human。隔离 planner/operator 能力；普通工具覆盖测试之外，加角色矩阵与绕过测试。
运行终态 → 评分R03：没有产物的 failed 被转为空 cases，生成零分对比。先做 measurement eligibility；区分生成坏代码与环境没启动。
注入探针 → 检出评分R02：unknown 可被记为 kill=1、score=1。可信注入回执 + 健康对照 + 故障观察；unknown 不进有效分母。
修订 → 批准 → 编译 → 导出现有 ledger 与 run-routes 测试提供较好版本绑定基础。把新实验 adapter 也接到这条链；固定 approved 起点的阶段实验不能冒称端到端人工流程。
执行/驳回 → 回归候选 → 实验任务前段已落地且理由必填；后段自动任务化与调度缺失。人工把 reason 变成固定输入与判分规则，批准 Task 后纳入开发集。
候选 → 留出 → 发布 → 生产加载受限 memory 策略有门禁，通用候选生命周期未统一。通用 HarnessVersion + release recipe + CAS + 实际加载证明；保留回滚。
不建议的改法：为每层各做一个综合分，然后相加。这样可能让产物数量抵消无效实验，或让规则覆盖率掩盖权限越界。契约类问题作为硬门禁，质量维度单独比较，成本作为约束与权衡。

从缺陷建任务EvalTask：可见输入、来源组、预期能力、失败家族、证据 refs隐藏答案与候选输入隔离；不得把整个失败 transcript 无审核塞进 prompt。
