                                              跨模块用户故事

                                              US-01 项目与目标端

                                              project
                                              - **US-01** 作为 QA，我要新建项目并指定目标端（web/iOS/Android）与入口，以便后续所有产物挂在它下面。
  - AC-01.1 目标端为 web 时可选启用 web3 能力；iOS/Android 时该选项不可见。
  - AC-01.2 删除项目级联删除其用例、运行、基线，且需二次确认。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-02 环境与登录

                                              project
                                              - **US-02** 作为 QA，我要为项目配置多套环境（变量、固定头、query、登录方式），以便同一批用例跑在不同环境上。
  - AC-02.1 登录支持三种：UI 步骤、API 登录、粘贴会话（cookie/storageState）。
  - AC-02.2 密钥只以 `${secret.KEY}` 引用，明文永不返回前端。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-03 规格导入

                                              requirements
                                              - **US-03** 作为 QA，我要上传/指向产品规格文档作为输入源，让 harness 拆出用户故事主干。
  - AC-03.1 拆解结果以故事树呈现，每个故事可展开为测试点。
  - AC-03.2 每条用例可追溯到唯一的故事/需求；孤儿用例被计数并高亮。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-04 界面探索

                                              requirements
                                              - **US-04** 作为 QA，我要用探索模式让 agent 漫游界面补充故事（无规格或规格不全时）。
  - AC-04.1 探索过程实时可见（页面截图 + 日志 + 逐条产出）。
  - AC-04.2 探索产物与规格产物同构，进入同一条流水线。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-05 测试设计方法

                                              requirements
                                              - **US-05** 作为 QA，我要 harness 按测试设计方法展开用例（等价类、边界值、状态迁移、判定表、异常路径）。
  - AC-05.1 每条用例标注所用设计方法。
  - AC-05.2 负例/边界用例占比不低于阈值。
  - AC-05.3 每条用例标注判定硬度 tier1/2/3，看板显示分布。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-06 文本用例门禁

                                              requirements
                                              - **US-06** 作为 QA，我要看到门禁①的逐条判据结果与总分，以便决定复核哪些。
  - AC-06.1 门禁①只打分标记，不阻断流程。
  - AC-06.2 不合格项进入复核队列，可批量修正或重生成。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-07 生成 Midscene 代码

                                              execution
                                              - **US-07** 作为测试开发，我要把一条文本用例生成为 Midscene 用例代码，并在真实目标上跑通。
  - AC-07.1 代码分层：`cases/` 只表达意图，页面细节在 `actions/`，业务流在 `flows/`。
  - AC-07.2 公共片段（登录、造数、清理）被引用而非复制。
  - AC-07.3 数据与逻辑分离，支持环境变量、密钥、用例级参数、数据行。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-08 有界修复

                                              execution
                                              - **US-08** 作为测试开发，我要生成失败时 harness 自主有界修复，直到通过门禁②或判定放弃。
  - AC-08.1 修复次数有上限，且连续 K 轮无进展即停并标记原因。
  - AC-08.2 失败先归因为 `infra` / `locate` / `assert` 三类，infra 不计入产品缺陷。
  - AC-08.3 每轮修复的改动分类落盘；报告同时给宽口径与严口径通过率。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-09 执行与归因

                                              execution
                                              - **US-09** 作为 QA，我要单条或成套运行用例，并得到通过/失败与失败原因。
  - AC-09.1 支持数据驱动（一条用例按数据行跑多次）。
  - AC-09.2 套件运行给出门禁结论（pass/fail）与抖动、隔离统计。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-15 工作流编排

                                              workflow
                                              - **US-15** 作为 harness 开发，我要编辑画布（增删节点与连线、改参数），保存即产生新图版本。
  - AC-15.1 连线按节点 IO 契约校验，类型不兼容时给出明确原因。
  - AC-15.2 每次运行 pin 图版本，历史运行的解释不受后续改图影响。

                                              来源：spec · 02-业务规格与用户故事.md · reference

                                              US-16 节点调试

                                              workflow / requirements / execution / harness
                                              - **US-16** 作为 harness 开发，我要三种调试：
  - AC-16.1 只跑拆解子图，并与 gold checklist 对拍覆盖矩阵（"该拆成 N 个吗"）。
  - AC-16.2 抽样 1-2 条跑阶段一，查看门禁①逐条命中详情（"结构合理吗"）。
  - AC-16.3 pin 单条用例走完阶段二并真实执行（"代码合理吗、跑得动吗"）。
  - AC-16.4 任意节点可单跑、可断点、可带上游产物续跑。

                                              来源：spec · 02-业务规格与用户故事.md · reference
