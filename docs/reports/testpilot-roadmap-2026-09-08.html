SECTION 00

目标与接手方式

把衍生品交易前端的专业经验沉淀为可复用的领域规则、测试设计 skill、机器判据和基准，使用户通过 Web UI 或现有 coding agent 都能完成可靠测试，并用受控评测证明专业能力、成本和迭代效果。架构与演示服务于这个目标，也形成可以对外展示的工程证据。

本次用户明确的边界：

  • Web UI 是完整产品入口：配置两个模型角色，管理项目、workflow、材料和产物，review 后执行与交付。
  • 宿主 agent 是另一入口：Claude Code / Codex / PenguinHarness 安装 TestPilot 后，由宿主现有模型思考、规划和生成；另配 Midscene 执行模型。
  • 规划模型负责理解材料、领域推理、测试设计和修复建议；执行模型仅供 Midscene 做页面感知、定位和动作执行。机器 oracle 由确定性代码求值。
  • PenguinHarness UI 负责自进化评估：比较候选版本、看评估证据、批准晋级或回退。TestPilot 提供领域资产和评测工具，产品 UI 显示当前生效版本与结果链接。

两个角色可以选择同一提供商甚至同一模型，但配置、调用归属和预算必须独立。宿主模式不要求用户再买一个规划模型，也不把宿主凭证复制到 TestPilot。Web 模式需在 TestPilot 中配置规划角色和执行角色；规划配置可通过运行时适配层应用，不能只给一个外部设置页面链接。

A pipeline 是显式研究/回归对照模式，使用规划角色生成；C skill 模式才是宿主规划产品路径。固定阶段顺序由服务/MCP 状态机强制，skill 不可任意跳 gate。A 与 C 的机制比较不能声称“仅改变 skill 版本”；单 skill 进化实验要固定同一运行时和执行方式。
