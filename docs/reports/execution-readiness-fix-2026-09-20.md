# 执行就绪修复

本次修改公共探索、用例生成和执行链路，适用于之后的项目。旧项目冻结版本不原地改写，不把缺证据的用例批量标为 ready。

## 已实现

- 环境设置增加可见登录证据：连接状态、完整账户标识、网络、交易授权状态。探索按配置执行登录步骤，再匹配实际控件文字。钱包注入、capabilities 声明及点击登录动作本身不授予 session。
- 探索报告保留 not_found、blocked、failed 的待处理目标，防止漏探被误报为完成。覆盖优先模式先处理未尝试目标。不限屏仍受轮次及时间预算约束。
- 用例生成要求逐断言判据及前置条件，静态展示检查不机械继承交易资金夹具要求。
- 质量门禁产出独立 executionAdmission，包括可执行数量及逐用例阻塞原因。编译及执行入口均再次校验 readiness、声明的前置证据、每条独立断言的判据，阻止设计审核通过直接等同于允许执行。
- 新增 decimal-equation 屏幕判据：唯一范围、带单位数值、同次采集时间、已知舍入规则、BigInt 有理数区间计算。实际结果不能参与自身预期值公式。缺失、重复或过期数据返回 unobservable；计算区间不相交返回 fail。

## 边界与后续操作

- session 验证依赖配置的精确可见文字；账户、网络不能同时观察到时保守保持未验证，不推断已登录。
- requirements 的 evidenceRefs 当前检查是否提供；没有实现独立的资金/持仓夹具创建与真实性认证服务。
- frontier 现在完整保留缺口，但没有新增自动恢复浏览器会话或一键续探 API。
- decimal-equation 证明显示精度内的一致性，不证明交易账本精度，也不能保证同一个 DOM 内各行情数据来自同一市场 tick。跨时点收益对账仍需明确的数据采样及夹具支持。
- 当前 Hyperliquid 运行仍是 waiting_review，原 83 条用例保留。需补实际账户/网络证据、交易夹具和探索缺口后，再生成受影响物料的新版本；本次未批准用例或执行交易。
