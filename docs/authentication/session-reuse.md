# 登录方式与会话复用

环境可组合使用已有的 Cookie / localStorage 会话、请求 Header、API 登录生成的会话，以及注入式 Web3 钱包。并非互斥登录类型。

- `login.sessionChecks`：普通登录的可见状态检查，例如退出登录按钮；不要求钱包地址或网络。
- `login.injectedSessionCheck`：注入钱包检查；使用实际钱包地址、目标 origin、成功签名回执及页面就绪/断开文案。
- 两类同时配置时，须全部通过。检查值应使用稳定、独立显示的完整文案。
- 探索与用例执行先检查页面；通过时跳过登录步骤，失败时执行配置的备用登录步骤。
- 没有配置检查时，恢复的会话保持“未验证”；为兼容旧项目，不重复执行登录，也不把凭据存在视为登录成功。只有普通请求 Header 不会抑制登录步骤。
- localStorage 只注入完全匹配的 origin（协议、主机、端口）；Cookie 沿用浏览器域规则。
- 会话 Header 与环境 Header 合并，同名项使用会话值。
- 用例执行完成登录后仍未通过检查时，报 AUTHENTICATION_NOT_VERIFIED，归因环境且不自动重试。探索可以继续观察公开区域，受保护能力仍须证据确认。
- API 登录凭据过期后的自动刷新尚未实现；需要重新获取会话或配置 UI 登录备用步骤。
- 本次修改不回写历史探索、故事和用例。应从探索开始逐节点重跑，检查登录证据，再生成后续物料。
