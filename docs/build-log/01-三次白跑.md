# 三次白跑 · Three blank runs

> 2026-08-30 · 出处：`evals/README.md`「跑之前先看产物，别只看报告」；测试 `packages/harness-testing/test/casegen.test.ts`

## 中文

**发生了什么。** 一天里连着跑了三次配对评测（A 臂 vs B 臂，只差一件事），三次的报告都**看起来完全正常**：门禁 1.0、结构完整、零错误、McNemar 有数。三次都是跑完之后去数了一下两臂产物的分布，才发现整次评测什么都没量到。

| 报告上的症状 | 真相 |
|---|---|
| 两臂 McNemar 完全一致 | `priority` 不在 `CASES_SCHEMA.properties` 里，两臂都产不出这个字段 |
| 加进 properties 后仍然全空 | 在 properties 里但不在 `required`，这个模型跳过可选键 |
| 覆盖率在 0.111 和 0.556 之间乱跳 | `plan.stories` 只回一条故事、零条验收标准，模型随机挑中哪条决定一切 |

**预判对错。** 第三条我一度当成提示词的效应，还给它编了一个机制——预判错。它不是效应，是 `acceptance` 可选造成的。更要紧的一条：这些字段在上一个模型（mimo）上都产得出来，所以「可选键会被产出」从来不是这套代码的保证，只是那个模型的性质，换端点会把它变成静悄悄的回归。

**改了什么。** ① 一组测试把 zod、提示词点名的字段和三份 JSON schema 钉在一起（在不在 properties、在不在 required），漏一个就红；② 评测从「一次 HTTP 请求」变成 `evals/*.json` 一个文件，`expect` 在跑之前写；③ 规矩写进 `docs/v3/07 §0` 第 9 条：**任何配对评测跑完，先数一遍两臂产物的分布，再读那个 p 值。**

**它为什么值得记。** 一个会红的评测会被人调到绿为止；一个永远绿的评测则会被人相信。三次白跑的代价是一天，换来的是「先看产物」这条不需要再学第二次的规矩。

## English

**What happened.** Three paired evaluations in one day (arm A vs arm B, differing in exactly one thing). All three reports looked entirely normal: gate 1.0, complete structure, zero errors, a McNemar number. Only counting the distribution of both arms' outputs afterwards showed that none of the three had measured anything.

| Symptom in the report | Cause |
|---|---|
| Both arms' McNemar identical | `priority` was not in `CASES_SCHEMA.properties`; neither arm could emit it |
| Still empty after adding it to properties | present in properties but not in `required`; this model skips optional keys |
| Coverage jumping between 0.111 and 0.556 | `plan.stories` returned one story with zero acceptance criteria; which one the model picked decided everything |

**Prediction vs outcome.** I read the third row as a prompt effect and invented a mechanism for it. Wrong: it was `acceptance` being optional. The sharper lesson: the previous model (mimo) emitted all of these fields, so "optional keys get emitted" was never a guarantee of this code, only a property of that model. Switching endpoints turned it into a silent regression.

**What changed.** A test suite pins zod, the fields the prompt names, and the three JSON schemas together (in properties, in required); one miss is red. Evaluations became files (`evals/*.json`) with `expect` written before the run. Rule 9 in `docs/v3/07 §0`: after any paired eval, count the outputs of both arms before reading the p-value.
