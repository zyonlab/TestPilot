# Explore 的宿主规划与界面探索

Web 运行使用注册时冻结的 `plannerRuntime`。Explore 将当前组件编号、标签、角色、容器、状态、页面文字，以及本次运行绑定的领域知识和规则包交给本机 Codex / Claude Code。不会因为有规则包而跳过规划，也不会在宿主失败后静默切换到 API 模型。

规划输出是业务假设：组件对应什么功能、判断依据、预期可见后态、风险等级。只能引用采集到的组件编号；模型不生成选择器。每次新状态后可以补充规划，总共最多四批。规则包限定范围、前提和权限；未知风险不进入通用点击。预算用尽和未观察到的状态都不能计为已验证。

界面操作同时识别标准/ARIA 组件和有明确指针、短文案的自定义 div/span 候选，过滤数字行情行及重复父容器。点击前核对标签、区域和实际遮挡；弹窗遮住的背景按钮不能通过程序点击绕过。无候选时尝试 Escape 恢复浮层，再考虑历史回退。

Hyperliquid Testnet 内置示例 2026-09-24.2 将 Tab/订单类型/杠杆面板等设为 `activate + ui-only`，并声明提交下单、确认、撤单、平仓、提现等禁点标签。业务规则仍是待确认假设，不是验证通过的产品事实。

工作台 source 节点可打开探索报告与宿主规划调用记录。报告将模型理由、预期和实际结果分开：尚未探索、策略阻止/风险未知、状态变化、操作无变化。状态变化不等于预期成立或业务断言通过；目标覆盖仍只以规则包声明的目标为分母。

已登录宿主仅表示认证检查通过。模型请求失败或响应格式无效会留下计划错误，并保留已有观察与规则包允许的探索；不能表述为宿主规划成功。
