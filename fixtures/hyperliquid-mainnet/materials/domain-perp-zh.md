# 加密货币永续合约交易页：领域知识（两臂共用）

> 这份是**金融领域知识**，不是这个产品的规格。它描述的是「永续合约这门生意本身怎么运作」，
> 换一家交易所仍然成立。产品规格在 `rules.json`，两者不要混：
> 领域知识让人看懂界面上那些数字**是什么**，规格才说这个产品**承诺什么**。
> 每一段可以被引用为 `domain-perp-zh.md#N`。

## 1. 永续合约是什么

永续合约没有交割日。它靠**资金费**把合约价格锚回现货：合约比现货贵时多头付空头，
便宜时空头付多头。所以一个永续交易页上至少有三个价格，它们不是同一个东西。

## 2. 三个价格，用途各不相同

- **最新成交价**：撮合出来的价，订单簿中间那一行。它决定你的限价单会不会成交。
- **标记价（Mark）**：交易所算出来的"公允价"，通常由多家现货价加权而来。**盈亏与强平用它**，不用成交价——否则一次插针就能把所有人扫掉。
- **预言机价 / 指数价（Oracle）**：外部现货参考价，资金费率由**标记价相对它的偏离**决定。

页面上同时显示 Mark 与 Oracle 时，两者的差就是资金费率的方向来源。
**「明明成交价没到强平价却被强平」几乎都是因为强平看的是标记价。**

## 3. 资金费

资金费按固定周期结算，只在**结算时刻持有仓位**的账户之间收付，不持仓不收不付。
它不是手续费：它在多空之间转移，交易所通常不抽成。
费率为正＝多头付空头，为负＝空头付多头。页面通常给「当期费率 + 倒计时」。

## 4. 保证金与账户权益

- **账户权益** = 钱包余额 + 未实现盈亏。**未实现盈亏计入权益，但通常不计入可用保证金**。
- **起始保证金**：开这一仓需要冻结多少。名义价值 ÷ 杠杆。
- **维持保证金**：保住这一仓至少要留多少。低于它就被强平。维持率通常随名义价值分档递增。
- **全仓（Cross）**：整个账户的权益给所有全仓仓位共用，一个仓位亏损会吃掉别的仓位的保证金，爆则一起爆。
- **逐仓（Isolated）**：只有划给这一仓的保证金承担亏损，爆仓最多损失那一份。

全仓的强平价随账户其他仓位变化而变化——**同一个仓位、什么都没做，强平价也会动**。

## 5. 杠杆

杠杆决定起始保证金，不决定亏损速度：亏损由价格变动和仓位大小决定，杠杆只决定你能开多大。
上限通常**按标的分档、并随名义价值递减**（同一标的，仓位越大可用杠杆越低）。
改杠杆会改变强平价：调高杠杆＝保证金变少＝强平价向现价靠拢。

## 6. 强平与之后

维持保证金不足 → 强平引擎接管仓位。之后可能还有：
- **保险基金**吸收穿仓损失；
- **自动减仓（ADL）**：保险基金不够时，按盈利与杠杆排序强制减对手方的仓。
一个页面如果只讲强平不讲 ADL，用户会以为对手方的仓位永远安全。

## 7. 订单类型

- **市价单**：立刻按对手盘吃单，可能吃穿几档。所以会有**滑点上限**（Est / Max），超过就拒。
- **限价单**：挂在订单簿上等成交，价格是你给的。
- **止损 / 止盈（触发单）**：先给触发价，触发后按市价或限价发单。它在触发前**不占订单簿**。
- **Scale（分批）**：在一个价格区间铺多笔限价单。
- **TWAP**：把一笔大单按时间切成小单，降低冲击成本。
- **Chase（追价）**：跟着盘口移动挂单，尽量做 maker 又尽量成交。

## 8. 有效期（TIF）

- **GTC**：挂到成交或撤销。
- **IOC**：能成交多少成交多少，剩下立刻取消。
- **ALO / Post Only**：只做挂单方；如果这一单会立刻吃单，直接拒绝。
用它的人图的是 maker 费率，所以「被拒」是正确行为，不是失败。

## 9. 只减仓（Reduce Only）

勾上之后这一单**只能让仓位变小**：不能开新仓，不能把仓位做反。
没有持仓时提交只减仓单，正确行为是不产生任何仓位。
数量超过持仓时各家行为不同（拒绝 / 裁剪），**不能想当然**。

## 10. 费用与滑点

maker / taker 两档费率，页面通常写成 `taker% / maker%`。
市价单额外有滑点：Est 是按当前盘口估的，Max 是允许的上限。
**滑点不是费用**，它是吃穿档位造成的成交价劣化。

## 11. 订单簿的读法

- **价差（Spread）**＝ 最优卖价 − 最优买价，既是绝对值也是百分比。它是流动性的直接读数。
- **精度分组**（0.1 / 1 / 10…）：把相邻价位合并显示，只改变呈现，不改变真实挂单。
- **计价单位切换**（标的 / 计价货币）：同一批挂单换一种计量显示。
- 「合计」列是**累计量**，不是该档量。

## 12. 现货与合约是两个账户

存款进来的钱通常先在现货账户，要划转到合约账户才能做保证金。
页面上的「合约 ⇄ 现货」就是这件事。统一账户（Unified）模式下两者合并计算，
但那是一种可选模式，不是默认前提——**不能假定余额在哪一侧**。

## 13. 预测市场不是永续合约

同一个交易所可能同时提供**预测市场**（对某个事件结果下注，到期按结果结算）。
它有到期、没有资金费、没有杠杆分档，与永续的风控模型完全不同。
把两者放进同一个模块是分类错误。

## 14. 这类页面上最容易被测错的四件事

1. **把会变的读数写进断言**：标记价、资金费率、倒计时、24 小时量每秒都在变，只能断言"存在"或两次读数之间的关系。
2. **拿成交价验强平价**：强平看标记价，用成交价算必然对不上。
3. **把可用保证金当成账户权益**：未实现盈亏在权益里、不在可用里。
4. **假定余额在合约账户**：现货与合约分离时，"有钱"不等于"能开仓"。
