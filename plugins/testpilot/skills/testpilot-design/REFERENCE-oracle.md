# 什么才算一个可观察的现象

> 这一份对应 `prompts.ts` 里的 `ORACLE_STRICT`。它在那里是**可选的一段**，
> 因为它存在的目的就是被比较：critic 读到 77 条 `oracle-vague` 之后提议收紧断言标准，
> 而一个只能靠改源码采纳的提议，是没有人能称量的提议。
> 在 skill 世界里，「可选」= **这份文件在不在**。装上它是一臂，卸掉它是另一臂。

**这一节决定 `expected` 能不能用。**

## 算数的（写成这样）

- **一句界面逐字显示的话**，原样引用：页面显示「用户名不能为空」
- **一个计数或一个数字**：列表少一行；余额为 0；耗时字段显示 0ms
- **一个具名元素的出现或消失**：「删除」按钮消失；进程行出现 anvil-local
- **一个位置**：仍停留在登录页；跳转到 /review

## 不算数的（无论听起来多具体）

- 「弹出确认对话框，提示用户确认删除」——**没点名任何文案、元素、数字**
- 「配置保存成功并正确回显」——「正确」是读者的判断，不是产品的输出
- 「页面正常展示各项指标」——这是对一屏的描述，不是一个能失败的主张

**把第二类改写成第一类之后再交出去。**

## 五种 oracle

tier 1 和 tier 2 **必须**同时给 `oracle`——同一个结果，写成程序不看图就能核对的形式：

```json
{"kind":"text",   "value":"<页面显示的一句字面文案>"}
{"kind":"noText", "value":"<页面必须不显示的一句字面文案>"}
{"kind":"url",    "value":"<地址里的一段>"}
{"kind":"count",  "value":"<一句字面文案>", "op":"eq|gte|lte", "n":3}
{"kind":"delta",  "value":"<数字旁边那个标签>", "direction":"increased|decreased|unchanged", "by":1}
```

`delta` 是 **tier 2**——它是两次观察之间的关系，不是一次观察。

**写法上的一条硬规矩（2026-09-08）**：`oracle` 对象永远在，tier 3 写 `{"kind":"none"}`；不适用的字段用占位符填满（字符串 `"-"`、method `"GET"`、op `"eq"`、数字 `0`），harness 在校验前剥掉。约束解码下模型会跳过可选键，所以 schema 里每个字段都是必填的。

## 第六种：`api`——判决从接口读，不从屏幕读

被测对象有机器可读的状态接口时（交易所的清算 / 挂单 / 余额接口），资金与仓位类的结果**必须**写成它：

```json
{"kind":"api","url":"${env.INFO_URL}","method":"POST","body":"{\"type\":\"openOrders\",\"user\":\"${env.ADDRESS}\"}","path":"[coin=BTC].limitPx","op":"eq","value":40000,"settleMs":2500}
```

- `path` 是点分路径；数组元素**按字段选**（`[coin=BTC]`、`assetPositions[position.coin=BTC].position.szi`），不按下标——下标随账户里有几个仓位而变。
- `op`：`eq / neq / gte / lte / exists / absent` 是 tier 1；`increased / decreased / unchanged` 是两次读数的关系，tier 2。
- `settleMs` 给 2–4 秒：接口比界面慢一拍。
- 接口地址与账户标识走 `${env.*}` 占位符，永远不写字面量。
- 什么时候用：期望结果是接口会返回的一个数或一条记录（数量、价格、余额）。拒绝类结果仍用 `text`。

**字面量逐字照规格写。** 结果没法写成上面任何一种，那它就是 tier 3：
就说它是 3，并且不写 `oracle`。

## 一条反向约束：**读数是数据，不是行为**

计数、倒计时、实时价格、余额、合计、时间戳——**任何两次访问之间会自己变的东西**——
永远不要变成一条关于它的值的断言。

- 错：「首页显示 6 条未完成任务」「列表更新于 3 分钟前」
- 对：「首页显示未完成任务的数量和列表最后更新的时间」

你可以断言这个字段**存在**、它在哪、用什么单位、随什么变。
你不可以断言它等于材料被采集的那一刻它恰好是多少。

这条不是洁癖。2026-09-01 实测过：材料是整屏转储，
模型把一个实时费率 `0.01000%` 和一个倒计时 `05:40:16` 抄成了两条「规则」，用例跟着断言它们——
**下一次跑必然失败，而那一批用例在门禁上拿了满分、零条 warn。**
门禁后来加了 `oracle-volatile` 来拦（只认三种一望即知是快照的字面量：时刻、
三位以上小数的百分比、千分位大数），但**源头在写断言的这一刻**。

一条必然失败的用例比没有这条用例更糟，因为它会把真实的失败淹掉。
