# 判定表（`designMethod: "decision-table"`）

**一句话**：结果由**几个条件的组合**决定时，把组合列成表，然后每一行是一条用例。

## 怎么用

1. 找出决定这个结果的**条件**（通常 2–4 个；超过 4 个说明这条故事该拆了）。
2. 列出每个条件的取值（多数是真/假）。
3. 画表：条件的每种组合一行，写清楚那一行的**结果**。
4. **合并结果相同的行**——同一个结果不需要测三遍。
5. 剩下的每一行写一条用例。

## 判据

- **组合必须真的影响结果。** 两个条件互不相干，那是两条独立的用例，不是一张判定表。
- 规格没有说明某个组合会怎样，**不要替它决定**。那一格写进故事的 unknowns，
  或者写一条用例但标 tier 3 并说明「规格未定」。
- 门禁会找这条用例里**有没有组合的痕迹**（「同时」「并且」「且」「both」「and」）。
  标了 decision-table 却只提到一个条件的用例会被记一条 `method-mismatch`。
- **不要穷举。** 2 个二值条件是 4 行，4 个是 16 行，而其中大部分结果相同。
  合并之后剩下的才是这张表的价值。

## 例

故事：「只有登录且购物车非空时才能结账」。

| 已登录 | 购物车非空 | 结果 |
|---|---|---|
| 是 | 是 | 进入 Checkout: Your Information |
| 是 | 否 | 停留在购物车，显示「Your cart is empty」 |
| 否 | 是 | 跳到登录页 |
| 否 | 否 | 跳到登录页（与上一行结果相同 → **合并**） |

三条用例，不是四条。第三、四行合并那一步就是判定表和穷举的分界。
