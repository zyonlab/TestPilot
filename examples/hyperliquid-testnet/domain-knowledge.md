# Hyperliquid Testnet 内置示例

这是可修改的测试规划起点，不是产品规格、实时观察或 Gold。以下覆盖范围均需结合当前页面与用户确认，不得直接作为失败判据。

- 账户与资产：区分钱包连接、交易会话、账户模式、账户资产与可用保证金。连接钱包不证明余额充足或可交易。
- 币对：记录当前市场、计价单位、数量单位和价格精度；具体约束【待确认】。
- 杠杆与保证金：关注模式、杠杆、保证金输入及确认后的状态；上限、公式和风控条件【待确认】。
- 保证金模式与持仓（用户 2026-09-25 提供）：某市场有持仓时，该市场的保证金模式可能不能切换。切换模式的用例先证明该市场无持仓；建立持仓的用例若也改了保证金模式，收尾先平仓、再还原模式。有持仓时切换是被禁用、被拒绝还是被允许【待实测】。
- 订单：区分下单面板、提交确认、未成交订单、部分成交、完全成交、撤单及被拒绝；不能把弹窗打开当作下单成功。
- 持仓与盈亏：区分无持仓与已有持仓、方向、数量、未实现与已实现盈亏。动态行情读数不能断言为固定值。
- 生命周期：账户准备 → 选择币对 → 配置下单 → 开仓 → 查看订单与持仓 → 调整保证金 → 撤单或平仓 → 核对收尾状态。具体支持的路径【待确认】。
- 状态覆盖：未连接/已连接、无订单/有订单、无持仓/有持仓分别记录；缺少前提属于未验证，不等于产品缺陷。
- 风险边界：下单、撤单、平仓和调整保证金属于业务状态变更。示例探索仅观察，不执行这些操作。


## 业务生命周期候选（待产品确认）

当前空订单或空持仓只限制观察范围，不缩小候选需求范围。规则包 businessTransitions 给出候选目标、前置条件、成功结果、失败分支和状态准备；这些声明不证明功能存在，也不授权执行。

- 下单被接收、未成交挂单、部分成交、完全成交是不同状态；挂单不等于持仓。
- 撤单依赖可撤销的未成交订单；平仓依赖非零持仓。未成交的平仓委托不代表平仓完成。
- 增加持仓保证金依赖已有持仓、适用的保证金模式及可用资产；模式支持范围、限制与计算规则待确认。
- 订单历史、成交历史、资金变化应分别核对来源事件和身份；不能用某一历史表非空推断其他历史存在。
- 故事应覆盖进入条件、业务动作、可见结果及拒绝/恢复分支。未观察到的目标仍可提出候选故事，具体产品规则由用户确认。
- 观察模式只探查入口、弹窗、下拉、标签页和说明。准备订单/持仓需要明确的测试资源归属、操作授权及清理方案。
- 执行优先级（用户 2026-09-26 确认）：生命周期主链、影响资金、高频使用三项全中是 P0，中两项 P1，其余 P2。高频：选市场、下单、看持仓、撤单、平仓；中频：改杠杆/保证金模式、追加保证金、看历史；低频：充值提现划转入口、水龙头、隐藏小额余额、市场列表筛选。

## 测试市场说明

- **用 BTC-USDC 做下单类用例**：HYPE-USDC 是入口市场，用于只读用例；BTC-USDC 流动性稳定、价格高，0.001 BTC 就满足最小订单价值。
- **最小订单价值 $10**：低于这个会被拒（见上面的瞬时提示）。`TP_BELOW_MIN_SIZE=0.0001`（42,000 × 0.0001 = $4.2）用来测拒绝。
- **80% 价格带**：限价单价格偏离中间价太远会被拒。`TP_BTC_ORDER_PRICE=42000` 取在 BTC 中间价（约 84k，2026-09-27）的一半附近，既挂得上又不会成交；`TP_BTC_CLOSE_PRICE=120000` 用于 Reduce Only 卖单。BTC 价格大幅变动时先核对这两个值还在价格带内。
- **下单数量** `TP_BTC_ORDER_SIZE=0.001`，显示为「0.00100 BTC」（`TP_BTC_ORDER_SIZE_TEXT`）；两笔同量为「0.00200 BTC」。
- **只有一个测试账户**：用例只能串行跑，前一条的残留会让后一条入口检查失败；收尾与入口检查因此必须严格。部分成交、断网、低余额、从没成交过的账户在这个账户上做不出来。
- 执行环境里下单价与数量变量的取值随行情需要人确认；换市场要同时换价格、数量、显示文本三组变量。
