# Hyperliquid Testnet：合约交易全生命周期与资金准确性

版本 2026-09-20.1；目标 https://app.hyperliquid-testnet.xyz/trade；范围为加密资产线性永续。页面观察见 site-observations.md，用户目标见 scope.md，机器结构见 rule-pack.json。本资料基于本次未登录页面与官方文档，是待执行的测试设计依据，不是通过报告。官方文档可能描述主网/通用能力，测试网与当前账户适用性需核对。

## 1. 业务模型与边界

必须独立记录五个维度：
- 身份：注入钱包地址、主/子账户、连接/交易授权状态。钱包可见不等于已启用交易；签名拒绝不能产生委托。
- 市场：DEX、币对、基础资产、结算资产、数量精度、价格合法性、保证金档位。BTC/ETH/HYPE 作为代表性覆盖对象，不假定参数相同。
- 仓位：做多/做空、单币对/多币对；同一市场反向成交可能减仓或反手，不能套用其他交易所双向对冲模式。
- 保证金：Cross / Isolated。共享或隔离的是风险资金；不能等同于持仓币种数。
- 账户：Unified / Portfolio Margin / Manual，独立于上述维度。

Unified 按抵押资产共享现货与相关全仓风险；Manual 按 DEX 分账；Portfolio Margin 引入合格多抵押品、借贷和利息。多币对仓位并不自动启用多抵押品。
来源：[账户模式](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/account-abstraction-modes)、[保证金](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margining)、[组合保证金](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/portfolio-margin)。

## 2. 七个业务模块及生命周期

1. 身份与账户资产：注入钱包→连接/授权→确认账户与模式→核对可用资产、测试资金与余额来源。
2. 市场选择与合约参数：选择币对→区分标记/预言机/成交价→取得精度、杠杆档位和市场约束。
3. 风险与保证金：全仓/逐仓→杠杆→资金可用性→跨币对风险与账户模式适用性。
4. 下单与预估：多空→订单类型→数量/金额/比例→精度和最低金额→保证金、费用、滑点、清算价估计。
5. 委托与成交：提交/拒绝→挂单/部分成交/全部成交→修改/撤销剩余→逐笔成交映射。
6. 持仓与退出：加仓→资金费与浮盈亏→TP/SL→部分平仓/全部平仓/反手→清算异常路径。
7. 结算与复核：成交费用、已实现盈亏、资金费、利息→权益对账→跨币对隔离验证→刷新重连核对→恢复已约定夹具。

每个阶段都必须关联上一个阶段产生的身份、市场与数值，不用七组互不相关的页面检查冒充完整交易。

## 3. 独立数值核对口径

以下是测试方的代数模型与推导。变量一律十进制字符串计算，q 为带符号数量（多正空负），Q=|q|，E 为入场均价，M 为同一快照标记价，P_i/Q_i 为逐笔成交价格/数量，L 为杠杆，f_i 为已核实的逐笔费率。

| 项目 | 核对方法与适用前提 |
|---|---|
| 名义价值 | N=Q×价格。委托用限价/已核实估算价；仓位价值用标记价；实际成交用各笔价格。三者不能混用。 |
| 金额换数量 | 基础估算 Q_raw=金额/估算价；数量受数量步长约束。若输入的是保证金预算，Q_raw≈预算×L/估算价仅为未计费用、持仓和风险占用的上界近似。百分比滑杆具体分母和费用预留需实测，不把近似当精确判据。 |
| 最低下单 | 官方普通永续订单最低名义金额为10美元。数量步长Δ=10^(-szDecimals)，静态价格P下满足名义门槛的推导量为ceil((10/P)/Δ)×Δ；边界要再计算量化后的Q×P。测试低一个步长、恰到门槛、高一个步长；减仓/尘埃仓位和高级订单例外单列待验证。 |
| 价格与数量合法性 | 永续价格最多5位有效数字，且小数位≤6-szDecimals；整数价格有例外。数量精度按资产元数据。过精度输入是拒绝、截断还是舍入需独立核对UI，不自行认定。 |
| 保证金 | 文档初始保证金基式 IM=Q×M/L。下单预估还需识别既有仓位、净增风险、未成交委托和费用口径；不能直接用余额减IM声称“可用余额正确”。 |
| 成交与加仓均价 | 本次成交VWAP=Σ(P_iQ_i)/ΣQ_i；同向加仓新E=(旧Q×旧E+ΣP_iQ_i)/(旧Q+ΣQ_i)。部分平仓不重写剩余仓位入场价。 |
| 未实现盈亏 | U=q×(M-E)。多空用同一带符号公式，必须使用同一时刻M；不是以最新成交价代替M。 |
| 平仓与反手 | 交易方毛平仓盈亏R=sign(q_old)×Q_close×(P_fill-E_old)。反手拆为平掉旧仓和剩余量开新仓，避免把全笔数量算成平仓。它是独立经济核算，不直接等同于平台Closed PNL字段。 |
| 费用 | Fee=Σ(P_iQ_if_i)，每笔核对maker/taker、折扣、返佣、builder/deployer费用和费用币种；费用正值记支出，返佣负值。不能把下单框显示的费率当所有成交的费率。 |
| 资金费 | 单次现金流CF_funding=-q×Oracle×r_hour，正费率多头支出。以结算时仓位与该小时费率核对，不能拿当前展示费率追算旧记录。 |
| 风险 | 维持保证金按有效档位及扣减项计算；预计清算价不是无条件保证。组合抵押下含借款、利息和抵押折算；当前账户准入及阈值需按当期规则核对。 |

来源：[精度](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/tick-and-lot-size)、[错误条件](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/error-responses)、[入场价与PNL](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/entry-price-and-pnl)、[费用](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/fees)、[资金费](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/funding)、[保证金档位](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margin-tiers)。

## 4. 全过程资金守恒（测试方账务模型）

对同一账户边界、同一计价币、同一时间窗，先做逐币种流水，再折算总权益：
Δ权益 = 净外部流入 + 毛已实现交易盈亏 + Δ未实现盈亏 - 净交易费用 + 有符号资金费 + 净利息 + 其他已解释项。

“其他项”必须逐项有证据，例如抵押资产重估、清算费用、奖励，不能用它填平差额。借款新增资产必须同时记负债，借入本金不是收益；还本金不是损失。内部划转在同一个总账户边界内抵消，在子账边界则是流入/流出。隔离保证金分配与挂单冻结影响可用性，不是直接消耗权益。借款利息与永续资金费不可混为一项。

平仓结束且无其他持仓、借款或外部现金流时，应能把最终余额差还原为交易毛盈亏、费用和资金费；不能把释放的保证金再算一遍收益。多币对分别核对后汇总，任何币对操作不能改错另一币对的数量/入场价。

官方将Entry Price/PNL描述为前端便利指标，Closed PNL的文档公式、费用符号与UI窗口可能不同。必须在字段字典里记录口径：毛/净、含哪些费用、mark/fill、时间窗及币种；未确定前，不宣称Closed PNL=独立R。ROE也必须确认分母，不能把价格收益直接乘杠杆当成精确值。

## 5. 订单与异常覆盖

Market与Limit；GTC/IOC/ALO；部分成交后撤余单；Reduce Only不得扩大或翻转仓位；TP/SL的触发与实际成交分开，触发不保证全额成交。高级TWAP/Chase/Scale/Trailing Stop按页面可用性分支，不复用普通订单门槛。覆盖无钱包、拒签、会话失效、资金不足、零/负/空/过精度数量、错误价格、无流动性、档位限制、重复点击和撤单成交竞态。错误后同时查拒绝反馈和订单/仓位/资金的无意外变化，不能仅凭toast判定成功或失败。
来源：[订单类型](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/order-types)。

## 6. 执行矩阵与准确性等级

主链组合：多/空 × 全仓/逐仓 × 单市场/双市场 × 市价/限价 × 首开/加仓/部分平/全平/反手。
账户模式独立覆盖：Unified相同抵押币多市场、不同抵押币隔离；Manual同DEX/跨DEX；Portfolio Margin合格多抵押品、借款、利息、限额与风险。后者先验证准入，不能未测就报支持。
金额边界：最低名义金额±一个有效数量步长、余额不足/临界充足、数量最小精度、价格合法边界、最大杠杆与跨档位、百分比0/100、部分成交残量、尘埃平仓。

数值测量记录币种、精度、时间、市场与订单ID。显示四舍五入到d位时单读数区间为显示值±0.5×10^-d；如果产品截断，使用单侧区间。多输入通过区间运算传播，不统一放宽到1%。行情无法同步、费用明细缺失或精度不足则不能声称资金精确正确。decimal-check.py仅验证测试方算术样例，不验证网站。

## 7. 登录与待确认事项

环境设置injectWallet=true，视口1600×1000；仅引用本机现有测试钱包，资料不含助记词/私钥。准备Enable Trading→Establish Connection登录步骤，来源为仓库既有测试网夹具，当前新环境尚未首跑验证。注入、连接、启用交易、资金充足是四个不同状态，不能只勾选配置就标wallet-session已满足。

未知项：钱包当前余额/仓位与账户模式；测试网各币对精度/最低金额例外；Closed PNL及ROE确切口径；Portfolio Margin账户准入/限额；切换模式限制；金额/比例输入的计算价与预留项；逐仓/反手/多市场结果。未经验证不升级为观察事实。Outcomes、Earn、Vaults、Staking不在本次合约主链覆盖范围内，抵押利息和资产供给只在组合保证金关联场景覆盖。
