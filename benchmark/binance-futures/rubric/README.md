# 评分口径（私有 —— Test Agent 不可见）

> **这个文件、`gold.json`、`held-out/` 都不能进 Test Agent 的 Workspace。**
> P2：考卷不能由考生出。`testpilot-evaluation` 只拷 `statement/` 进去。

## 分不是评测者算的

`benchmark-design` 原来让评测者应用 rubric 得出 0–100。**这里不这么做。**
分由 `score_run` 确定性算出，评测者只是把工具的输出原样转出来。

```
mcp__testpilot__score_run({ runId, goldPath: "<此目录>/gold.json" })
```

`score` = `coverage × 100`，两位小数，**不做别的加工**。
`score_run` 拒绝打分（`RunMeta` 缺 `skillVersion` / `promptsDigest` / `model` /
`materialsHash` 任一项）→ `evaluation_failed`，**不是 0 分**。

## 两个 coverage 怎么读

| 数 | 含义 |
|---|---|
| `coverage` | 调优集上的覆盖率。**会被拟合**——它涨了不一定说明什么 |
| `heldOutCoverage` | 留出集上的覆盖率。**从不进任何调优。只有它涨了，才是真的涨了** |

`coverage` 涨而 `heldOutCoverage` 不涨 = 过拟合，这是它的定义。
两个数在报告里**必须一起出现**，只报前一个等于报一个已知会被拟合的数。

`semantic`（`{coverage, kappa, spread}`）只有在跑过 `calibrate_judge` 之后才有。
**看 κ，不要看原始一致率**——实测原始一致率换成 κ 会掉 33–41 点。

## 覆盖率量的是什么、不量什么

`scoreCoverage` 是**确定性关键词匹配**，不是模型对齐。这买到了可复现性
（同一次运行打两遍分一样，配对比较才有意义），代价是**漏掉清单没预料到的措辞**。

它**量**：该被想到的东西有多少真的被想到了。
它**不量**：这些用例能不能真的抓到缺陷。一批措辞漂亮、断言恒真的用例可以拿到很高的覆盖率。

所以覆盖率**不能单独用**，必须配 F2P/P2P。

## F2P / P2P

```
mcp__testpilot__mutate_and_detect({ runId, defects: [ … ] })
```

| | 判据 | 不过意味着 |
|---|---|---|
| **F2P** | 注入缺陷时必须失败，缺陷移除后必须通过 | 这批用例对这个缺陷是瞎的。**能力信号**——记进 Capability Contract 的「更弱行为」 |
| **P2P** | 与缺陷无关的用例两种状态下都必须通过 | 这批用例**不稳**。多半是易变读数或恒真断言。**这不是能力信号，是缺陷** |

**先修 P2P。** 一批不稳的用例上量出来的 F2P 数字没有意义。

P2P 失败允许**重试一次**（基线里的基础设施抖动会伪装成 P2P 失败），
仍然挂就当真——代价是那一条整场不上场。宁可少一条，不要一条会随机变色的。

**注入哪些缺陷是私有的。** 让 Test Agent 知道要注入什么，它会照着写用例，
于是 F2P 变成一次针对已知答案的考试。

## 这个基准特有的两条

1. **易变读数是陷阱，也是考点。** 材料里全是会自己变的数。
   一批把它们写成断言的用例，覆盖率可能不低，但 P2P 必然崩。
   这正是这个基准要分离的那个「更弱行为」。
2. **观察不能反驳被观察者。** 材料 `derivedFrom: "exploration"`。
   这个基准量的是**生成器的能力**，不是被测产品的正确性。
   一条用例说「产品这里有 bug」，在这份材料上是没有依据的——它至多能说「产品变了」。

## 每题跑几次

**n ≥ 3**（Formal Baseline 与任何配对评测）。报**中位数与散布**，不要只报均值。
理由在 `../README.md`：思考模式关不掉，同一份输入的方差比历史数字大。
