# 留出集

**空的，等 `gold.json` 复核完才分得出来。**

## 规矩

- 这个目录里的东西**只有 `score_run` / `paired_eval` 读**。
- **对 Optimizer 是文件权限只读。** `agent-optimization`（以及任何优化流程）
  不许把这里的内容当成改进依据——读都不该读。
- 留出的那一半**从不进任何调优**。这是它存在的全部意义：
  调优集上的数会被拟合，留出集上的数不会。**只有 `heldOutCoverage` 涨了，才是真的涨了。**

## 怎么分

复核 `gold.json` 时，**分层之后在每层内部对半分**：
`designMethod`（五种）× `tier`（1/2/3）× `priority`（P0/P1/P2）各层内部各留一半。

**不是**前一半留出、后一半调优——那样两个集合的分布不同，两个数就没法比。

## 为什么这个目录在仓库里空着也要存在

held-out / freeze 是整个 agent 评测生态的空白（三路调研的结论之一）。
把目录和规矩先立在这里，是为了让「往哪儿放」这个问题在第一次有留出集的时候
已经有答案，而不是那时候临时决定——临时决定的留出集，多半是从调优集尾巴上切下来的。
