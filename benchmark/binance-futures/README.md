而那个数字什么也不代表。

顺带一提，即使有人误用 `gold.draft.json` 去打分，它也**不会**给出虚高的分：
`scoreCoverage` 的 `matches()` 要求三个 match 子句至少有一个非空并且命中，
G-11 / G-12 的 `assertAnyOf` 是空的（它们的验收标准全是易变读数，被滤掉了），
所以那两条永远 miss。**这个空数组本身是复核清单的第一条证据**——
那两条故事的验收标准里除了会变的数字什么都没有，说明它们八成不该是清单项。

## goldHash

`gold.json` 定稿之后，把它的哈希记在这里：

```bash
shasum -a 256 gold.json | cut -c1-16
```

**goldHash 是谱系标识**（数据契约 §2、架构 §3 的 P2）：
它变了就是一个新基准，跨谱系的分数不可比。`paired_eval` 引用的 entry 若 `goldHash` 不同
会直接抛错。所以 gold.json 一旦冻结就**不要顺手改一条措辞**——
真要改，那是新谱系，从头建基线。

## 观察 ≠ 意图

材料的 `derivedFrom` 是 `exploration`。这决定了这个基准**能测什么**：

> 对着观察写的用例只能发现「产品变了」（回归），
> **永远不可能发现「产品错了」**——观察不可能反驳被观察者。

所以这个基准量的是**生成器的能力**（拆得对不对、断言硬不硬、方法用得对不对），
不是被测产品的正确性。把它读成后者是这份材料最容易出的错。

## 复核 draft 要做的事

`gold.draft.json` 的 `humanReviewChecklist` 里写着六条。最要紧的两条：

1. **删掉钉在易变读数上的条目。** 价格、倒计时、资金费率、24h 量、持仓量——
   2026-09-01 实测过：模型把 Funding `0.01000%` 和 Countdown `05:40:16` 抄成了规则，
   用例跟着断言它们，**下一次跑必然失败，而那批用例在门禁上拿了满分**。
2. **把 `match` 收紧到「测对了才算命中」。** 现在的 `anyOf` 宽到一条只提了标题的用例
   就能命中——那不是覆盖，是提及。

## 每题跑几次

思考模式关不掉（网关不认 `enable_thinking:false`），同一份输入的方差比历史数字大：
Phase 0 实测直连 25 条 / gate 0.72，经 agent 30 条 / gate 0.4——同一件事，两个数。

所以 **Formal Baseline 与任何一次配对评测，n ≥ 3**，报中位数与散布，不要只报均值。
校准阶段可以 n=1 省钱，但要在 scoreboard 的 entry 里写明。
