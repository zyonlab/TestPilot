# 任务：为 BTCUSDT 永续合约页设计测试用例

工作区的 `materials/` 里是对一个**跑着的**产品的观察记录：
`https://demo.binance.com/en/futures/BTCUSDT`（USDⓈ 本位永续合约页）。

材料包含：

- 逐屏的文本转储，每屏以 `===== 屏名 =====` 开头；
- 一张状态转移图：屏（`states`，带 `route` / `title` / `controls`）
  与转移（`transitions`，带 `from` / `to` / `action` / `effect`）；
- 探索没走到的地方（`unvisited`）与它为什么停（`stoppedBecause`）。

## 要交的东西

在 `runs/<runId>/` 下：

| 文件 | 内容 |
|---|---|
| `stories.json` | 从材料里抽出的用户故事 |
| `cases.json` | 每条故事的文本级测试用例 |
| `meta.json` | 这次运行的来源印记 |

（`gate.json` 不用你写——写 `meta.json` 时它会自动生成。）

外加 `scans/<runId>.json`：对自己这批产物的审计。

## 材料的性质

**这是观察，不是规格。** 它记录的是这个产品**现在做什么**，不是它**应该做什么**。
写规则时用陈述现状的语气，不要写成「应当」。

材料是**未登录**会话采集的。`Login with Binance` 之后的一切都没有观察支撑。

## 一条硬约束

材料里有大量**两次访问之间会自己变的数**：价格、倒计时、资金费率、24h 高低、
成交量、持仓量、成交时间。

**不要写任何断言它们的值的用例。**
你可以断言这个字段存在、它在哪、用什么单位、随什么变；
你不可以断言它等于材料被采集的那一刻它恰好是多少。

- 不行：「入口页显示 0.01000%」「Countdown 显示 05:40:16」
- 可以：「入口页显示一个资金费率和距下次结算的倒计时」

## 覆盖

材料里的转移 id 形如 `/en/futures/BTCUSDT->/en/futures/BTCUSDT~1`。
用例走到某条转移，就把那个 id 逐字抄进它的 `covers`。
**只抄材料里真有的 id**——自己拼出来的 id 什么也没覆盖。
