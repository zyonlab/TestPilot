# 评分口径（私有 —— Test Agent 不可见）

> **这个文件和 `gold.json` 都不能进 Test Agent 的 Workspace。**
> `testpilot-evaluation` 只拷 `statement/` 进去。

## 分不是评测者算的

```
mcp__testpilot__score_run({ runId, goldPath: "<此目录>/gold.json" })
```

`score` = `coverage × 100`，两位小数，**不做别的加工**。
`score_run` 拒绝打分（`RunMeta` 缺四项之一）→ `evaluation_failed`，**不是 0 分**。

**打分前先核 goldHash = `2405209c3fe70ac7`。** 对不上就是另一份清单，
那条结果不能和这个基准的任何历史条目比。

## 这份 gold 的构成

16 条，其中 **4 条 `heldOut`**。匹配是**双语关键词**（界面是中文、规格也是中文，
但节点类型与 API 是英文），所以两种写法都要能命中。

`matches()` 的规矩：`anyOf` / `allOf` 匹配「标题 + 步骤」，`assertAnyOf` 匹配 `expected`。
**在场的子句必须全部成立**——一条说对了主题但断言无关的用例**没有覆盖**这一项，
它只是提到了它。这条口径是这份 gold 的核心：它区分「测了」和「提了」。

## 两个 coverage

| 数 | 含义 |
|---|---|
| `coverage` | 12 条调优项上的覆盖率。**会被拟合** |
| `heldOutCoverage` | 4 条留出项上的覆盖率。**从不进任何调优。只有它涨了才是真的涨了** |

**两个数必须一起报。** 只报前一个，等于报一个已知会被拟合的数。

留出只有 4 条，所以 `heldOutCoverage` 的粒度是 0.25——
**一条的进退就是 25 个点**。不要把它当成一个连续的指标去追，
它是一个粗读数：0/4 和 3/4 有意义，1/4 和 2/4 之间的差别多半是噪声。

## F2P / P2P

```
mcp__testpilot__mutate_and_detect({ runId, defects: [ … ] })
```

- **F2P**：注入缺陷时必须失败、移除后必须通过。不过 = 这批用例对这个缺陷是瞎的（**能力信号**）。
- **P2P**：无关用例两种状态下都必须通过。不过 = 这批用例**不稳**（**缺陷，不是能力信号**）。

**先修 P2P。** 一批不稳的用例上量出来的 F2P 没有意义。
P2P 失败允许重试一次（基线里的基础设施抖动会伪装成 P2P 失败），仍然挂就当真——
代价是那一条整场不上场。

**注入哪些缺陷是私有的**：让 Test Agent 知道要注入什么，它会照着写用例。

## 这个基准特有的一条：自举的循环

材料是 TestPilot 自己的规格，被测的也是 TestPilot 的生成器。**这有一个真实的风险**：
生成器可以从规格里读到「门禁怎么打分」，然后照着门禁写用例。

所以读这个基准的数时要配着 `scans/<runId>.json` 一起看：
覆盖率高而 Scanner 报出大量 `assert-trivial` / `unanchored`，
说明它在迎合评分口径，而不是在做测试设计。

另外：**别在评测跑着的时候改服务端代码**，SUT 要独立实例与端口。
自举基准最容易出的事故是「一边跑一边改被测对象」。
